## 관점
골격(AGENTS.md 라우터·절 번호 불변, 대장 3곳·결정 기록 2곳·인덱스 2개 이동 없음, NOW/Worklog/Lessons 분리, 규칙 2계층)은 유지하되, 반박 3건이 공통으로 짚은 "설계안이 채택 즉시 스스로 어기는 항목"을 없앤다. (1) AGENTS.md 예산은 줄 수를 버리고 바이트 단일 지표(소프트 18KiB·하드 20KiB)만 두며, 15절에서 시작·종료 10줄을 빼고 [A] 9줄만 남겨 절차 전문은 Docs/AgentRules.md 3절 한 곳에만 둔다(사본 4→1). (2) 기존 결정론 도구(Tools/tasks_recount.py)와 기존 관례(2열 상태표, Docs/Validation의 `<ID>-<설명>-<날짜>` 명명, Tools/ 루트 범용 도구, `[← 인덱스로]` 34개 문서)를 새 규칙보다 우선해 규칙이 도구를 무력화하지 않게 한다. (3) 설계안 자신의 예약 스크립트 이름을 OP-14에 맞추고(승인 동사형), 승인 동사는 '권장'·동의어 4개 금지만 '규칙'으로 내린다. (4) 집행 수단을 정직하게 적는다: 완료 보고 2줄은 사용자 열람용이고, 저장소에 남는 검출은 Worklog 항목 안 `읽음:` 줄과 OP-07·OP-09의 파일 대조뿐이다. (5) 배선 사실을 2026-09-18 재검증 결과로 교체한다: Serena project.yml 실재(검증됨), Antigravity 작업 공간 `.agents/mcp_config.json`, Codex 스킬 탐색 순서, `/memory refresh`, context.fileName 배열은 문서화됨, Antigravity 훅 2.6.0+, codex_git_commit 제거. (6) PowerShell에서 rg 경로 와일드카드가 실패하므로 모든 명령을 '디렉터리 + --glob' 형태로 통일한다. (7) 종료 절차의 액터 삭제 지시를 제거한다(TDGen_은 정식 생성물 라벨). 도구 이동·개명·코드 리팩터링은 여전히 사용자 결정 뒤이며, 이번 도입의 코드 변경은 capture_views_mcp.py 14행·tasks_recount.py 확장·ue_editor.py 상수 이동 세 건뿐이다.

## LLM Wiki 질문에 대한 답
결론은 r1과 같다. Karpathy "LLM Wiki"(gist 2026-04-04, 2026-09-17 확인)를 그대로 채택하지 않고 구조 요소 4개(스키마 문서·index·log·lint)만 부분 채택하며, 나머지는 2026-09 시점 공개 표준(AGENTS.md: Linux Foundation 산하 AAIF(Agentic AI Foundation, 에이전틱 AI 재단) 관리; Agent Skills: agentskills.io; 구조 검사는 LLM(Large Language Model, 대규모 언어 모델) 없이 결정론 스크립트)을 조합한 자체 규칙으로 만든다. 채택 4요소 — ① 스키마 = AGENTS.md(항상 로드, [A] 규칙 9줄·대장 지도·식별자 어휘) + Docs/AgentRules.md(조건부 규칙·절차 전문; 원문의 '스키마가 커지면 분할' 취지), ② index = 영역 단위 AGENTS.md 15절 표 5행, 문서 단위 Docs/<주제>_Plan.md와 Docs/README.md(등록 정확히 1곳), 도구 단위 Tools/README.md 표, 교훈 단위 `rg -n "^### L-" --glob '*.md' Docs/Lessons`, ③ log = Docs/Worklog/YYYY-MM.md 추가 전용(항목 안 `읽음:` 줄이 세션 간 대조의 유일한 파일 근거), ④ lint = 구조 검사(고아·깨진 경로·미등록·필수 필드·상태 사슬·규칙 ID 접두어)를 결정론 파이썬으로, 의미 모순은 분기 1회 범위 지정 점검. 채택하지 않는 것 — raw/·wiki/ 이중 폴더와 코드 재요약(코드·Docs가 진실의 원천, Verdent 2026-04-06 '유지되지 않는 위키는 능동적으로 오도', Docs 1.09MB는 원문 상한 초과), 무조건 ingest(1건 약 35K 토큰, Proudfrog 2026-04-08), LLM 전체 lint(100문서 약 300K 토큰/회, 같은 모델 자기 검사는 환각을 못 잡음), 벡터·qmd·그래프 DB·Obsidian 문법(원문 스스로 '~100 소스까지 index+grep'), 신뢰도 점수·감쇠·검토 타이머(날짜·증거 경로·상태 3필드 + 손 유지 표의 `확인: 날짜 <agent>` 줄로 대체), 'LLM 전담 편집'(결정·대장은 사람 우선, 에이전트는 (미정) 제안만). 더 최신 대안(Beads v1.0 Dolt, Mem0/Zep, Cline Memory Bank, Ruler, BMAD/Spec Kit)은 사람 1명·순차 세션·git 조건에서 파일 기반 규칙보다 이득이 작아 배제. 재검토 조건: Lessons 300개 초과로 rg가 무뎌지거나 기계 2대 이상 동시 작업 시 SQLite FTS5 인덱스 재검토. 이번 수정에서 얻은 교훈 둘: (1) 위키식 스키마도 손 유지 이중화(절차 사본·집계·상수·기대값)를 만들면 썩으므로 절차는 AgentRules 3절 한 곳, 집계는 Worklog에서 `rg -c`, 파생 표는 스크립트가 만들기 전까지 두지 않는다. (2) 새 규칙은 저장소에 이미 있는 결정론 도구(tasks_recount.py)와 관례(파일 명명·역링크·2열 표)를 먼저 조사해 그 위에 얹어야 한다 — 규칙이 도구를 조용히 무력화하면 규칙 권위가 첫날에 무너진다.

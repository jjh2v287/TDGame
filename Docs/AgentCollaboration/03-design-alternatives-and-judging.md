## minimal-router-three-files (AGENTS.md 라우터 + 새 파일 3개: CLAUDE.md · Docs/NOW.md · Docs/Lessons.md)
- 관점: 최소 변경·토큰 절약 우선. 새 파일은 정확히 3개(루트 CLAUDE.md, Docs/NOW.md, Docs/Lessons.md)만 만들고 나머지는 기존 파일(AGENTS.md, GEMINI.md, .gemini/settings.json, Tools/README.md, 대장 README 3곳, Docs/Validation/README.md, .gitignore) 보강으로 해결한다. AGENTS.md는 "항상 읽는 라우터"로 유지하되 크기를 지금 수준(약 8,700자) 이하로 묶고, 절차·명령줄·상세는 Tools/README.md와 Docs/로 내려 링크한다. 기존 할 일 대장 3곳·결정 기록 2곳·인덱스 2개는 옮기지 않고 AGENTS.md의 '대장 지도' 표와 NOW.md로 연결한다. 결정론적 검사는 지금 규칙·완료 보고 자기 점검으로 강제하고, 스크립트는 사양만 예약한다.
- 요약: 세 에이전트(Claude Code·Codex·Gemini CLI/Antigravity)와 Cursor·VS Code가 공통으로 자동 로드할 수 있는 유일한 파일은 루트 AGENTS.md이므로, (1) 벤더별 배선 3건(CLAUDE.md `@AGENTS.md` 임포트, .gemini/settings.json `context.fileName`, 사용자 전역 파일의 "AGENTS.md 참고 하지 않는다" 줄 삭제=사용자 결정)으로 AGENTS.md 자동 로드를 보장하고, (2) AGENTS.md 11절의 절차 매뉴얼(clangd·에디터 기동 명령)을 Tools/README.md 0절로 내려 자리를 만든 뒤 그 자리에 15절 '세션 절차와 대장 지도'(시작·종료 5줄 + 영역별 대장·결정·기준문서·도구 절 표)를 넣어 총량을 늘리지 않는다. (3) 진행 상태는 Docs/NOW.md 한 장(덮어쓰는 '지금' 절 + 맨 위에 붙이는 '최근 세션 기록' 30줄)으로, 문제→해결·실측 함정은 Docs/Lessons.md 한 파일(L-<영역>-<번호>, 필수 4필드)로 모으고 Tools/README.md 5절·Claude 메모리 8개·AnimationAuthoring_Tasks 실측 메모를 여기로 이관한다. (4) 도구 생성은 '검색 인용 → Tools/<영역>/ 위치 → 환경 접두어+승인 동사 이름 → docstring 4줄 → README 표 1행 → 실험은 Tools/scratch/(gitignore)' 6단계로 고정하고, 애니메이션 폴더 4개와 Content/Python·SKILL.md를 README 표 2b절에 등록한다. (5) 세션 시작 읽기 예산은 기본 11,300자(AGENTS 8,700 + NOW 2,000 + 진입 파일 ≤600), 영역 진입 포함 20,000자 이하로 현재(월드젠 49,534자, 몬스터AI 152,889자)보다 줄인다. LLM Wiki는 '스키마=AGENTS.md, index=대장 지도+NOW, log=NOW 최근 기록, lint=지연 스크립트' 네 요소만 부분 채택하고 raw/wiki 이중 구조·LLM 전담 쓰기·LLM lint·벡터 검색은 채택하지 않는다.
- LLM Wiki 답: 결론: 부분 채택(구조 요소 4개만) + 최신 표준 조합. 그대로 채택하지 않는 이유 — (a) 원문(gist 2026-04-04)은 외부 자료 약 100건을 LLM이 요약·상호링크하는 개인 지식베이스용이며 소프트웨어 저장소는 코드·설계 문서가 이미 진실의 원천이라 wiki/ 재요약은 정보 손실과 드리프트만 더한다(Verdent 2026-04-06 '코드는 무엇을, 위키는 왜'; Neo4j 2026-08-31 한계 6가지). (b) 비용 추정치 ingest 1건 약 35K 토큰·100문서 lint 약 300K 토큰(Proudfrog 2026-04-08)은 토큰 절약을 중시하는 사용자 조건과 반대이고, 같은 모델의 자기 lint는 환각을 못 잡는다('감사자를 감사'). (c) TDGame Docs는 이미 1.09MB·인덱스형 계획서 2개로 사실상의 위키이며, 원문도 '모두 선택적·모듈식'이라고 명시했다. 직접 만들기(자체 설계)도 아닌 이유 — 2026-09 시점의 더 나은 최신 방법이 이미 표준화돼 있다: AGENTS.md(Linux Foundation 산하 AAIF 관리, 2025-12-09)를 스키마로, Agent Skills(agentskills.io, Claude·Codex·Gemini 공통)를 도구 묶음 단위로, 인덱스·링크·고아 검사는 LLM 없이 결정론 스크립트로(Towards Data Science 2026-07-03: 5,000파일 12.4초·API 0회; akm '위키 조작에 무조건적 LLM 호출 없음'), 교훈은 compound 패턴(Every docs/solutions + 규칙 한 줄 승격)으로 쌓는 조합이다. 가져오는 4요소 — ①스키마 문서 = AGENTS.md 단일(원문이 'CLAUDE.md 또는 AGENTS.md'로 지정), ②index.md = AGENTS.md 15절 대장 지도(경로 + 한 줄 요약 + 언제 읽는지) + Docs/NOW.md, ③log.md = NOW.md '최근 세션 기록' 절(`- YYYY-MM-DD <agent> | <작업ID> | <동사> | 요약` 파싱 가능 접두어, append 전용), ④lint = Docs/Lessons.md·등록표·링크 실존 검사를 결정론 스크립트로(deferred_automation 1·2). 버리는 것 — raw/·wiki/ 이중 폴더, '사람은 편집하지 않고 LLM 전담' 원칙(결정 기록·대장은 사람 우선), 벡터·qmd·그래프 DB, Obsidian 전용 문법([[wikilink]]), 신뢰도 점수·감쇠·검토 타이머(Astro-Han 94문서 실운영이 의도적으로 제외), 모든 대화 자동 ingest(성공 조건은 유한한 입력).
- 토큰 비용: 세션 시작 기본 로드 ≤ 11,300자(AGENTS.md 8,700 + 진입 파일 ≤ 600 + NOW.md 2,000) ≈ 7~10K 토큰(한글 위주 마크다운 0.6~0.9 토큰/자 가정); 영역 진입 포함 ≤ 20,000자 ≈ 12~18K 토큰. 현재 실측 온보딩(월드젠 8파일 49,534자 ≈ 30~45K, 몬스터AI 5파일 152,889자 ≈ 92~138K, 애니메이션 54,872자 ≈ 33~49K) 대비 55~85% 감소. 세션 종료 기록(NOW 재작성 + append 1줄 + Lessons 1항목 + 등록 1행) ≈ 1~2K 토큰. ## wiki-compiled-repo — LLM Wiki 개념을 저장소 문서 체계에 이식한 컴파일형 지식 관리
- 관점: Karpathy "LLM Wiki"(2026-04)의 다섯 개념 — 원본(raw)·정제본(wiki)·스키마(schema)·인덱스(index.md)·정리 점검(lint) — 만 떼어 TDGame의 기존 파일 체계에 1:1로 대응시킨다. 별도 wiki/ 폴더를 만들지 않고 "저장소 자체가 위키"로 본다. 원본 = Source/·Docs/*/research/·Docs/Validation 증거 파일·git 이력·외부 참고(Docs/UKGame, UE_Engine_*, docx). 정제본 = Docs/<주제>_Plan.md 인덱스·설계서·할 일 대장·결정 기록·새 Docs/Lessons·Tools/README.md 등록표. 스키마 = AGENTS.md(축소해 라우터로). index.md = 새 Docs/README.md. log.md = 새 Docs/Worklog/YYYY-MM.md. lint = 나중에 만들 결정론 파이썬 스크립트(지금은 규칙·완료 보고 체크로 대체). 뺀 것: LLM(Large Language Model, 대규모 언어 모델)이 위키 전체를 다시 쓰는 ingest, LLM이 수행하는 전체 lint, 벡터 검색·그래프 DB·Obsidian, 신뢰도 점수·감쇠, "사람은 편집하지 않는다" 원칙(결정·대장은 사람 우선). 사용자 요구 4가지 — (a) 세션 시작 시 AGENTS.md 자동 읽기, (b) 도구·리소스 공통 관리 규칙, (c) 지금은 규칙 우선·스크립트는 나중, (d) 문제 해결 기록 메모리 — 를 이 대응으로 한 번에 푼다.
- 요약: 설계 요지: (1) 배선 — 루트 CLAUDE.md(`@AGENTS.md` 1줄) 신설, .gemini/settings.json에 context.fileName 배열 추가, GEMINI.md를 10줄 진입점으로 축소, AGENTS.md 1절에 "전역 지침의 'AGENTS.md 참고 하지 않는다'는 이 저장소에서 무효" 선언. 전역 파일(~/.codex/AGENTS.md:27, ~/.gemini/GEMINI.md:30)의 해당 줄 삭제는 사용자 결정 항목으로 분리한다. (2) 스키마 축소 — AGENTS.md를 14절 8,503자에서 ≤150줄·≤6,000자로 줄인다: 0절 '세션 절차' 신설, 11절 3,291자 중 clangd·UBT(UnrealBuildTool)·에디터 기동 매뉴얼을 Tools/README.md로 옮기고 원칙 3개+경로 6곳만 남김, 12·13·14절을 '지식 체계 지도' 한 절(Docs/README.md 포인터+대장 3곳·결정 기록 2곳 한 줄씩+승격 규칙)로 합침, 마지막에 '하지 말 것' 경계 목록. (3) 인덱스·로그·현황 — Docs/README.md(위키 index: 묶음 표 = 인덱스|대장 ID 접두어|결정 기록|증거 폴더|교훈 파일|언제 읽는지), Docs/NOW.md(세션 종료 시 덮어쓰는 현재 상태 ≤40줄), Docs/Worklog/YYYY-MM.md(append-only, 에이전트명 포함) 3개 신설. 기존 할 일 대장 3곳·결정 기록 2곳은 옮기지 않고 상태 어휘·`담당:` 필드·기록 칸 형식·경로 동반 인용 규칙으로만 연결한다. 애니메이션 묶음은 Docs/Animation_Plan.md 인덱스를 신설해 발견 문제를 푼다. - LLM Wiki 답: 답: 부분 채택(개념 이식) — 그대로 채택도, 완전 자체 설계도 아니다. 가져오는 것 다섯 가지: ① 원본/정제본 구분("raw는 불변, 정제본의 모든 수치 주장은 원본 경로를 붙인다") → TDGame은 이미 research/·Validation/·계획서 구조가 있어 규칙만 적으면 된다. ② 스키마 문서 1벌 → 원문이 'CLAUDE.md 또는 AGENTS.md'라고 명시했으므로 기존 AGENTS.md가 그 역할이며, SamurAIGPT식 3벌 분리(CLAUDE/AGENTS/GEMINI 각각 본문)는 드리프트를 낳아 배제. ③ index.md → Docs/README.md(저장소 관례 'README = 폴더 인덱스'를 따름), 항목 = 경로+한 줄 요약+언제 읽는지+갱신일. ④ log.md → Docs/Worklog/YYYY-MM.md, 항목 접두어 `## [날짜 시각] 에이전트 | 작업ID | 동사 | 제목`로 `rg "^## \["`로 파싱 가능(커밋 메시지 '작업'만으로는 추적 불가한 사실 7의 해법). ⑤ lint 개념 → 원문 6항목 중 고아·상호참조 누락·인덱스 누락·낡음 4개는 세기·비교 작업이라 결정론 파이썬으로(2026-07 이후 커뮤니티 결론: Towards Data Science 5,000파일 12.4초·API 0회, Mograbi CLI exit 1), 의미 모순만 분기 1회 범위 지정 LLM 점검. 버리는 것: (가) wiki/ 폴더에 코드 재요약 페이지 — 코드가 진실이고 Serena·grep으로 직접 읽으므로 요약본은 정보 손실+드리프트만 추가(Verdent 2026-04-06 '유지되지 않는 위키는 능동적으로 오도'), Docs가 이미 1.09MB라 index 모호성(77페이지 사례) 악화.

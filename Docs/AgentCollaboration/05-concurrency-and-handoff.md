# 05. 동시 작업과 죽은 세션 인수: 최신 기술로 해결되는가 (딥리서치 종합)

종류: 리서치 · 작성: 2026-09-18 claude · 방법: 웹 조사 7갈래 → 종합 → 반박 3렌즈(실현성·비용·보안) 2회 + 보수 2회. 사용자 질문: Codex가 애니메이션, Claude가 전투 C++를 동시에 할 때(가), Codex가 할당량 소진으로 죽은 뒤 Claude가 이어받을 때(나) 기록과 기억이 최신 기술로 해결되는가.

이 문서는 워크플로 종합안의 원문 정리다. 채택 여부는 `Docs/Tasks/decisions.md` '관리 체계' D-25와 D-32 이후 항목이 정하며, 채택된 규칙의 정본은 `../AgentRules.md`다.

## 1. 판정

### (가) 동시 작업
부분 해결(2회차 수정 반영) — 그리고 (가)의 전제 자체를 정정한다. Windows에서 실행 중인 언리얼 에디터는 Binaries/Win64/UnrealEditor-TDGame.dll을 잠근 채 로드하고, 라이브 코딩이 켜져 있으면 UnrealBuildTool이 빌드를 거부한다(엔진 HotReload.cs 277행 "Unable to build while Live Coding is active", 뮤텍스 이름은 UnrealEditor.exe 경로 기준이라 같은 엔진을 쓰는 워크트리 빌드도 함께 거부, 2026-09-18 로컬 소스 확인). 저장소 도구도 이를 전제한다: Tools/ue_editor.py cmd_build는 editor_pids()가 있으면 종료코드 2로 거부(123~127행, -WaitMutex -NoHotReload), Tools/README.md 20행 "에디터가 켜진 상태에서는 Build.bat 대신 라이브 코딩". 에디터 안 라이브 코딩은 함수 본문만 패치하고 디스크 DLL을 갱신하지 않으므로(L-build-01) 그 뒤의 UnrealEditor-Cmd 헤드리스 테스트는 옛 DLL을 돌린다. 따라서 "Codex가 에디터를 임대한 동안 Claude가 헤드리스로 빌드·테스트한다"는 1회차 전제는 폐기한다. 같은 작업 트리에서 Codex 애니메이션(에디터 필요)과 Claude 전투 C++(빌드는 에디터 종료 필요)는 동시가 아니라 시분할이다: 코드 편집만 병렬이고, 빌드·헤드리스 테스트·라이브 코딩·PIE(Play In Editor, 에디터 내 플레이)·MCP(Model Context Protocol) 도구 호출은 모두 에디터 자원 하나의 임대 안에서 순서대로 한다. 진짜 동시 빌드는 별도 체크아웃(git worktree 또는 사본) + 그 체크아웃 자체의 Binaries/Intermediate + Codex 에디터의 라이브 코딩 꺼짐이 있어야 가능하며(LFS 체크아웃·DDC(Derived Data Cache) 중복 비용), 헤드리스 테스트가 Content 없이 도는지 실험한 뒤 조건부로만 제안한다. 에디터 통째 임대의 근거는 Epic 공식 문서의 "MCP 도구 호출은 게임 스레드에서 직렬 실행되므로 클라이언트는 겹치는 호출을 내면 안 된다"(https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor, 2026-09-18 확인) 하나로 둔다. 1회차의 "Tools/uemcp.py가 세션 ID를 공용 파일에 저장해 덮어쓴다"는 사실이 아니므로 삭제한다(SESSION_FILE 상수는 정의만 있고 읽기·쓰기 없음, main()이 호출마다 connect()→initialize로 새 세션, 엔진 서버는 세션을 배열로 여러 개 보유; 실제 부작용은 반대로 DELETE 미전송에 의한 세션 누적, 경미). 기술로 풀리는 부분: ① 자원 임대(Backlog 11번 수정본 Tools/lib/resource_lock.py: mkdir 원자 잠금 + owner.txt mtime TTL, 진입부 검사에서 소유자 자신이면 mtime touch로 무비용 heartbeat, 자원 editor는 `open|closed` 모드를 가져 build·헤드리스 테스트는 closed 모드 획득 후에만) ② 공용 장부 쓰기는 파이썬 단일 write 1회(L-repo-03) 유지. 벤더 편집 도구(Codex apply_patch·Antigravity write_to_file)는 mtime 검사 없이 전체 재작성하므로 "동시 세션 중 편집 범위 = 자기가 청구한 대장 항목 영역의 코드 폴더(AgentRules 3절 시작 4단계 대응표) + 장부 파일의 자기 줄"이라는 규칙과 "벤더 MCP 클라이언트로 unreal-mcp 직접 호출 금지(uemcp.py 경유)" 규칙은 어떤 기술로도 대체되지 않는다(에이전트 이름을 규칙에 고정하지 않는다). 죽은 세션의 잠금 회수는 TTL 경과 또는 사용자 확인 뒤이며 즉시가 아니다.

### (나) 죽은 세션 인수
부분 해결(2회차 수정 반영). 죽은 Codex 세션이 "무엇을 어떤 순서로 건드렸고 마지막 발화가 무엇이며 무엇을 검사·계획 중이었나(제목 수준)"는 ~/.codex/sessions의 rollout JSONL(JSON Lines)로 모델 호출 없이 복원할 수 있다. 정정: reasoning 상세는 encrypted_content지만 이 기계의 TDGame rollout에서 reasoning 1,009건 중 471건(47%)이 평문 `summary[].text` 제목을 가지므로(2026-09-18 로컬 집계) "어떤 기술로도 복원 불가"는 "상세 추론과 하위 에이전트 send_message(gAAAAA… 암호화)는 불가, 요약 제목은 가능"으로 좁힌다. 명령은 `event_msg/item_completed` CommandExecution 항목이 평문 command 배열·cwd·exit_code·status·duration을 이미 담으므로 그것을 1차 소스로 쓰고 code-mode `exec` JS 문자열 정규식은 폴백으로만 둔다. 죽은 세션 판정은 "task_started에 짝(task_complete·turn_aborted·error) 없음 AND source≠subagent AND 마지막 레코드 후 무기록 경과(임계는 스크립트 상수) AND Worklog 마지막 시작 항목 담당=codex"로 하며(로컬 데이터에 turn_aborted 2건·error 0건이라 할당량 소진 rollout의 실제 형태는 첫 발생 때 실측 후 파서 갱신), 후보 탐색은 ~/.codex/session_index.jsonl로 먼저 줄인다. 그러나 3층 파서를 지금 만들지는 않는다: 할당량 소진은 Codex 앱·백그라운드 서버를 죽이지 않으므로 사람 1명 환경에서는 사용자가 Codex Desktop 스레드의 마지막 메시지를 읽어 대장 기록 칸에 3줄(완료·다음·검증)을 옮기는 무비용 경로가 먼저이고, 그 경로가 실패한 죽은 세션이 1회 관측된 뒤에만 Backlog 13번 Tools/draft_session_handoff.py를 착수한다(D-27 "2주 운영 뒤 Worklog 지표로 순서 결정"과 일치). 규칙 측 해법은 형식 변경 0으로 한다: 검증 가능한 단계마다 OP-29 기록 칸에 `YYYY-MM-DD 진행(<agent>): 완료 …, 다음 …, 검증 <명령>` 1줄, 인수는 담당 필드 교체 + 기록 칸 `YYYY-MM-DD 인수(<agent>): ← codex, 초안 <경로|앱 스레드>` 1줄. Worklog `진행` 유형·`인수:` 필드·보고 `메모리` 항목은 모두 [A] 규칙(OP-06·OP-08)과 AGENTS.md 15절 동시 수정을 요구하므로 삭제하며, 위험 명령(restart·PIE) 시각의 정본은 lock.log다. 인수자는 초안·앱 화면·전사를 사실로 쓰지 않고 git diff·빌드·테스트로 재검증한다. Codex Desktop 표면의 훅 발화는 미해결(#21639 Open)이라 Codex 계층 훅 예방은 실측 전까지 기대하지 않는다.

### 기록 전반
부분 해결(2회차 수정 반영). 자동 기록은 결정론 필드(도구 이름·저장소 상대 경로·종료 코드·출력 바이트·sha256·시각)를 토큰 0으로 남길 수 있으나 의도·성공 조건·판단·다음 행동은 어떤 기술도 생성하지 못한다. 저장소 장부(NOW·Worklog 단일 파일·대장·Lessons)가 정본이고, 자동 산출물은 Saved/AgentOps/{journal,handoff}/(git 제외, OP-18)에만 둔다. 설계 문장은 "허용 목록 + 자유 텍스트 3필드(cmd 200자·마지막 AgentMessage 2KB·live-<agent>.md 2KB)는 표준 정규식 마스킹(`(api[_-]?key|token|secret|password|bearer)\s*[=:]\s*\S+` → `***`)"으로 고친다(실측: CommandExecution.command에 pwsh 전체 명령줄, exec input에 JS 본문, FileChange.changes 값에 파일 전체 내용이 있어 키(경로)만 쓴다). 유출·오염 경로 정정: ① Blender MCP 텔레메트리(약관이 프롬프트·생성 코드·장면 메타데이터·뷰포트 스크린샷을 'AI 학습·연구·공개 데이터셋' 영구 라이선스로 수집, https://raw.githubusercontent.com/ahujasid/blender-mcp/main/TERMS_AND_CONDITIONS.md 2026-09-18 확인)는 "학습·공개 데이터셋 라이선스를 명시한 유일한 경로"이지 "유일한 외부 유출 경로"가 아니다(Codex 전역 config의 Notion 원격 MCP·openaiDeveloperDocs, Claude 전역 settings의 Notion 플러그인, Cursor 클라우드 인덱싱이 장부 내용을 외부로 보낼 수 있는 허용 채널). 위험한 인스턴스는 GUI Blender 5.2 사용자 애드온(blender_mcp.py 4203~4207행 telemetry_consent default=True, 1.7)이며, 저장소 경로(.mcp.json 등 → Run-BlenderMCP.ps1 → Start-BlenderMCP.ps1 → bootstrap_blender.py)는 .runtime의 addon.py를 td_blender_mcp_upstream으로 직접 로드해 get_telemetry_consent가 fail-closed(항상 False)이고 Start-BlenderMCP.ps1은 9876 포트 소유자가 bootstrap blender.exe가 아니면 throw하므로 GUI Blender에 연결될 수 없다. 따라서 1회차의 "get_addon_status telemetry_consent=false 확인"은 거짓 안심 증거이며, 검증은 GUI Blender 5.2 파이썬 콘솔에서 `bpy.context.preferences.addons['blender_mcp'].preferences.telemetry_consent = False; bpy.ops.wm.save_userpref()` 후 재평가 출력 캡처, 또는 더 단순하게 5.2 사용자 애드온 자체를 비활성화·삭제하고 기록한다. 홈 설정 파일의 실제 경로는 `~/.gemini/antigravity/mcp_config.json`(내용 `uvx blender-mcp`, env 없음; PyPI blender-mcp 2.0.0은 mcp-for-blender 2.0.0으로 위임하는 셤이라 규칙은 두 이름과 pip 설치본을 모두 금지)이고 OP-31·D-19가 적은 `~/.gemini/config/mcp_config.json`은 빈 폴더라 같은 변경에서 경로를 정정한다. ② Claude 자동 메모리는 매 세션 주입되는 것이 색인 MEMORY.md(2,501바이트)뿐이고 나머지 14개 파일(합계 47,076바이트)은 필요할 때만 읽히므로 이전의 세션당 토큰 절감은 사실상 0이며 blocker가 아니다 → 이미 규정된 OP-30·D-27 이관 순서 안의 항목으로 되돌리고, 이전 규칙을 3갈래(실측 함정·엔진 제약만 L-ID로 날짜·미검증 표기, 절차·도구 위치는 README 표 참조가 있으면 메모리에서 삭제, 인덱스 포인터는 삭제)로 한정한다. ③ Serena 메모리(.serena/memories/)는 .gitignore 93행으로 제외되어 git diff로 검토되지 않는 유일한 교차 에이전트 메모리 채널이다(현재 logs만 있어 오염 없음) → decisions.md에 (a) `.serena/*` + `!.serena/memories/` 또는 (b) check_agent_ops --config 검사 1줄 중 결정 요청. Docs/AgentRules.md는 16,596자·180줄로 02-design-final 21행 상한(≤13,000자)을 이미 초과했으므로 1층 설치에 재측정과 상한 수치 정정을 포함한다.

## 6. 어떤 기술로도 풀리지 않는 것(운용으로만)
- (가)는 동시가 아니라 시분할이다. 빌드는 에디터 종료가 전제(라이브 코딩 뮤텍스·DLL 잠금)이므로 코드 편집만 병렬이고 빌드·테스트·PIE·MCP 호출·재시작 순서와 미저장 에셋 처리는 사람이 정한다. 잠금은 동시 실행을 막을 뿐 순서를 정하지 않는다. 진짜 병렬 빌드는 별도 체크아웃과 디스크·DDC 비용을 사람이 수용해야 가능하다.
- 겹치는 영역을 동시에 할당하지 않는 작업 분배. Codex apply_patch·Antigravity write_to_file은 남의 변경을 조용히 되돌리므로 대장 청구 시 사람이 영역이 겹치지 않게 배분해야 한다. 규칙은 '청구 항목 영역'을 기준으로 삼을 뿐 배분 자체는 못 한다.
- 벤더 MCP 클라이언트(.mcp.json·.codex/config.toml·.gemini/settings.json·.agents/mcp_config.json)로 unreal-mcp를 직접 호출하는 경로는 어떤 잠금도 못 막는다. 'uemcp.py 경유' 규칙 준수만이 방어다.
- Codex의 상세 추론과 하위 에이전트 메시지는 암호화되어 복원되지 않는다(요약 제목·명령·파일 순서·마지막 발화는 복원 가능). 남는 방법은 기록 칸 `진행` 줄을 검증 단계마다 쓰는 규칙 준수이며 Antigravity·Cursor는 훅으로 강제할 수 없다.
- 할당량 소진은 프로세스를 죽이지 않고 사전 경고도 없다(#2903, #45977). 잠금은 TTL 경과까지 남고, 긴 작업 전 잔여 할당량 확인과 작업 단위를 작게 자르는 운용, 그리고 죽은 세션 뒤 앱 스레드에서 마지막 메시지를 읽어 기록 칸에 옮기는 일은 사람이 한다.
- 커밋 분리는 사람이 한다(git add -p, single-committer). 같은 작업 트리에서 에이전트 자동 커밋은 남의 헝크를 흡수한다.
- 훅 신뢰 승인(Codex /hooks, Claude 프로젝트 훅), Codex Desktop·VS Code 확장 및 Antigravity IDE Windows에서의 훅 실제 발화 확인, GUI Blender 5.2 애드온 텔레메트리 동의 해제 또는 애드온 삭제, 홈 설정 파일(~/.gemini/antigravity/mcp_config.json·~/.claude/settings.json) 수정과 D-19 결정은 사람이 1회 수행·검증한다.
- 장부 내용이 허용된 외부 채널(Notion MCP·플러그인, Cursor 인덱싱, 벤더 모델 API)로 전송되는 것은 사용자가 알고 수용하는 사항이며 기술로 막지 않는다. 학습 라이선스 채널(Blender MCP 텔레메트리)만 차단 대상이다.
- 인수자가 전사 요약·앱 화면·인수 초안을 '검증된 사실'로 취급하지 않고 git diff·빌드·테스트로 재확인하는 습관. 초안의 `상태: 인수됨` 갱신과 폐기도 인수자의 몫이다.
- 벤더 메모리(Claude 자동 메모리·Codex memories·Antigravity knowledge)와 git 밖 Serena 메모리에 프로젝트 사실을 넣지 않고 Docs/Lessons에 적는 규율. 쌓인 Claude 메모리는 사람이 3갈래로 판정하며 옮겨야 한다.

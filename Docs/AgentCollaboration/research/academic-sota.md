# 학계·업계 에이전트 메모리 최신 동향(2025-07~2026-09)

## 주제
2025-07~2026-09 에이전트 메모리 동향 중 이종(heterogeneous) 다중 에이전트·다중 세션 연속성 관련 항목 조사 — Claude Code·Codex·Antigravity·Cursor가 같은 작업 트리를 쓰는 1인 파일 기반 체계(AGENTS.md/AgentRules/NOW/Worklog/Lessons/대장)에 대한 실무 적용 판정. 모든 웹 사실 확인일 2026-09-18.

## 핵심 사실
- [벤치마크 결론] 2026 벤치마크 비판이 일치함: LoCoMo는 약 35세션·지식 갱신 미평가(Mem0 2026-09-17), MemDelta(2026-06-29)는 임베딩만 바꿔도 결론이 뒤집히고 단순 RAG≈전체 문맥, 에이전트 자기 메모리(42%)<기본 검색(47%), 고가 시스템이 50배 비용으로 클라우드 RAG와 동률임을 보임. Anatomy(2026-02)도 '이론적 약속에 못 미침'. → 외부 메모리 서비스 불채택 판단은 2026-09 시점 학계 결과와 일치.
- [낡음(staleness)] STALE(2026-05) 최고 55.2%: 갱신 증거를 검색해도 적용을 못 함. 해법 방향은 '명시적 상태 판정'(CUPMem: 구조화된 상태 통합+전파). Mem0 보고서(2026-09-17)도 시간 감쇠(decay)는 고관련 낡은 사실을 못 다룬다고 명시. → 코딩 사실은 시간이 아니라 사건(커밋·리팩터)으로 낡으므로 에빙하우스식 감쇠(MemoryBank 계열)는 부적합, '대체됨(superseded_by)' 링크와 단일 상태 파일(NOW.md)이 정답 방향.
- [파일이 이김] LongMemEval-V2(2026-05)에서 '메모리=파일 관리' AgentRunbook-C(궤적을 파일로 두고 매니페스트+검사 스크립트로 코딩 에이전트가 조사) 74.9% > 기본 Codex 69.9% > RAG 58.6%. 평가 항목 '환경 함정(gotchas)'·'전제 인식'은 Docs/Lessons와 동형. Anthropic 메모리 도구(2025-09-29)도 /memories 파일 디렉터리, Letta Context Repositories(2026-02-12)도 git 마크다운. → 벤더·학계 모두 파일 기반으로 수렴.
- [공유 메모리 4대 고장] Governed Shared Memory(2026-06-23): 무단 누출·낡은 정보 전파·모순 잔존·출처 붕괴. 원시 연산 4개(범위 한정 검색, 시간적 대체, 출처 추적, 정책 기반 전파)는 마크다운 필드·규칙으로 옮길 수 있고, 서비스(MemClaw) 자체는 불필요.
- [출처 결속] MemIR(2026-05-25): 비구조 텍스트는 출처 감시 오류를 낳음, 주장은 증거 있을 때만 승인. TMA-NM(2026-06-23): 쓰기 시점 출처 결속이 필수이며 요약을 거쳐도 신뢰도가 오르면 안 됨. Mem0 행위자 인지: 사용자 진술 vs 에이전트 추론 구분. Poison Once(2026-04): 도구/웹 관찰 하나가 미래 작업을 오염. → 항목마다 writer(에이전트+세션)·source(사용자/추론/도구/웹)·evidence를 쓰기 시점에 기록하면 세 논문의 핵심을 규칙으로 흡수.
- [일관성 유비] 컴퓨터 구조 관점 논문(2026-03): 다중 에이전트 메모리의 최우선 과제는 일관성(캐시 일관성 유비). → 에이전트별 사설 파일(캐시)과 공용 파일(메모리)을 나누고, 공용 파일은 단일 작성자(스크립트 생성)로 두는 것이 가장 단순한 일관성 모델.

## 권장하지 않는 것
- **MemOS(MemCube) 제품 채택** — 로컬 SQLite 지원은 있으나 Claude Code/Codex 플러그인 없음(OpenClaw·Hermes·DSH만), 메모리가 DB라 git diff 검토 불가, '35.24% 토큰 절감' 근거 미상세. MemCube의 '출처·버전 메타데이터' 개념만 C5로 흡수.
- **A-MEM 라이브러리** — 노트마다 임베딩+LLM 호출, 장기 대화 벤치 지향. '새 항목이 옛 항목 링크·속성 갱신' 개념은 Lessons 상호 참조로 충분.
- **Zep/Graphiti, Mem0(OpenMemory MCP 포함), Letta 서버** — 기존 판정(서비스형·diff 불가) 유지. MemDelta(2026-06)가 고가 메모리 시스템=클라우드 RAG 동률·50배 비용을 실증. 개념(이중 시간 유효 구간, 행위자 인지)만 C5에 차용.
- **Letta Code/Context Repositories 제품** — 설계는 우수하나 5번째 벤더 추가이며 메모리 저장소가 Letta 에이전트에 귀속. 설계만 C3·C7로 복사.
- **Letta Agent File(.af)** — 자체 README가 '메모리 블록은 타 프레임워크에 없어 적응 필요'라고 명시. Letta 간 이동용.
- **W3C AI Agent Memory Interop CG / SAIHM 인터넷 초안** — 보고서 전용 그룹, 단일 저자 독립 제출 초안, 지갑 파생 키·공개 체인 감사·양자내성 신원 등 로컬 파일 체계와 무관.
- **Engram 명세, Portable Agent Memory, Mesh Memory Protocol** — 채택 거의 없음/8쪽 초기 연구/v0.2.3 자체 배포. 필드 이름(id/status/scope)만 C5에서 호환되게 채택.
- **MCP 메모리 원시 요소** — 2026-07-28 명세에 존재하지 않음. 확장 프레임워크만 있고 메모리 확장 제안은 미확인.
- **AAIF의 AGENTS.md 메모리 확장** — 존재하지 않음. 2026-06-08 블로그는 LLM Wiki 소개일 뿐 절·프런트매터·다중 에이전트 규약 제안 없음.
- **Grite(CRDT git ref WAL) 등 git 참조 기반 이벤트 로그** — Beads 불채택 사유와 동일(1인·순차에는 과함, 별도 데몬·CBOR). 에이전트별 추가 전용 파일(C3)로 충분.
- **STORM(쓰기 시점 버전 검사) 직접 구현** — 연구 코드. 원리는 C3(단일 작성자)+C4(임대)로 더 단순하게 달성.
- **agenthandoff 도구 자체** — Claude Code·Gemini CLI·Cursor 미지원, 0스타 초기. 번들 명세(필드 구성)만 C1이 차용.
- **시간 감쇠(에빙하우스) 기반 망각(MemoryBank 계열)** — 코딩 사실은 시간이 아니라 사건으로 낡음. Mem0 보고서(2026-09-17)도 감쇠가 고관련 낡은 사실을 못 다룬다고 명시. superseded_by 링크(C5)로 대체.
- **Claude 앱 메모리 내보내기/가져오기** — 웹/데스크톱 앱 전용 평문, 실험 단계, Claude Code 해당 없음.
- **MemR3·Memory-as-Action·SEDM·CUPMem 등 학습 기반 메모리 제어기** — 연구 단계(훈련·재생 인프라 필요). '재현 가능해야 승인' 원리만 C6에 반영.

## 신뢰도
중간~높음. 논문 사실은 arXiv 초록/HTML(2026-09-18 확인) 기반이며 본문 세부 수치는 미검증. 벤치마크·표준화 현황·파일 기반 수렴 결론은 복수 출처가 일치해 높음. Codex 롤아웃 파일의 압축 여부·스키마(0.154.0)와 Antigravity 훅 이벤트명은 미확인(추정)이라 C1·C4는 저장소에서 파일 경로·형식 실측 후 확정 필요. 토큰 절감 수치(C7 20~40%)는 추정.

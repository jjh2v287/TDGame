# 작업 기록·청구·자원 공유 관례 조사

종류: 리서치 · 작성: 2026-09-18 claude · 웹 사실은 URL과 확인 날짜 기준. 결론은 `../../AgentCollaboration_Plan.md` 1절.

## 주제
여러 벤더의 AI 에이전트(Claude Code · OpenAI Codex · Gemini CLI/Antigravity)와 사람 1명이 같은 저장소(단일 작업 트리, 단일 PC)에서 번갈아 작업할 때 "누가 무엇을 했고 무엇을 하는 중인지"를 파일 기반·저비용으로 공유하는 관례 조사 — 작업 기록, 작업 청구(claim), 에이전트용 이슈 트래커, 커밋 식별, 단일 인스턴스 자원 잠금, 현재 상태 한 장 문서. (조사일 2026-09-17)

## 핵심 사실
- (1) 작업 기록 형식은 두 계열로 갈린다. ①매 세션 덮어쓰는 단일 '현재 상태' 파일(pi-agent-memory latest.md 2026-08-24, graph.med HANDOFF.md 2026-09-12) + ②append-only 이력 파일(Karpathy log.md 2026-04-04는 `## [날짜] 동작 | 제목` 접두어, graph.med LOG.md는 최신이 위·약 200줄에서 archive 회전). 세션마다 새 파일(softaworks .claude/handoffs/YYYY-MM-DD-HHMMSS-slug.md, 10개 필수 절)은 파일 폭증·읽기 비용 때문에 소수. '최신 찾기' 비용이 append-only의 약점이고, 상태와 이력을 한 파일에 섞으면 '최신'이 모호해진다는 것이 pi-agent-memory #50의 명시적 근거.
- (1) 크기 관리 실측 기준: 로그 파일은 약 200줄에서 회전(graph.med), Claude 자동 메모리 MEMORY.md는 첫 200줄/25KB만 로드(code.claude.com/docs/en/memory), Codex는 AGENTS.md 연결 합계 32 KiB(project_doc_max_bytes)에서 중단 — 현재 AGENTS.md 약 16KB이므로 여유는 있으나 절을 더 붙이면 한계에 가까워진다.
- (2) 작업 청구 관례의 공통 최소 단위는 '상태=진행 중 + 담당자 필드'(graph.med status: claimed + owner; Arggon #16 assignee + in_progress; battyterm/TICK.md claimed_by; beads `bd update --claim`). 공통 규칙: 담당 필드가 비어 있을 때만 청구, 에이전트당 동시 청구 1개(graph.med), 오래된 청구는 N일(graph.med 7일)·TTL/PID 소멸(Hermes) 기준으로 회수, 청구 변경은 코드 변경보다 먼저 기록. 동시 편집 회피는 (a) 항목별 파일 분리 + OS 파일 잠금(battyterm), (b) .tick.lock 30초 잠금(TICK.md), (c) SQLite 트랜잭션(Hermes) — 사람 1명이 세션을 순차로 돌리는 환경에서는 잠금 파일 없이 '담당 필드 규칙'만으로 충분하다는 것이 graph.med 사례.
- (2) 이 저장소의 Docs/Tasks/README.md 34행은 이미 doing 전환 시 '날짜와 담당(세션)'을 기록하라고 하지만 담당 식별자 어휘(claude/codex/gemini/user)와 필드 위치가 정해져 있지 않아 실제 추적이 불가능하다(사실 7: 커밋 메시지로도 추적 불가).
- (3) Beads(bd)는 2026-04 v1.0에서 JSONL(JSON Lines)+SQLite를 버리고 Dolt embedded로 이동. 이슈 데이터는 .beads/ 아래 gitignore 되어 git 이력에 남지 않으며(discussion #2332), 이력 공유는 Dolt 원격 또는 `bd export` JSONL로만 가능. `bd init`이 AGENTS.md를 수정하고 Codex/Claude/Cursor 훅을 설치. 설계 목표는 Gas Town의 20~30개 병렬 에이전트(Mike Mason 2026-01-22). 사람 1명 + 순차 세션 3개에는 새 CLI(Command Line Interface, 명령줄 인터페이스) 의존성과 git 밖 데이터라는 비용이 이득보다 크다.
- (3) git 기반 대안(에이전트별 worktree/브랜치)은 '병렬 실행'의 파일 충돌 해결책이지 '누가 무엇을 했나' 추적책이 아니며, 순차 병합·3~5개 한계(battyterm). 추론: 언리얼 프로젝트는 Content/ LFS 바이너리·Intermediate·DerivedDataCache가 워크트리마다 중복되고 에디터 인스턴스는 하나뿐이라 워크트리 이득이 거의 없다(저장소 사실 기반 추론, 웹 출처 없음).
- (4) 커밋 식별 기본 동작: Claude Code는 기본으로 `Co-Authored-By: Claude … <noreply@anthropic.com>` 트레일러를 붙이며 attribution.commit 으로 변경·숨김(includeCoAuthoredBy는 deprecated). Codex CLI는 `[features].codex_git_commit = true` 일 때만 `Co-authored-by: Codex <noreply@openai.com>`(commit_attribution 키, 2026-02-17 PR #11617, opt-in). Gemini CLI는 기본 트레일러 없음(discussion #11447 미답변, 2026-02-27 기준). Antigravity는 2026-09-17 현재 미확인(clocwork #38). Linux 커널은 `Assisted-by:` 트레일러를 쓰고 'AI는 Signed-off-by 금지'. 이 저장소는 AGENTS.md 82행·Docs/Tasks/README.md 39행에 따라 사람이 커밋하므로 트레일러는 보조 신호일 뿐이며, 주 신호는 저장소 안 작업 기록이어야 한다.
- (5) 단일 인스턴스 자원 잠금의 검증된 두 방식: mkdir 원자성 잠금 디렉터리 + mtime 기반 stale 회수(기본 600초) + 획득/해제/강제해제 로그(lock-folder-util 2026-08-22), 배타적 파일 핸들 + 항상 해제 + 프로세스 종료 시 OS 자동 해제(Unreal-MCP PR #294 2026-09-14, "AutomationTool is single-instance"). 이 저장소는 세 에이전트 설정이 모두 같은 unreal-mcp 8000 포트·blender 9876 포트를 가리키므로(.codex/config.toml 2·11행, .gemini/settings.json 6·10행) 동시 세션이 열리면 충돌 가능. 잠금 위치는 git 제외 폴더(Saved/, AGENTS.md 80행)가 적합.
- (6) '현재 상태 한 장' 문서의 수렴 형식: 날짜·작성 에이전트, 진행 중(청구 목록), 방금 끝난 것, 막힘, 다음 행동 3개, 남은 위험(pi-agent-memory #50, graph.med HANDOFF.md, softaworks 'Current State Summary/Immediate Next Steps'). 세션 종료 시 재작성, 세션 시작 시 가장 먼저 읽기. 종료 게이트는 '경고만, 차단 안 함'(pi-agent-memory).
- (a) 세션 시작 때 AGENTS.md 읽기를 보장하는 각 벤더의 공식 경로: Claude는 CLAUDE.md만 읽으므로 프로젝트 CLAUDE.md에 `@AGENTS.md` import(Windows는 심볼릭 링크 대신 import 권장); Codex는 AGENTS.md 네이티브이나 전역 ~/.codex/AGENTS.md가 먼저 연결되고 프로젝트 파일이 뒤에 와서 '나중 것이 우선'이지만 모순 지침은 임의 선택 위험(사실 3의 '참고 하지 않는다' 줄 제거 필요); Gemini는 `context.fileName: ["AGENTS.md","GEMINI.md"]` 설정으로 직접 로드 가능(전역 ~/.gemini/GEMINI.md의 모순 줄도 제거 필요). 세 벤더 모두 SessionStart 훅 출력이 컨텍스트로 주입되므로(Claude stdout, Gemini/Codex additionalContext) '상태 문서 읽기'를 지침이 아니라 훅으로 결정론화할 수 있다. 단 Codex는 프로젝트 .codex/ 훅에 신뢰 승인이 필요하고, Claude SessionEnd는 1.5초 예산·Gemini SessionEnd는 best-effort라 '종료 시 기록'은 훅보다 지침+검사 스크립트가 안전.
- Karpathy LLM Wiki(2026-04)는 '불변 원본에서 LLM이 위키 전체를 쓰는' 지식베이스 패턴이며 코드 저장소·사람이 쓰는 설계 문서에는 적용 지침이 없다. v2(2026-09)는 200~500문서에서 깨져 신뢰도·감쇠·검색 계층을 덧붙였다. 이 프로젝트에 가져올 가치가 있는 부분은 ①log.md의 파싱 가능한 항목 접두어, ②index.md 한 줄 요약 목록, ③lint(끊긴 링크·고아 페이지·모순 점검) 세 가지뿐이다.
- 벤더별 사설 메모리(Claude 자동 메모리는 PC 로컬·Claude 전용, Codex/Antigravity도 각자)는 공유되지 않으므로 다른 에이전트가 봐야 할 교훈은 저장소 파일에만 쓰는 규칙이 필요하다(사실 6과 code.claude.com/docs/en/memory '자동 메모리는 machine-local').

## 권장하지 않는 것
- **Beads(bd) 도입** — v1.0(2026-04)부터 Dolt embedded로 바뀌어 이슈 데이터가 .beads/에 gitignore 되어 git 이력에 남지 않고(discussion #2332), 공유하려면 Dolt 원격이나 JSONL export가 따로 필요. `bd init`이 AGENTS.md를 수정하고 벤더별 훅을 설치해 관리 표면이 커짐. 설계 목표가 Gas Town의 20~30개 병렬 에이전트라 사람 1명·순차 세션 3개에는 과잉이며, 사용자의 '지금은 규칙 우선' 요구(사실 8c)와 충돌. 가져올 아이디어(ready 작업 = 선행 done, 원자적 claim, 해시 ID)는 이미 Docs/Tasks 규칙 2·담당 필드로 흡수 가능.
- **Karpathy LLM Wiki를 프로젝트 문서 체계로 채택** — 패턴 자체가 '불변 원본(raw/)에서 LLM이 위키 전체를 쓰는' 지식베이스용이고 코드 저장소 적용 지침이 없다(gist 2026-04-04). 이 프로젝트는 사람이 쓰는 설계·계획서와 실측 문서가 이미 1.09MB 있어 '원본/위키' 이분법이 맞지 않고, v2(2026-09)가 보여주듯 200~500문서에서 index가 깨져 검색·감쇠 계층이 필요해진다. log.md 항목 접두어·index 한 줄 요약·lint 세 아이디어만 Worklog·계획서 인덱스에 빌려 쓰면 충분.
- **에이전트별 git worktree/브랜치 운용** — 병렬 실행의 파일 충돌 해결책이지 추적 수단이 아니며 순차 병합·3~5개 한계(battyterm). 언리얼 프로젝트는 Content/ LFS 바이너리와 Intermediate/DerivedDataCache가 워크트리마다 중복되고 에디터·MCP 인스턴스는 하나뿐이라(사실 기반 추론) 비용만 늘어난다. 사용자 세션이 순차적이면 단일 작업 트리 + NOW.md 자원 줄로 충분.
- **세션마다 새 핸드오프 파일(softaworks 방식 .claude/handoffs/YYYY-MM-DD-HHMMSS-slug.md, 10개 필수 절)** — 파일이 세션 수만큼 늘어 '최신 찾기' 비용이 생기고(pi-agent-memory #50이 지적한 약점), 10개 절·점수 검증은 토큰 절약 요구와 반대. .claude/ 아래라 Codex·Gemini가 보지 않는다. 덮어쓰는 NOW.md + 월별 Worklog 두 파일이 같은 정보를 더 싸게 준다.
- **TICK.md·kanban-md·Hermes kanban·MatLomax worklog(MCP 서버) 같은 잠금·DB 기반 작업 보드 도구** — 잠금 파일·SQLite·데몬이 필요해 세 벤더 모두에 도구 등록·학습 비용이 들고, 동시 청구 경쟁이 실제로 없는 순차 환경에서는 '담당 필드' 규칙만으로 같은 효과. 사용자 요구 (c) '도구보다 규칙 우선'에 반함.
- **커밋 트레일러(Co-Authored-By / Assisted-by)를 '누가 했나'의 주 신호로 삼기** — 이 저장소는 사람이 커밋하고(AGENTS.md 82행, Docs/Tasks/README.md 39행) 메시지가 '작업' 수준이라 트레일러가 붙지 않는다. Gemini CLI는 기본 트레일러가 없고(#11447 미답변), Antigravity는 미확인(clocwork #38, 2026-09-17), Codex는 opt-in 기능 플래그가 필요. 벤더마다 동작이 달라 일관성을 보장할 수 없으므로 저장소 안 Worklog가 주 신호, 트레일러는 보조.
- **SessionEnd 훅으로 작업 기록 자동 생성** — Claude SessionEnd는 훅 전체 1.5초 예산이고 Gemini SessionEnd는 best-effort(완료 대기 안 함), Codex 프로젝트 훅은 신뢰 승인이 필요해 '종료 시 반드시 기록'을 보장하지 못한다. 종료 기록은 지침 + 완료 보고 자기 점검 + (2단계) 검사 스크립트로, 훅은 SessionStart의 NOW.md 주입에만 쓰는 편이 안전.
- **벤더 사설 메모리(Claude 자동 메모리, Codex memories, Antigravity knowledge)에 공유 교훈 저장** — 모두 벤더·PC 로컬이라 다른 에이전트가 볼 수 없다(사실 6, code.claude.com/docs/en/memory). 다른 에이전트도 알아야 할 함정·해결책은 Worklog '교훈' 항목 → 정리 시 Tools/README 5절 또는 해당 문서로 승격하는 경로만 허용.

## 신뢰도
중간~높음. 관례(1)(2)(6)와 잠금 방식(5)은 2026-03~09 사이의 공개 사례 다수가 같은 구조로 수렴해 근거가 안정적. Beads(3)는 v1.0 Dolt 전환과 gitignore 사실을 공식 저장소·토론에서 확인. 커밋 식별(4)은 Claude·Codex는 공식 문서로 확인했으나 Claude 기본 트레일러의 정확한 문구(모델명 포함 여부)는 버전에 따라 다르고, Gemini CLI는 미답변 토론, Antigravity는 2026-09-17 현재 미확인이라 이 부분만 낮음. 워크트리 비적합 판단 중 언리얼 특유 비용은 저장소 사실에 기반한 추론이며 웹 출처가 없음.

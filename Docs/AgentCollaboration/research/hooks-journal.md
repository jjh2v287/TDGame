# 벤더 훅으로 자동 작업 기록 만들기

종류: 리서치 · 작성: 2026-09-18 claude(다중 에이전트 워크플로 2차) · 웹 사실은 URL과 확인 날짜 기준. 판정은 `../05-concurrency-and-handoff.md`.

## 주제
벤더 훅(Claude Code·Codex CLI 0.154.0·Gemini CLI 0.35.3·Antigravity 2.14.0)으로 '자동 작업 기록'을 남기는 설계 조사 — PostToolUse 페이로드, SessionEnd/Stop 신뢰도, 단일 파이썬 스크립트 공용화, 동시 쓰기 안전성, 기존 사례, Stop 훅 강제 요약 패턴 (조사일 2026-09-18, 저장소 C:\Project\TDGame, Windows 10)

## 핵심 사실
- [1-Claude] PostToolUse stdin JSON에 tool_name·tool_input(Edit/Write→file_path, Bash→command, MCP 도구는 mcp__서버__도구)·tool_response·session_id·transcript_path·cwd가 들어간다. PostToolUseFailure(tool_error)와 StopFailure(error=rate_limit|billing_error|max_output_tokens 등, 2.1.274에서 실측)가 있어 '할당량 소진 순간'을 훅으로 잡을 수 있는 유일한 벤더다. 매처는 정규식(`Edit|Write|MultiEdit|NotebookEdit|Bash|mcp__.*`).
- [1-Claude] SessionEnd는 모든 훅 합쳐 1.5초 예산(개별 timeout으로 60초까지 상향)이며, 실측(2.1.261 macOS)으로 /exit·/clear·SIGTERM·터미널 닫기에는 오고 SIGKILL에는 안 온다. 비동기 작업(예: `claude -p` 요약)은 완료 전 죽는다(#41577). Windows에서 터미널 창을 강제로 닫을 때의 동작은 실측 자료가 없다(추정: 프로세스 강제 종료면 SIGKILL과 같게 무음).
- [1-Codex 0.154.0] PostToolUse에 tool_name·tool_input·tool_response·turn_id·session_id·cwd가 있고 Bash·apply_patch 모두 tool_input.command에 들어간다. apply_patch는 패치 본문이 command이므로 파일 경로는 `*** Update File:/*** Add File:` 줄을 파싱하거나 tool_response에서 얻어야 한다. MCP 도구(Blender·언리얼)도 발화한다. 페이로드에 transcript_path가 없다(rollout 파일은 ~/.codex/sessions에서 session_id로 찾는다).
- [1-Codex] SessionEnd는 reason이 항상 "other", 기본 1초·최대 3초, 정상 종료·보관/삭제·30분 유휴에만 발화하고 하위 에이전트에는 안 온다. 사용량 한도·레이트 리밋으로 멈출 때 이를 알리는 훅·notify 이벤트가 없다(#45977, 2026-09-16 열림). 따라서 '할당량 사망'은 Codex 쪽 훅으로는 잡을 수 없고 PostToolUse 누적 기록과 rollout 전사로만 복원 가능하다(추정: Stop도 오류 정보 없이 안 오거나 무의미).
- [1-Codex 신뢰] 비관리 훅은 /hooks에서 정의를 검토·신뢰해야 실행되고 신뢰는 ~/.codex/config.toml `[hooks.state.<key>] trusted_hash`(정의 SHA256)에 저장된다. 훅 명령 문자열이 바뀌면 다시 검토 대상이 되어 조용히 건너뛴다(시작 시 경고 1줄). 프로젝트 .codex/hooks.json은 프로젝트가 trusted일 때만 로드된다(TDGame은 trusted 확인). `codex exec`는 신뢰 없으면 진단 없이 건너뛴다(#46210). `features.hooks`는 공식 설정 문서에 '기본 꺼짐'으로 남아 있으나 제3자 기록은 0.150.1부터 기본 켜짐 — 로컬 config.toml에 hooks 키가 없으므로 /hooks로 실제 활성 여부를 한 번 확인해야 한다.
- [1-Codex 위험] Windows에서 Codex 데스크톱 앱·IDE 확장은 훅을 무시한다는 보고(#18090 2026-04, #21639 2026-05)가 해결 확인 없이 남아 있다 → 사용자가 '앱'으로 돌리면 기록이 안 남을 수 있어 CLI로 1회 검증 필요. 큰 파일 편집 시 훅 무음 실패(#18067, 0.121.0 기준, 열림)도 있다.
- [1-Gemini CLI 0.35.3] AfterTool에 tool_name·tool_input(write_file/replace→file_path, run_shell_command→command)·tool_response·mcp_context·transcript_path·timestamp가 있다. SessionEnd는 공식 문서가 'CLI는 완료를 기다리지 않고 흐름 제어를 무시'라고 명시(best effort). 턴 단위로 신뢰할 수 있는 종료 신호는 AfterAgent(prompt, prompt_response, stop_hook_active, decision:"deny"+reason)다. 기본 타임아웃 60000ms, 프로젝트 훅은 지문(fingerprint) 변경 시 경고. 환경변수 GEMINI_PROJECT_DIR·GEMINI_SESSION_ID·CLAUDE_PROJECT_DIR(별칭).
- [1-Antigravity] 설정 파일은 워크스페이스 `.agents/hooks.json`(IDE·CLI·2.0 공통) 또는 전역 `~/.gemini/config/hooks.json`, 구조는 '훅 이름 → {enabled, PreToolUse[], PostToolUse[], PreInvocation[], PostInvocation[], Stop[]}' 맵. 이벤트는 5종뿐이고 SessionEnd·SessionStart는 없다. PostToolUse는 toolCall{name,args}(run_command→CommandLine·Cwd, write_to_file→TargetFile·CodeContent, replace_file_content→TargetFile·TargetContent·ReplacementContent), stepIdx, error, conversationId, transcriptPath, workspacePaths. Stop은 실행 루프 종료마다(턴 단위) terminationReason(model_stop|max_steps_exceeded|error)·fullyIdle을 주며 decision:"continue"로 차단 가능. 기본 타임아웃 30초, stdin/stdout JSON, 비0 종료는 턴을 중단시킬 수 있으므로 항상 exit 0. IDE 2.14.0에서 실제 발화는 로컬 미검증(공식 문서상 지원).
- [2-공용 스크립트] 4벤더 모두 '명령 문자열 + stdin JSON'이므로 `python C:/Project/TDGame/Tools/agent_journal.py --agent <claude|codex|gemini|antigravity> --event <post_tool|session_start|session_end|stop|stop_failure>` 하나로 정규화할 수 있다(선례: hookstack 동일 .mjs 공유, atuin의 Claude/Codex/Antigravity 3핸들러, agenthooks 타입 정규화). 정규화 레코드: ts, agent, session_id(Antigravity는 conversationId), cwd, tool, files[](경로 키 매핑: file_path / apply_patch 파싱 / file_path / TargetFile), command(command / command / command / CommandLine), ok, error, transcript(있으면). Windows 실행 셸이 벤더마다 다르므로(Claude=Git Bash 기본, Gemini 예제=PowerShell, Codex=command_windows, Antigravity=미문서) 슬래시 경로·인용부호 없는 절대 경로·셸 기능 미사용으로 쓴다.
- [2-예산] 훅 본체는 Codex SessionEnd 1초·Claude SessionEnd 1.5초 안에 끝나야 하므로 파이썬 시작(약 50~100ms, 추정)+파일 1줄 추가만 하고, 요약·병합 같은 무거운 일은 하지 않거나 분리 프로세스(subprocess DETACHED_PROCESS)로 넘긴다. Claude PostToolUse는 `async:true`, Codex는 0.148.0부터 비동기 훅 지원.
- [2-동시 쓰기] 파이썬 open(path,'a')는 Windows UCRT가 'FILE_END로 seek → WriteFile' 두 단계로 append를 흉내내므로(write.cpp 725-728행) 두 세션이 같은 파일에 붙이면 겹침·유실이 가능하다. 안전한 선택은 ① 세션마다 파일을 나눠 공유 자체를 없애기(`Docs/Worklog/auto/<날짜>-<agent>-<session8>.jsonl`), ② SQLite WAL(표준 sqlite3, timeout= 지정; 같은 호스트 로컬 디스크면 다중 프로세스 안전, Codex도 ~/.codex에 WAL 사용), ③ msvcrt.locking 바이트 잠금 또는 ctypes CreateFile(FILE_APPEND_DATA, 섹터 크기 이하 쓰기). ①이 가장 단순하고 git diff로 검토 가능하다.
- [3-사례] claude-mem(Claude 전용, SQLite+Bun 워커, Stop에서 LLM 요약), ai-memory(Rust, 20+ 하네스, SQLite+git 마크다운 위키, 네이티브 Windows 실험적), claude-code-handoff(Stop 턴별 백업 + /handoff-recover로 급사 재구성), ddaanet/handoff(Stop이 JSONL에서 최근 프롬프트·파일 추출), disler hooks-mastery(13 이벤트 → logs/*.json, 동시성 없음), atuin PR #4117(3벤더 셸 명령 캡처), engram(Claude·Codex 플러그인, Stop→SessionEnd 이전), cc-donut(StopFailure로 레이트 리밋 인수). 공통 교훈: 기록은 PostToolUse 누적이 본체이고 세션 종료 훅은 '표식'일 뿐이다.
- [4-Stop 강제 요약] Claude는 Stop에서 exit 2+reason(또는 decision block)으로 '요약을 쓰기 전엔 못 멈춤'을 강제할 수 있고 stop_hook_active로 1회만 밀어붙여야 무한 루프를 피한다. 신뢰도 한계: Stop은 턴마다 오지 세션 종료·Ctrl+C·할당량 소진에는 안 온다(engram 실측 24.5% 누락), 레이트 리밋 중 Stop 게이트는 무한 반복을 만든다(codex-plugin-cc #306), Stop 출력에 additionalContext를 쓰면 JSON 검증 실패(claude-mem #1290). Gemini는 AfterAgent deny, Antigravity는 Stop decision:"continue", Codex는 Stop decision block으로 같은 패턴이 가능하다. 결론: 강제 요약은 '해당 대장 항목에 완료|막힘 항목이 없으면 1회 차단'하는 결정론 검사로만 쓰고, 기록의 본체로 삼지 않는다.
- [인수 (나)] 어떤 벤더든 급사 시 남는 확실한 자료는 ① 작업 트리 diff, ② 훅이 누적한 PostToolUse 저널(파일·명령 순서), ③ 벤더 전사(Claude JSONL·Codex rollout JSONL·Gemini chats JSON; Antigravity는 .pb라 파싱 곤란)다. 따라서 '전사+저널+git diff → 인수 문서'를 만드는 결정론 스크립트가 훅보다 더 확실한 보험이며, Claude에는 StopFailure(rate_limit) 훅으로 그 스크립트를 즉시 돌려 인수 초안을 남길 수 있다.

## 권장하지 않는 것
- **Codex `notify` 설정으로 턴 종료 기록** — 명령 슬롯이 하나뿐이며 이미 computer-use 플러그인 실행 파일("turn-ended")이 점유하고 있어 우리 스크립트로 바꾸면 그 플러그인이 깨진다. 턴 완료만 알리고 도구·파일 정보가 없다.
- **SessionEnd 훅만으로 세션 종료·요약을 남기는 설계(claude-mem식 LLM 요약 포함)** — Claude 1.5초·Codex 1초 예산, Gemini는 완료를 기다리지 않음, SIGKILL·할당량 사망에는 어느 벤더도 안 옴, Antigravity에는 이벤트 자체가 없음. `claude -p` 요약은 완료 전 죽는다(#41577).
- **훅이 Docs/Worklog/<월>.md·Docs/NOW.md·Tools/README.md에 직접 쓰기** — 두 세션 동시 append는 Windows C 런타임의 seek+write 방식 때문에 유실 가능하고, NOW.md 덮어쓰기는 마지막 쓰기 승리를 그대로 재현한다. 기존 규칙(장부는 부모 세션만 1회 기록)과도 충돌한다.
- **Stop 훅을 세션 종료 신호로 사용** — 턴마다 발화하는 이벤트라 Ctrl+C·exit·터미널 닫기·할당량 소진에는 오지 않는다. engram 실측 294 세션 중 72개(24.5%) 종료 누락.
- **disler 방식 logs/<event>.json 읽고-전체-다시쓰기** — 두 세션이 같은 JSON 배열을 동시에 읽고 쓰면 한쪽 기록이 통째로 사라진다. 추가 전용 JSONL 또는 세션별 파일이어야 한다.
- **Antigravity 전사(.pb)를 인수 자료로 파싱** — ~/.gemini/antigravity-ide/conversations/*.pb는 문서화되지 않은 프로토버프라 형식 변경에 취약하다. Antigravity는 훅 저널이 유일한 텍스트 흔적이므로 PostToolUse 캡처를 빠뜨리면 안 된다.
- **외부 서비스형 메모리(Mem0·Zep·Letta 등)나 Bun 워커 상주 프로세스** — 이미 확정된 판단(git diff 검토 불가, 유지 부담)과 같다. 훅 예산 안에서 HTTP 호출은 실패하기 쉽고, 상주 프로세스는 Windows 재부팅·안티바이러스와 충돌한다.

## 신뢰도
중상. Claude Code·Codex·Gemini CLI의 페이로드 필드·타임아웃·신뢰 절차는 2026-09-18 공식 문서에서 직접 확인했고, SessionEnd/StopFailure 실제 동작은 2026-09 실측 이슈(2.1.261·2.1.274)로 뒷받침된다. Antigravity는 공식 문서(이벤트 5종·.agents/hooks.json·페이로드)로 확인했으나 IDE 2.14.0에서의 실제 발화·실행 셸은 로컬 미검증(중). 낮은 부분: Codex 데스크톱 앱에서 훅 발화 여부(2026-04/05 미해결 보고), Codex `features.hooks` 기본값(공식 설정 문서 '꺼짐' vs 제3자 '0.150.1부터 켜짐' 상충 — 로컬 config.toml에 키 없음, /hooks로 확인 필요), Windows 강제 종료 시 Claude SessionEnd 동작(실측 없음, 추정). 파이썬 시작 시간·구현 규모는 추정치.

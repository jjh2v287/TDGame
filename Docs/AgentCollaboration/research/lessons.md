# 문제→해결 기록(교훈) 관례 조사

종류: 리서치 · 작성: 2026-09-18 claude · 웹 사실은 URL과 확인 날짜 기준. 결론은 `../../AgentCollaboration_Plan.md` 1절.

## 주제
"문제 발생 → 해결 → 기록 → 재사용" 관례 조사: 교훈(lessons)·함정(gotchas)·사후 분석(postmortem) 기록 형식, 기록 정리(lint), 점진적 공개(progressive disclosure), 읽기 트리거, 증거 명명, 규칙 승격 기준 — TDGame의 흩어진 "실측 함정" 통합 관점

## 핵심 사실
- [기록 형식] 업계에 단일 표준은 없으나 수렴하는 최소 필드는 6개: 증상(오류 문구 원문) / 원인 / 해결(실행 명령 한 줄) / 재현 / 적용 범위(버전·경로·도구) / 날짜+상태. jerdaw는 '증상|유력 원인|해결' 표, Floyd는 'did/failed/fix/next time', SRE는 13개 필드 전체 사후 분석. 가벼운 함정 기록과 무거운 사후 분석을 같은 형식으로 쓰는 곳은 없다.
- [기록 형식] TDGame 현재 상태: Tools/README.md:73-79 '5. 실측된 함정'은 '증상 → 해결' 한 줄 불릿 6개(원인·날짜·범위·증거 없음). Claude 메모리 tdgame-anim-notify-facts.md는 날짜+사실 목록+Why+How to apply 형식이나 Claude만 본다. 함정이라는 말이 Docs 12개 파일과 Tools/README.md에 흩어져 있고, 결정 기록은 Docs/Tasks/decisions.md(D-01, 질문/선택지/권장/영향/결정)와 Docs/MonsterAI_CombatSim/00-decision-record.md(D1~, 근거 파일명+결론 번호 인용) 두 형식이다.
- [lint] Karpathy 원문의 lint 항목은 5개(모순, 뒤집힌 옛 주장, 고아 페이지, 페이지 없는 개념, 빠진 상호 참조)이고, 구현체(Astro-Han)는 index 누락·깨진 링크·오래된 참조·모순·인용 누락을 검사한다. 이 중 구조 검사(index 동기화, 링크·경로 존재, 필수 필드, 중복 증상 문구, 대체 사슬)는 결정론 스크립트로 가능하고, '의미적 모순'만 LLM 주기 점검이 필요하다.
- [lint] gh-aw-cao의 agents-md-curator는 규칙 파일 자체를 정기 lint한다: 존재하지 않는 파일·명령 참조, 다른 문서와의 중복 문단, 200줄·10KB 초과. TDGame Tools/README.md 등록표에 없는 폴더 3개(Animation, AnimationAuthoring, BlenderAnimation)와 .gemini/scripts 미등록은 정확히 이 검사가 잡는 종류다.
- [lint] 만료 처리의 보수적 합의: 신뢰도 숫자 감쇠(LLM Wiki v2 제안)보다 ADR식 명시적 상태(active / superseded by ID / deprecated)와 날짜, 그리고 git 이력을 쓰는 편이 검증 가능하다. 번호는 재사용하지 않고 옛 항목은 지우지 않는다(Anthropic도 시점 정보는 '옛 패턴' 접힘 절로 보존).
- [크기 기준] 상시 로드 층: Claude MEMORY.md 200줄/25KB 초과분은 로드조차 안 됨, CLAUDE.md 200줄 목표, agents-md-curator 목표 200줄/10KB, Codex AGENTS.md 체인 합계 32 KiB(TDGame AGENTS.md 16KB로 절반 소진). 필요 시 층: SKILL.md·Cursor 규칙 500줄, 참고 파일 100줄 넘으면 목차, 참조 깊이는 인덱스에서 1단계.
- [크기 기준] 두 논문의 함의: 컨텍스트 파일은 성공률을 높이지 못하고 비용만 20%+ 늘리며(2602.11988), 파일 구조 4변수는 준수율에 영향이 없고 세션 내 감쇠(함수 하나당 -5.6%)만 유의(2605.10039). 즉 상시 층은 최소로, 기록은 작업 시점에 적시 주입하는 편이 효율적이다.
- [트리거] 세 에이전트 모두 훅으로 '실패 → 기록 검색 → 문맥 주입'이 가능하다: Claude PostToolUseFailure(매처 Bash)+additionalContext, Codex PostToolUse(비0 종료 코드에도 실행)+additionalContext, Gemini AfterTool(tool_response.error)+hookSpecificOutput.additionalContext. 세 훅이 같은 파이썬 스크립트를 호출하면 된다.
- [트리거] 영역별 자동 로드: Claude는 .claude/rules/*.md의 paths 프런트매터(해당 파일을 읽을 때만 로드)와 하위 디렉터리 CLAUDE.md(그 디렉터리 파일을 읽을 때 로드), Codex·Cursor·Gemini는 하위 디렉터리 AGENTS.md/GEMINI.md를 지원. 단 Codex는 AGENTS.md 안에 적힌 경로를 자동으로 읽지 않으므로 '읽어라'는 지시가 있어야 한다.
- [트리거] 문서 우선 반사(doc-first reflex): kunglao 사후 분석은 '실패 시 다음 행동은 반드시 문서·소스 읽기, 플래그만 바꿔 재실행 금지'를 규칙화했고, jerdaw는 '막혔을 때 순서(문서→로그→테스트→git log)'를 AGENTS.md에 넣으라고 한다. 이는 AGENTS.md 9절 '작업 중'에 한 줄로 추가 가능한 종류다.
- [트리거] 에이전트 전용 메모리의 위험: Codex 이슈 #39223에서 오래된 지속 메모리가 현재 AGENTS.md를 덮어썼다. TDGame처럼 Claude 메모리 14개·Codex·Antigravity 지식이 각자 프로젝트 사실을 갖고 있으면 저장소 기록과 어긋날 때 아무도 모른다.
- [증거 명명] 감사 분야 관례는 '식별자_설명_YYYY-MM-DD.확장자'와 계열별 폴더. 에이전트 증거 관례는 스크린샷 단독 금지, manifest(json)에 출처·실행·검사 결과를 묶고 PR/문서에는 정본 하나만 링크, 원본이 바뀌면 편집 말고 재생성. TDGame Docs/Validation은 'P1-pie-checks-2026-09-12.md'처럼 작업 ID+날짜가 있는 파일과 'meteor-active.png'처럼 없는 파일이 섞여 있고 README.md는 옛 GAS 내용이다.
- [승격 기준] Anthropic: '같은 실수 두 번째, 리뷰가 잡음, 지난 세션과 같은 교정을 또 침'이면 CLAUDE.md로. Floyd·productcompass: 같은 'next time'/가설이 3회 이상이면 스킬·규칙으로, 반박되면 강등, 고위험은 훅으로 강제. ADR 운영: 사소한 선택·임시 우회책은 기록하지 않음, 결정은 '왜', 규칙은 '어떻게'이며 규칙에서 결정 ID를 링크. /doctor는 '함정·근거·기본값과 다른 관례'만 CLAUDE.md에 남긴다.
- [승격 기준] 반대 방향도 정해져 있다: 코드에서 도출 가능한 것, 저장소 개요, CLAUDE.md에 이미 있는 것은 메모리에 저장하지 않는다(Claude 자동 메모리 규칙, ETH 논문). 즉 '기록할 가치' 판정 = 코드·문서·엔진 문서에 없고 다시 알아내려면 토큰이 드는 것.
- [Karpathy LLM Wiki 적합성] 원문 대상은 외부 자료(논문·기사) 수백 건을 위키로 컴파일하는 개인 지식 베이스이며, 자료 1건 ingest마다 페이지 10~15장을 갱신한다. TDGame의 필요는 자기 생산 사실 수십~수백 건의 재사용이므로 3층 중 '스키마(=AGENTS.md)'와 'index/log 분리', 'lint 개념'만 빌리면 되고 raw/wiki 전체 구조와 페이지 재작성 비용은 맞지 않는다.
- [결정론 도구 우선] Anthropic: 결정론적 작업은 스크립트로(실행은 컨텍스트 무소모). agentmemory 저자: 수작업 유지보수는 반드시 버려진다. 사용자 선호(반복 작업은 프로그램)와 일치하며, lint·검색·인덱스 재생성·증거 목록 생성이 스크립트 후보다.

## 권장하지 않는 것
- **Karpathy LLM Wiki 전체 구조(raw/ + wiki/ 개체별 페이지 + ingest마다 10~15페이지 갱신 + 임베딩)를 그대로 도입** — 원문 대상은 외부 자료 수백 건의 개인 지식 베이스다. TDGame의 기록은 자기 생산 실측 사실 수십~수백 건이며 사용자는 토큰 절약을 우선한다. ingest마다 여러 페이지를 다시 쓰는 비용이 재사용 이익을 넘고, 원문 자신도 수백 페이지까지는 index+검색으로 충분하다고 적었다. 빌릴 것은 스키마=AGENTS.md, index/log 분리, lint 개념 세 가지뿐이다.
- **신뢰도 점수·시간 감쇠·자동 결정화(LLM Wiki v2 제안)** — 구현 정의가 없고(같은 gist 댓글이 지적) 다중 에이전트 감사 추적이 없다. ADR식 명시 상태(active/superseded/deprecated)+날짜+git 이력이 검증 가능하고 스크립트로 검사된다.
- **모든 함정을 SRE 13필드 사후 분석으로 작성** — 항목당 비용이 커서 기록을 건너뛰게 된다. 사후 분석은 트리거 기준(데이터 손실, 1세션 이상 낭비, 에디터 상태 파괴)에 걸린 사건에만 쓰고 나머지는 6필드 항목으로 충분하다.
- **교훈 전부를 AGENTS.md 본문에 넣기** — AGENTS.md는 이미 16KB이며 Codex 체인 상한이 32 KiB, Claude 권장이 200줄이다. ETH 논문은 상시 컨텍스트가 비용 20%+를 늘리면서 성공률을 못 올린다고 했고, 2605.10039는 파일 구조를 아무리 바꿔도 준수율이 안 변하고 세션 내에서 잊힌다고 보였다. 상시 층은 한 줄 규칙+ID, 본문은 대장에서 적시 주입이 맞다.
- **에이전트 전용 메모리(Claude auto memory, Codex memory, Antigravity knowledge)를 공유 기록의 저장소로 쓰기** — 서로 못 보며, Codex 이슈 #39223처럼 오래된 개인 메모리가 현재 저장소 규칙을 덮어쓰는 사고가 실제로 보고됐다.
- **의미적 모순 검사를 커밋 전 자동 게이트로 만들기** — LLM 판단이 필요해 결정론적이지 않고 비용이 든다. 월 1회 에이전트 패스로 충분하며, 구조 검사(경로·인덱스·중복 문구·상태 사슬)만 스크립트 게이트로 둔다.
- **기존 Docs/Validation 파일을 새 명명 규칙에 맞춰 일괄 이름 변경** — Docs 문서와 계획서가 이미 경로로 참조하고 있어 링크가 깨진다. 새 파일부터 규칙을 적용하고 기존 파일은 생성된 INDEX.md로 연결한다.
- **교훈 검색을 위한 벡터 검색·임베딩 도입** — 수백 항목 규모에서는 증상 필드의 오류 문구 원문에 대한 rg/키워드 매칭이 더 정확하고 비용이 0이다. LLM Wiki v2도 100~200페이지를 넘어야 병목이 생긴다고 했다.

## 신뢰도
중간~높음. 도구 동작(Claude·Codex·Gemini·Cursor의 로드 순서, 크기 한계, 훅 이벤트와 문맥 주입)은 2026-09-17에 공식 문서를 직접 읽어 확인했으므로 높음. 기록 형식·승격 횟수(2~3회)·크기 기준(200줄/500줄)은 여러 실무 출처가 수렴하는 경험칙이지 단일 표준이나 측정 결과가 아니므로 중간. 두 arXiv 논문은 초록 수준으로만 확인했다. TDGame 적용안은 저장소를 직접 확인한 경로(Tools/README.md:73-79, AGENTS.md:85-106, Docs/Validation 목록, 두 결정 기록 머리)에 근거하되 설계 자체는 제안이다.

# MCP 메모리 서버 계열(ai-memory·engram·basic-memory·claude-mem·Serena 등)

종류: 리서치 · 작성: 2026-09-18 claude(다중 에이전트 워크플로 2차) · 웹 사실은 URL과 확인 날짜 기준. 판정은 `../05-concurrency-and-handoff.md`.

## 주제
여러 벤더 코딩 에이전트(Claude Code·Codex CLI·Gemini CLI·Antigravity·Cursor)가 MCP(Model Context Protocol, 모델 컨텍스트 프로토콜)로 공유하는 '메모리 서버' 계열 2026-09 조사 — 동시 작업(가)과 죽은 세션 인수(나) 해결력 중심

## 핵심 사실
- 문제 (가)의 핵심인 언리얼 에디터·Blender 단일 인스턴스 충돌(재시작·PIE·미저장 에셋)은 조사한 메모리 서버 어느 것도 다루지 않는다. 메모리 서버는 '기억'을 공유할 뿐 '자원 임대(lease)'를 제공하지 않는다. 유일하게 parallel-memory-mcp가 claim_worktree/release_worktree라는 청구 원시를 갖지만 스타 0·커밋 10의 초기 프로젝트다. 결론: 자원 임대는 저장소 안의 잠금 파일 규칙(예: Tools/ue_editor.py에 lease 서브커맨드)으로 푸는 것이 가장 싸고 diff로 검토된다.
- 공용 파일(Worklog·NOW.md·Tools/README.md)의 마지막 쓰기 승리는 '단일 라이터 큐를 가진 서버로 쓰기를 옮길 때만' 해결된다. 그 조건에서 사람이 diff로 검토 가능한 파일을 정본으로 유지하는 것은 ai-memory(OKF 마크다운 wiki를 별도 git 저장소로 관리)와 parallel-memory-mcp(마크다운 미러)뿐이다. Engram·claude-mem·agentmemory는 SQLite가 정본이라 git diff 검토 불가(Engram git sync는 gzip JSONL).
- 문제 (나)에서 '세션 사망 시 남는 것'은 캡처 방식에 따라 갈린다. 훅 기반 즉시 기록(ai-memory·claude-mem·agentmemory·Cognee)은 프롬프트·도구 호출 단위로 디스크에 남아 중간 판단이 살아남고, 명시적 저장(Engram·Basic Memory·Serena·Anthropic 참조 서버·Hindsight)은 에이전트가 write를 호출한 것만 남아 갑작스런 종료엔 무력하다. 단, 훅 기반도 SessionEnd 전 사망 시 '통합 요약·handoff 생성'은 건너뛰므로 수동 마무리(ai-memory finalize-session --agent codex)가 필요하다.
- ai-memory run(managed workstream)은 Codex 종료 후 Codex의 네이티브 세션 저장소를 읽기 전용으로 가져와 append-only 장부에 넣고 다음 하네스(Claude Code)에 bounded delta를 주입한다. 이는 (나)의 '중간 판단·다음 단계 계획 소실'을 도구 중 가장 직접적으로 메운다. Gemini CLI·Cursor는 managed resume 미지원.
- Codex 훅의 한계: SessionEnd 타임아웃은 3초로 클램프되고, codex exec(비대화형)에서는 SessionEnd가 발화하지 않는 측정(0.153.4, 2026-09-10, 제3자)이 있다. 할당량 소진 시 SessionEnd 발화 여부는 어떤 문서에도 없다(추정: 프로세스가 살아 있으면 사용자가 종료할 때 발화). 따라서 Codex 쪽 (나) 대비는 '세션 끝 훅'이 아니라 '턴 단위 즉시 기록 + 종료 후 트랜스크립트 읽기'에 의존해야 한다.
- Antigravity(IDE·CLI 공통 하네스)의 훅 이벤트는 PreToolUse/PostToolUse/PreInvocation/PostInvocation/Stop 5개뿐이며 SessionStart/SessionEnd가 없다. 설정은 .agents/hooks.json(작업공간)·~/.gemini/config/hooks.json(전역), MCP는 ~/.gemini/config/mcp_config.json. 자동 캡처 도구들은 PreInvocation(첫 호출)을 세션 시작으로 간주하고 세션 종료는 수동이다.
- 설정 파일 5벌 문제: ai-memory(install-mcp --client ×5 + install-hooks --agent ×5)와 Engram(engram setup <agent> ×5)·agentmemory·claude-mem(install --ide)은 설치기가 5개 클라이언트 설정을 대신 써 준다. Basic Memory·Hindsight·Serena·Anthropic 참조 서버는 수동으로 5벌을 써야 한다. 어떤 도구도 '한 파일'로 5개 클라이언트를 구동하지는 못한다(각 클라이언트 설정 형식이 다름).
- 동시 쓰기 안전성 실측 근거: Anthropic 참조 server-memory는 프로세스 2개가 같은 memory.jsonl을 쓰면 나중 쓰기가 앞을 덮어씀(코드 확인; parallel-memory-mcp 벤치에서 20건 중 1건 생존). Serena는 파일 잠금 없음(#1235, 미해결; main에 원자적 temp+replace만 추가). Basic Memory는 동시 MCP 세션에서 edit_note append 유실(LWW) 미해결·Windows에서 'database is locked' 잔존. Engram v1.20.0은 stdio 프로세스 다중 실행 시 migration에서 SQLITE_BUSY로 MCP 연결 끊김(#1182, 2026-09-14 미해결; v2 rc에서 재시도 창 확장). ai-memory는 HTTP 서버 1개+단일 라이터 큐라 프로세스 경합 자체가 없다.
- 토큰 비용(도구 정의 크기는 도구당 100~200토큰으로 추정): Serena 메모리 도구 6개(≈1k, 단 Serena 전체는 25개 안팎), Anthropic 참조 9개(≈1.5k), Mem0 11개, Graphiti 15개, ai-memory 18개(≈2~4k), Basic Memory 18+개, Hindsight 27~30개(≈5k+), MemPalace 45개, agentmemory 54개(린 8개; 세션 시작 주입 ≈2,000토큰), sqlite-memory-mcp 92개. Claude Code는 도구 설명이 컨텍스트 10%를 넘으면 자동 지연 로드하지만 Codex·Gemini CLI·Cursor·Antigravity는 전부 적재한다(추정: 각 공식 문서에 지연 로드 기능 없음). 검색 결과 주입량은 ai-memory 16KiB 상한, Engram mem_context 16KiB 기본, Hindsight recall 4,096토큰 기본, claude-mem 3계층(50~100→500~1,000토큰).
- 보안: Mem0 자체 호스팅 서버 CVE 7건(2026-05~07, 최고 9.8 무인증 메모리 읽기/쓰기/삭제), Graphiti CVE 3건(Cypher 인젝션 8.1, 인증 우회 7.3, 9.1), claude-mem CVE 1건(저심각 2.0, 12.0.0 수정). ai-memory·Engram·Basic Memory·agentmemory·Hindsight는 검색 기준 CVE 없음(Hindsight·ai-memory는 localhost 무인증 기본). 메모리 오염(OWASP ASI06)에 대해 '메모리를 데이터로만 렌더링·격리'하는 완화를 문서화한 후보는 없었다 — 자동 캡처 도구일수록 도구 출력(웹·에셋 이름)이 메모리에 그대로 들어가므로 프로젝트 규칙(도구 결과는 데이터)이 유일한 방어선이다.
- 벤더 내장·호스팅 흐름: Mem0 OpenMemory 로컬 경로는 2026-07-29 삭제되어 공식 MCP는 호스팅 전용. Supermemory v1 저장소 폐기·로컬 바이너리는 Windows 명시 없음. Letta memory-mcp는 2025-09 이후 갱신 없음·클라우드 키 필수. Cognee는 로컬이라도 LLM 키 필수(Claude·Codex 플러그인은 훅 6개 자동 캡처).
- Windows 10 네이티브 설치 난이도(낮음→높음): Serena(이미 설치) < Anthropic 참조(npx) < Engram(go install 또는 exe, 백신 오탐 가능) < Basic Memory(uvx, Windows SQLite 경합 이슈) < claude-mem(Node 20+Bun 워커) < ai-memory(exe 실험적, WinSW 서비스 권장, 훅 경로 검증 필요) < Hindsight(pip, 임베디드 Postgres 첫 부팅 60~90초) < agentmemory(iii.exe 수동) < Cognee(Python PATH+LLM 키) < Graphiti/Mem0 서버(Docker 다중 컨테이너).
- 사용자 전제('순차 세션·사람 1명에서는 파일이 낫다')는 동시 작업이 생기면 부분적으로 바뀐다. 그러나 (가)의 진짜 병목은 에디터·Blender 자원과 git 변경 섞임이고 이는 메모리 서버 밖의 문제다. 메모리 서버 도입 없이도 가능한 최소 대안: ① 자원 lease 파일(Tools/), ② Worklog는 append-only 유지·NOW.md는 lease 보유자만 재작성, ③ Codex 사망 대비로 ~/.codex/sessions의 rollout JSONL에서 마지막 어시스턴트 메시지·계획을 추출해 Worklog '막힘' 항목으로 넣는 결정론 스크립트(추정: Codex 세션 저장 경로는 버전별 확인 필요).

## 권장하지 않는 것
- **Mem0 (호스팅 MCP·자체 호스팅 서버·OpenMemory)** — OpenMemory 로컬 경로가 2026-07-29 삭제되어 공식 MCP는 호스팅 전용(도구 11개, 명시적 저장). 자체 호스팅 서버는 FastAPI+Postgres+Neo4j 3컨테이너에 CVE 7건(2026-05~07, 최고 9.8 무인증 메모리 읽기/쓰기/삭제, 9.3 LLM 키 평문 노출). Claude Code·Codex 훅 예제 PR #6761은 2026-09-11 미병합 종료. git diff 검토 불가.
- **Graphiti / Zep MCP** — LLM 키 필수(구조화 JSON 출력 요구, 소형 모델 실패), FalkorDB/Neo4j Docker 필요, 도구 15개, 2026 CVE 3건(Cypher 인젝션 8.1·인증 우회 7.3·9.1). 그래프 DB 정본이라 diff 불가. 문제 (가)(나) 어느 쪽도 직접 다루지 않음.
- **Letta memory-mcp** — Letta 클라우드 키 필수, 도구 80개(컨텍스트 압박), 마지막 갱신 2025-09-09, GitHub 저장소 404. Letta Code는 자체 에이전트 하네스이지 공유 메모리 서버가 아님.
- **Supermemory 로컬** — MIT·로컬 바이너리는 있으나 curl|bash/npx 설치로 Windows 명시 없음, ./.supermemory 임베디드 그래프(diff 불가), 자체 호스팅에서 MCP는 플랫폼 전용이고 Claude Code·Codex는 환경변수 플러그인 경유. 자동 캡처는 '모델이 알아서 도구 호출'에 의존.
- **MemPalace** — 도구 45개, ChromaDB 정본(diff 불가), Windows 미문서. Claude Code·Codex·Cursor 훅 자동 저장은 있으나 사람 검토 불가와 도구 수 때문에 토큰 절약 성향과 충돌.
- **sqlite-memory-mcp(RMANOV) / mcp-memory-service(doobidoo)** — 각각 도구 92개, Codeberg 이전으로 이력 리셋·Python 무거운 의존. 동시성(WAL)은 되지만 diff 불가·도구 과다.
- **claude-mem·Cognee를 '토큰 절약' 목적으로 도입** — 둘 다 압축·추출에 LLM 호출이 필수(claude-mem은 30일 후 사용자 Anthropic 플랜 소비, Cognee는 LLM_API_KEY 상시 과금). 사용자 성향과 정면 충돌하므로 (나) 해결 목적이 아니면 후보에서 제외.
- **메모리 서버로 언리얼 에디터·Blender 단일 인스턴스 충돌을 풀려는 시도** — 조사한 모든 후보가 자원 임대·잠금 기능이 없다. 이 문제는 Tools/ 아래 lease 파일 규칙(보유자·만료·PID)과 AGENTS.md 15절 청구 규칙 확장으로 푸는 편이 diff 검토 가능하고 비용이 0이다.

## 신뢰도
중간~높음. ai-memory·Engram·claude-mem·Basic Memory·Serena·Anthropic 참조 서버의 저장 형식·동시성·훅 지원은 공식 문서·이슈·코드로 확인(2026-09-18). 토큰 비용 수치는 도구당 100~200토큰 가정의 추정이며, Codex·Gemini·Antigravity가 MCP 도구 정의를 지연 로드하지 않는다는 점도 추정이다. ai-memory의 Windows 10 네이티브 안정성은 공식 문서가 '실험적'이라 실측 없이는 낮은 확신.

# 관측 추적(OpenTelemetry)으로 벤더 중립 기록 남기기

종류: 리서치 · 작성: 2026-09-18 claude(다중 에이전트 워크플로 2차) · 웹 사실은 URL과 확인 날짜 기준. 판정은 `../05-concurrency-and-handoff.md`.

## 주제
관측 추적(OpenTelemetry 등)으로 벤더 중립 '누가 무엇을 했나' 기록을 자동으로 남기는 방법 — Claude Code·Codex·Gemini CLI·Antigravity·Cursor 지원 현황, Windows 로컬 수집기 비교, Docs/Worklog 대체/보완 판정 (조사일 2026-09-18)

## 핵심 사실
- 벤더별 자체 OTel 내보내기: Claude Code(로그·메트릭 정식, 트레이스 베타, 환경 변수 또는 settings.json env 블록으로 저장소 단위 설정 가능), Codex(로그·트레이스·메트릭, 사용자 ~/.codex/config.toml [otel]만 가능하고 프로젝트 설정으로 덮어쓰기 불가, 메트릭 기본값이 Statsig 클라우드라 none 또는 otlp로 바꿔야 함), Gemini CLI(로그·메트릭·트레이스, OTLP 또는 로컬 outfile), Antigravity IDE/CLI(없음, 기능 요청 #366 open), Cursor(Enterprise 플랜 팀 설정 전용, 트레이스 없음). 즉 Antigravity·Cursor는 훅으로만 기록할 수 있다.
- '오늘 codex가 편집한 파일 목록' 질의 가능성: Claude Code는 OTEL_LOG_TOOL_DETAILS=1이면 tool_decision.file_path(Read/Edit/Write)와 tool_parameters.bash_command·mcp_server_name·mcp_tool_name이 나가므로 답할 수 있음. Codex OTel 이벤트(codex.tool_result)는 공식 문서상 소요·성공·출력 스니펫이며 인수(파일 경로) 포함 여부는 미확인 → Codex는 PostToolUse 훅의 tool_input.command나 git diff와 결합해야 함(이 사용자의 Codex 0.154는 exec 도구가 JavaScript 코드 문자열이라 경로가 구조화되어 있지 않음). Gemini CLI는 tool_call.function_args에 경로 포함. Antigravity 훅은 toolCall.args, Cursor 훅은 afterFileEdit.file_path로 경로를 준다.
- 개인정보·프롬프트 노출 기본값: Claude Code는 프롬프트·응답·도구 내용 모두 <REDACTED>(옵트인 4단계: USER_PROMPTS, ASSISTANT_RESPONSES, TOOL_DETAILS, TOOL_CONTENT; RAW_API_BODIES는 전체 요청 본문). 단 user.email·user.id·session.id는 항상 붙는다(로컬 수집기면 문제 없음). Codex log_user_prompt 기본 false. Gemini CLI는 logPrompts 기본 true라 반드시 false로 꺼야 한다. o11y-dev 훅은 기본이 SHA-256 해시+길이. Arize 하네스는 세 범주 모두 기본 꺼짐.
- 죽은 세션 인수(나)에 OTel이 주는 것: 도구 호출 순서·파일 경로·MCP 서버 이름·시간·토큰·마지막 응답(Claude는 OTEL_LOG_ASSISTANT_RESPONSES=1, Codex는 Stop 훅 last_assistant_message 또는 롤아웃 agent_message). 주지 못하는 것: 중간 판단과 다음 단계 계획(Codex 추론은 롤아웃에서도 encrypted_content, Claude 사고는 내보내지 않음). 따라서 Worklog 시작 항목(범위·성공 조건)은 여전히 유일한 '의도' 기록이다.
- 동시 작업(가)에 OTel이 주는 것: 에이전트별 MCP 호출(unreal/blender) 타임라인으로 '누가 언제 에디터를 만졌나' 사후 감사와 겹침 검출. 주지 못하는 것: 실시간 잠금(로그 내보내기가 5초 배치·비동기라 예방 수단이 아님). 예방은 PreToolUse 훅 + 잠금 파일(Tools/)이 담당하고 OTel은 증거 역할.
- 세션 누락 검출 자동화: session.count/SessionStart 이벤트가 있는데 짝이 되는 Stop/SessionEnd(Claude·Codex·Cursor 훅, Codex 종료 시 플러시)가 없으면 스크립트가 NOW ②절의 '기록 누락 의심'을 생성할 수 있다. 할당량 소진 중단은 프로세스가 살아 있어 이미 배치된 이벤트는 대부분 도착한다(추정).
- Windows 설치 난이도(로컬에 Docker·Go 없음, Python 3.12 있음 기준): otelcol-contrib MSI(서비스 자동 시작, 설정 1개 YAML) < otel-desktop-viewer zip(단일 exe, 실행 중일 때만 수신) < Phoenix pip(파이썬, 트레이스 전용이라 훅 브리지 필요) << SigNoz·OpenLIT·Langfuse(Docker Desktop 또는 WSL2 Docker Engine 필요, RAM 4~16GB, ClickHouse).
- 저장 용량(추정): 내용 가림 상태의 OTel 이벤트는 건당 약 0.5~2KB. 세션당 도구 호출 300건 기준 0.3~1MB, 월 10~30MB(TOOL_DETAILS 켜면 약 2배, TOOL_CONTENT 켜면 트랜스크립트 수준인 세션당 3~10MB에 근접). 비교 실측: Claude 트랜스크립트 세션당 약 10MB, Codex 롤아웃 약 3MB. file exporter 기본 회전 100MB×100개, otel-desktop-viewer 파일 DB 기본 상한 2GB.
- 질의 방법: (1) file exporter JSONL → Python 스크립트(또는 DuckDB read_json)로 '에이전트·날짜·file_path·mcp_server' 집계 — 결정론적이고 git 검토 가능한 요약(마크다운)을 만들 수 있음, (2) otel-desktop-viewer UI 필터(스크립트 질의는 미문서화, --db DuckDB 파일을 파이썬 duckdb로 여는 것은 가능할 것으로 추정하나 실행 중 잠금 주의), (3) SigNoz/OpenLIT는 SQL·대시보드지만 Docker 전제.
- Codex 커버리지 구멍: codex exec는 메트릭이 없고 codex mcp-server는 텔레메트리가 전무(#12913). Windows에서 Stop 훅 stdin이 비ASCII에서 깨지는 미해결 버그(#23784) → 한국어 답변이 있는 세션의 Stop 훅은 실패할 수 있으므로 Codex는 훅보다 자체 [otel]을 1차로, 훅은 PostToolUse(command만)로 한정한다.
- Antigravity 커버리지 구멍: 자체 내보내기 없음, IDE Windows에서 Stop·PostToolUse 훅 미실행 보고(1.107.0, 2026-08-14)가 2.14.0에서 해결됐는지 미검증. 대안은 transcriptPath·artifactDirectoryPath(훅 페이로드)와 ~/.gemini/antigravity/conversations·brain 파일을 읽는 스크립트.
- OTel 데이터 자체는 사용자 홈이나 저장소 밖(수집기 파일·DuckDB)에 쌓이므로 git diff로 검토되지 않는다. git 검토 가능성은 '일일 요약을 스크립트로 Docs/Worklog 옆에 생성해 커밋'하는 방식으로만 확보된다. 결론: OTel은 Docs/Worklog를 대체하지 않고 보완한다 — Worklog의 결정론적 부분(시작·완료 시각, 만진 파일, 도구 횟수, 세션 누락)은 자동 생성으로 옮기고, 의도·판단·다음 행동은 사람과 에이전트가 계속 쓴다.

## 권장하지 않는 것
- **SigNoz·OpenLIT·Langfuse 자체 호스팅** — 모두 Docker + ClickHouse 전제(로컬에 Docker 없음). SigNoz는 Windows에서 Docker Desktop 대신 WSL2 안 Docker Engine 권장(Keeper segfault), 최소 4GB·권장 8GB. Langfuse v3는 4코어·16GiB 권장에 Claude Code OTLP 로그를 400으로 거부(트레이스만 수신). 사람 1명·순차 세션에 유지 부담이 이득보다 크고, 데이터가 git 밖 DB에 갇힘.
- **Jaeger v2(Badger)** — 트레이스 전용이라 Claude Code(트레이스 베타)·Cursor(트레이스 없음)·Antigravity(없음)의 핵심 신호인 로그 이벤트를 저장하지 못함. 파일 경로 질의는 스팬 속성에만 의존.
- **Arize Phoenix(pip)를 1차 저장소로** — OpenInference 트레이스만 받아 Claude Code·Codex·Gemini의 자체 OTLP 로그를 못 받고 Arize 훅 하네스로 우회해야 함(구성 A의 훅 러너와 중복). Windows 인코딩·포트 이슈 이력(#4207은 수정됨). UI가 필요하면 구성 C가 더 가볍다.
- **Cursor Enterprise OpenTelemetry Export** — Enterprise 플랜 팀 설정 전용이며 트레이스·프롬프트 없음. 개인 사용자는 훅으로 충분.
- **Codex metrics_exporter 기본값(statsig) 유지, Gemini CLI logPrompts 기본값(true) 유지, Claude OTEL_LOG_RAW_API_BODIES=1** — 각각 클라우드로 메트릭 유출, 프롬프트 전문 기록, 요청 본문 전체 기록(용량·민감도 급증). 구성 A에서 명시적으로 none/false/미설정으로 둔다.

# 서로 다른 벤더 사이의 세션 인수(handoff)

종류: 리서치 · 작성: 2026-09-18 claude(다중 에이전트 워크플로 2차) · 웹 사실은 URL과 확인 날짜 기준. 판정은 `../05-concurrency-and-handoff.md`.

## 주제
서로 다른 벤더 에이전트(Claude Code · Codex CLI 0.154 · Antigravity 2.14/Gemini CLI · Cursor) 사이의 세션 인수(handoff) 기술과 관례 — 문제 (나) 죽은 세션 인수 중심, 문제 (가) 동시 작업 보조. 확인 날짜 2026-09-18.

## 핵심 사실
- (1) 저장 형식·위치(Windows 기준, 모두 사용자 홈 = 저장소 밖): Claude Code %USERPROFILE%\.claude\projects\C--Project-TDGame\<session-id>.jsonl(줄당 JSON, 형식 '내부용·버전마다 변경' 공식 경고, 30일 보존). Codex %USERPROFILE%\.codex\sessions\YYYY\MM\DD\rollout-<ts>-<uuid>.jsonl + state_5.sqlite(threads.rollout_path 색인; 불일치 버그 다수). Gemini CLI %USERPROFILE%\.gemini\tmp\<project_hash>\chats\*.json(30일). Antigravity 데스크톱 %USERPROFILE%\.gemini\antigravity\conversations\*.pb(프로토버프, 실행 중 LanguageServer API 로만 해독) + brain\<uuid>\task.md·implementation_plan.md·walkthrough.md(Markdown). Antigravity CLI %USERPROFILE%\.gemini\antigravity-cli\brain\<id>\.system_generated\logs\transcript_full.jsonl(읽기 가능). Cursor %APPDATA%\Cursor\User\globalStorage\state.vscdb(SQLite, 스키마 비공개, GB 단위).
- (1) 타 벤더 판독 가능성: Claude jsonl·Codex rollout·Gemini JSON·Antigravity CLI transcript 는 파일 읽기만으로 복원 가능(모델 불필요). Antigravity 데스크톱 .pb 와 Cursor state.vscdb 는 실용적으로 불가. 어떤 벤더도 다른 벤더의 세션 파일을 '재개'하지는 못함 — 재개는 자기 형식만(Claude `--resume <jsonl 경로>`, Codex `codex resume <id>`, Gemini `--resume`, Antigravity `agy -c`).
- (1) 내보내기: Claude `/export [파일]`(사람용 텍스트) 및 `claude -p --resume <id> --output-format json "요약"`(스크립트용, 모델 호출). Gemini `/chat share x.md|x.json`. Codex 는 공식 내보내기 명령 없음(비대화형 `codex exec resume <id> "요약"` 로 대체 가능, 모델 호출). Antigravity·Cursor 는 서드파티 도구만.
- (1) 크기·개인정보: 전사에는 도구 출력 원문(빌드 로그·파일 내용·환경 변수·경로)이 그대로 들어감. Codex 핸드오프 도구들이 50MB 스킵 임계를 두는 것으로 보아 rollout 은 수십 MB 까지 커짐. 따라서 전사 원문은 저장소에 커밋하지 말고, 추출한 인수 노트만 커밋 대상으로 삼아야 함(aihero 스킬도 비밀 제거·경로 참조 원칙).
- (2) 벤더 내장 요약: Claude Code 는 /compact, /rewind 의 'Summarize from/up to here', 재개 시 '요약으로 재개' 대화상자, 훅 PreCompact/PostCompact — 모두 자기 세션 내부용이며 요약을 저장소 파일로 내보내는 기능은 없음. Codex 는 /compact·PreCompact/PostCompact 훅, 0.155 부터 goal·스레드가 데몬 재시작 후 복구. Gemini CLI /compress. Antigravity 는 brain 아티팩트(task.md 등)가 사실상 자동 요약이지만 홈 폴더에 생성됨. 공식 '핸드오프 문서 생성' 기능은 네 벤더 모두 없음(Codex 0.138 `/app` 은 미커밋 변경을 Desktop 워크트리로 옮기는 git 이동일 뿐).
- (2) 서드파티: 모두 Markdown 파일 + 훅/스킬 조합. szepeviktor/codex-handoff(모델 호출 없이 rollout 에서 핸드오프 블록만 12k자 주입), LLeung49/codex-handoff(잔여 할당량 3% 에서 프롬프트 차단해 마지막 턴을 인수에 예약, .handoff/ 저장), openhandoff(CONTEXT.md+context.json, Codex·Claude JSONL 가져오기, 초기 단계), ai-agent-handoff(Claude jsonl→md, 셸), softaworks session-handoff 스킬(10절 템플릿, .claude/handoffs/), claude-fleet(전사 경로+세션 ID 를 Codex 에 전달). 공통 결론: '작고, 경로로 참조하고, 검증 명령을 포함하는' 문서가 표준.
- (3) 프로토콜: A2A v1.0 은 클라이언트↔원격 에이전트 서버 간 Task/Artifact 교환(종결 태스크 재시작 불가, contextId 로 후속). ACP 는 세션이 에이전트 소유이며 RFD 가 '제3자 대화 로드는 결함 있는 경험'이라 명시(session/resume 2026-04-22 안정화, fork 불안정). MCP 세션은 Mcp-Session-Id 전송 단위로 대화 상태 없음. 셋 다 로컬 CLI 두 개가 파일로 주고받는 이 사례에는 인수 채널로 부적합; MCP 리소스로 핸드오프 파일을 노출할 수는 있으나 저장소 파일 읽기와 이득 차이 없음.
- (4) 할당량 소진 시 남는 것: Claude·Codex 모두 전사를 이벤트 단위로 계속 기록하므로 마지막 이벤트까지 디스크에 남음. Claude 는 '실행 중이던 도구는 재개 시 완료·재실행되지 않음'. Codex 는 한도에서 세션이 종료되고 리셋 시각은 버려짐(#21073), 재개해도 작업 의도가 유실됨(#8310, 미수정). Antigravity CLI 는 모델 전환 시 문맥 전부 상실(#163, 미수정). 세 벤더 어디서도 '한도 도달' 전용 훅은 없음 — Claude StopFailure(rate_limit) 는 출력이 버려지고, Codex SessionEnd 훅 1초 예산·발화 여부 미확인.
- (4) Codex 의 '중간 판단·다음 단계'는 저장소에는 없지만 rollout 에는 있음: response_item(role=assistant 메시지=계획 서술, function_call apply_patch 인자=적용한 diff, function_call_output=빌드 결과), event_msg(agent_message 추론 요약, token_count). 마지막 task_started 뒤 task_complete 가 없으면 죽은 턴이고, call_id 짝이 없는 function_call 은 '결과 미확인 도구 호출'로 표시해야 함. 0.154 부터 사용자 턴은 item_completed/UserMessage 로 바뀌어 파서는 두 경로를 모두 처리해야 함.
- (4) 부분 적용 판정 관례: 전사보다 `git status`·`git diff` 가 진실. Codex apply_patch 는 패치 단위로 원자적이지만 여러 도구 호출 사이 상태는 부분적일 수 있음. 복구 순서 = ① git diff 로 실제 변경 확정 ② 전사에서 마지막 사용자 지시·마지막 어시스턴트 메시지·마지막 도구 호출 3개 추출 ③ 빌드/테스트로 상태 재검증 ④ Worklog 시작 항목의 성공 조건과 대조.
- (5) 체크포인트 강제 도구: Claude Code 체크포인트는 편집 도구 변경만, ~/.claude 에 대화와 함께 저장, 30일, Bash·다른 세션 편집 미추적 — 벤더 종속이며 Codex 는 못 읽음. Gemini 체크포인트는 그림자 git(~/.gemini/history) 이라 git 도구로는 읽히지만 기본 꺼짐. 벤더 중립 강제 수단은 훅뿐: Claude Stop/PreCompact/SessionEnd(1.5초), Codex Stop/PreCompact/SessionEnd(1초) 에서 git 스냅샷 명령 실행. 관례는 Stop 훅 `git add -A && git diff-index --quiet HEAD || git commit -m wip`; 이력 오염을 피하려면 `git stash create` 결과를 refs/wip/<agent> 에 update-ref 하는 방식이 더 깨끗함.
- (가 관련) 동시 작업 격리: Claude `--worktree` 는 메인 체크아웃 편집·git 리다이렉트를 차단하지만 언리얼 프로젝트에서는 Content(LFS) 복제와 `git lfs install --local` 포인터 문제가 있고, 언리얼 에디터·Blender 단일 인스턴스 충돌은 워크트리로 해결되지 않음(에디터 점유는 별도 락 파일 규칙 필요). Claude 두 터미널이 같은 세션을 포크 없이 재개하면 전사가 섞임. Codex 0.154 는 다른 앱에서 연 대화를 읽기 전용으로 보여 줌.
- 설계 결론: 벤더 세션 파일은 '최후의 원본', 저장소 안 인수 노트는 '일차 인수 채널'. 노트는 목표·완료·다음 1개·검증 명령·미해결 질문·참조 경로 6항목 ≤ 500자, 검증된 단계마다 갱신. 죽은 세션은 모델 없이 세션 파일에서 노트를 자동 생성하는 결정론 스크립트로 보강. 프로토콜·외부 메모리 서비스는 불필요.

## 권장하지 않는 것
- **A2A(Agent2Agent)·ACP(Agent Client Protocol)·MCP 세션을 인수 채널로 사용** — A2A 는 서버로 떠 있는 원격 에이전트 간 Task/Artifact 교환이며 Claude Code·Codex 는 A2A 서버가 아님. ACP 세션은 에이전트 소유이고 RFD 가 제3자 대화 로드를 부정. MCP 세션은 전송 연결 단위로 대화 상태가 없음. 사람 1명·로컬 CLI·파일 장부 조건에서는 파일보다 얻는 것이 없고 서버 운용 부담만 추가.
- **벤더 세션 파일(Codex rollout·Claude jsonl) 원문을 저장소에 커밋하거나 인수자가 통째로 읽기** — 수십 MB, 도구 출력 원문·환경 정보·잠재적 비밀 포함, 형식 불안정. 추출 노트(B)만 커밋·읽기.
- **Antigravity 데스크톱 .pb 파싱, Cursor state.vscdb 직접 질의** — .pb 는 실행 중 LanguageServer API 로만 해독 가능하고 스키마 비공개, Cursor 는 GB 단위 SQLite 에 비공개 스키마. 대신 Antigravity 는 brain/<uuid>/task.md·walkthrough.md(Markdown) 와 CLI 의 transcript_full.jsonl 만 읽음.
- **Claude Code 체크포인트(/rewind)·Gemini 그림자 git 을 벤더 간 복구 수단으로 신뢰** — Claude 체크포인트는 ~/.claude 전용·30일·Bash 변경 미추적·다른 세션 편집 미추적. Gemini 는 기본 꺼짐. 벤더 중립 복구는 저장소 git(C) 만.
- **`codex resume` 만으로 죽은 Codex 세션을 이어가기(노트 없이)** — Issue #8310: 한도 후 재개 시 작업 의도 유실·완료 단계 반복, 미수정. 한도 소진 상태면 Codex 자체가 응답 불가.
- **Serena 메모리 파일을 핸드오프 채널로 사용** — 두 벤더가 모두 읽을 수는 있으나 프로젝트 규칙(벤더·Serena 메모리에 프로젝트 사실 저장 금지, 장부는 Docs/)과 충돌하고 Antigravity·Cursor 는 접근 불가.
- **codex.danielvaughan.com '세션 지속성' 계열 글을 근거로 채택** — meta.json/state.json/`codex session export --format bundle` 등 공식 CLI 참조와 GitHub 이슈 어디에도 없는 명령을 서술. 교차 확인 안 되는 자동 생성 문서로 추정.
- **에이전트마다 git 워크트리 분리를 (가) 의 완전한 해법으로 채택** — 언리얼 Content(LFS) 복제 비용·`git lfs install --local` 포인터 문제·Windows 정션 주의가 있고, 언리얼 에디터·Blender 단일 인스턴스 충돌은 워크트리와 무관. 에디터 점유 락 파일 규칙과 공용 문서 파일 분리(에이전트별 Worklog 파일)가 먼저.

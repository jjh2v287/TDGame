## 주제
에이전트가 만드는 스크립트·도구를 저장소 안 공통 자산으로 관리하는 관례 조사 (Agent Skills 묶음 단위, 등록표·진입점, 이름 규칙, 만들기 전 검색, 등록 누락 검사, 일회용 격리, 언리얼 에디터 Python 도구 관리) — TDGame Tools/README.md 표 관례를 보강하는 방향

## 핵심 사실
- [표준] Agent Skills 규격은 SKILL.md 의 name 이 부모 폴더 이름과 일치해야 하고 소문자·하이픈만 허용. TDGame 의 두 SKILL.md 는 위반: Tools/AnimationAuthoring/SKILL.md 1~3행 name=td-animation-authoring, Tools/BlenderAnimation/SKILL.md 1~3행 name=td-combat-animation-quality (폴더명은 PascalCase 이고 다름).
- [표준] 스킬 발견 위치: Codex·Cursor 는 .agents/skills/, Gemini CLI 는 .gemini/skills/ 또는 .agents/skills/ 별칭, Claude Code 는 .claude/skills/ 만. 저장소 루트에는 .agents/ 도 .claude/ 도 없음(루트 목록: .cache .codex .cursor .gemini .git .idea .mcp.json .serena .vscode) → 현재 두 SKILL.md 는 어떤 에이전트도 자동 발견하지 못하고, 문서 링크를 따라 읽을 때만 쓰인다.
- [표준] 세 에이전트 모두 스킬 메타데이터(name+description ≈100토큰)만 세션 시작 시 로드하고 본문은 활성화 때 로드하며(점진적 공개), scripts/ 의 코드는 '읽지 않고 실행'한다(Claude Code 문서, Anthropic 2025-10-16). → 사용자의 토큰 절약 요구와 정확히 맞는 등록 단위.
- [표준] Codex 문서: '결정론적 동작이나 외부 도구가 필요할 때만 스크립트, 그 외엔 지시문'. Anthropic: 스크립트가 실행용인지 참고용인지 명확히 하라. → 등록표에 '실행/참고' 구분 열이 필요.

- [등록표] Tools/README.md 0절(7~10행)의 `python Tools/ue_editor.py ensure` 는 이미 '매 세션' 모든 에이전트가 실행하는 유일한 공통 진입 명령 → 등록 누락 검사를 붙일 최적 지점(에이전트 훅 불필요).

## 권장하지 않는 것
- **justfile/Makefile 을 새 진입점으로 도입** — Windows 10 + PowerShell 5.1/Git Bash 혼용 환경에서 just 설치와 셸 호환을 새로 관리해야 하고, Tools/README.md 표의 '예' 열이 이미 '명령 한 줄 = 레시피' 역할을 한다. just-mcp 처럼 MCP 로 노출하면 세 에이전트의 MCP 설정 3곳(.codex/config.toml, .cursor/mcp.json, .vscode/mcp.json, .gemini)을 또 늘린다. 규칙 정비가 우선인 지금은 표+생성기로 충분.
- **Agent Skills 규격대로 모든 스크립트를 scripts/ 하위로 옮기고 Tools/ 를 .agents/skills/ 로 통째 이동** — 규격의 scripts/·references/ 는 '권장' 이지 필수가 아니며, 이동하면 Docs·메모리·README 의 수백 개 경로 참조가 깨진다. Claude Code 는 .agents/skills 를 읽지 않아 어차피 .claude/skills 도 필요하다. 정본은 Tools/ 에 두고 발견 경로에는 3줄 스텁만 두는 것이 비용 대비 효과가 크다.
- **.claude/skills ↔ .agents/skills 를 심볼릭 링크로 연결** — Windows 심볼릭 링크는 Developer Mode 또는 관리자 권한과 core.symlinks 설정이 필요하고, 조건이 안 맞으면 링크 대상 경로가 적힌 일반 파일로 체크아웃되어 조용히 깨진다. 정션(junction)은 git 이 추적하지 못한다. 스텁 SKILL.md 파일이 안전하다.
- **pre-commit 프레임워크(Python 패키지) 도입** — 사용자가 커밋을 드물게 지시하므로 커밋 시점 검사는 늦고, 프레임워크는 별도 설치·가상환경 관리가 필요하다. git 내장 core.hooksPath + Tools/githooks/pre-commit 만으로 같은 효과를 얻고, 주 검사는 세션 시작 점검(ensure)에 둔다.
- **에이전트별 훅(Claude PostToolUse, Gemini AfterTool)으로 '새 스크립트 작성 시 등록 강제'** — Codex CLI 는 훅이 없어(2026-01-31 비교 기사) 3종 공통이 되지 않고, 훅 설정이 .claude/settings.json 과 .gemini/settings.json 두 곳으로 갈라져 또 다른 동기화 대상이 된다. 보조 수단으로만 고려.
- **스크래치 폴더를 30일 후 자동 삭제하는 스크립트** — 사용자 지시 없이 파일을 지우는 행위는 AGENTS.md 의 보수적 운영(커밋도 지시 시에만)과 어긋나고, automated-researcher #848 처럼 규칙 문서와 삭제 스크립트가 어긋나면 검증 증거를 잃을 수 있다. '만료 후보 보고' 까지만 자동화.
- **Content/Python 에 에이전트가 만드는 editor_*.py 를 두어 init_unreal 에서 자동 로드** — Content/Python 은 sys.path 자동 포함·시작 시 자동 실행 대상이라 실험 코드가 에디터 기동에 영향을 주고, 세 에이전트가 동시에 수정하면 충돌한다. 기존 관례(Tools/ + run_in_editor.py)가 더 안전하다.
- **README 표를 계속 손으로 유지(생성기 없이 규칙만 강화)** — 이미 규칙(4절 5항)이 있음에도 4개 폴더가 누락된 것이 손 유지의 한계를 보여준다. AAIF 인용 연구도 '개발자가 쓴 지침이 효과적' 이지만 '어긋나는 두 지침' 은 해롭다고 지적한다. 생성+검사가 사용자의 '결정론적 작업은 프로그램으로' 원칙에 맞는다.

# 벤더 내장 연속성 기능(자동 메모리·재개·체크포인트)

종류: 리서치 · 작성: 2026-09-18 claude(다중 에이전트 워크플로 2차) · 웹 사실은 URL과 확인 날짜 기준. 판정은 `../05-concurrency-and-handoff.md`.

## 주제
2026-09 시점 벤더 내장 연속성 기능(Claude Code·Codex·Antigravity/Gemini CLI·Cursor)이 (가) 동시 작업 충돌과 (나) 죽은 세션 인수에 주는 도움 평가 + 켜면 도움이 되는 설정 목록

## 핵심 사실
- 벤더 사이를 넘는 내장 연속성 기능은 2026-09 현재 하나도 없다. 자동 메모리(Claude)·memories(Codex)·지식 항목(Antigravity)·Memories(Cursor)·/chat save(Gemini)·Agent Teams·세션 간 메시징·codex multi_agent는 전부 같은 벤더 안에서만 동작하고 사용자 홈에 저장된다. 따라서 (가)(나)는 저장소 파일 체계(NOW·Worklog·대장·Lessons)가 유일한 공통 매체이며, 벤더 기능은 그 체계에 '자동 기록'을 붙이는 보조 수단으로만 쓸 수 있다.
- (가) 동시 작업: 어떤 벤더도 다른 벤더와 공유되는 잠금·단일 인스턴스 중재를 제공하지 않는다. Claude Agent Teams의 파일 잠금은 작업 청구용이고 팀원은 Claude뿐, Claude --worktree는 파일 편집만 격리하며 언리얼 에디터·Blender 같은 프로세스 단일성은 다루지 않는다. 네 도구 모두 PreToolUse 훅(Claude·Codex·Antigravity·Gemini BeforeTool)이 있으므로 '저장소 안 잠금 파일 + 각 벤더 PreToolUse 훅 검사'가 벤더 기능으로 할 수 있는 유일한 강제 수단이다.
- (나) 죽은 세션 인수: Codex는 롤아웃(~/.codex/sessions/…/rollout-*.jsonl)을 항목 단위로 계속 기록하므로 한도 초기화 후 `codex resume --last`로 같은 벤더 재개는 가능하나, 중단 시점 체크포인트는 없어 컨텍스트 재구축에 할당량을 다시 쓴다(issue #45383, 2026-09-14 열림). 벤더 간 인수는 Claude가 그 롤아웃 JSONL을 직접 읽는 방법뿐이며, 로컬 실측상 assistant 메시지·function_call 인자(명령·패치)·도구 출력은 평문이지만 reasoning은 encrypted_content(summary 비어 있음)라 Codex의 '중간 판단' 자체는 복구 불가. 복구 가능한 것은 마지막 assistant 발화와 실행한 명령·수정 파일 목록이다.
- Codex memories는 (나)에 도움이 되지 않는다: 스레드가 6시간(기본) 유휴여야 하고 요율 한도 잔여율이 25% 미만이면 생성을 건너뛰며 다음 Codex 시작 시에만 처리한다. 즉 할당량 소진으로 죽은 세션은 정확히 그 조건 때문에 메모리가 만들어지지 않는다. 또 개발자 전역(프로젝트 구분 없음)이고 Codex 세션에만 주입된다. 로컬에는 현재 꺼져 있고 ~/.codex/memories가 비어 있다.
- Codex 훅으로 예방은 가능하다: Stop 훅은 매 턴 끝에 last_assistant_message를 받고 기본 600초 예산이므로, 마지막 발화(다음 단계 계획)를 저장소 파일에 덧붙이면 세션이 죽어도 직전 계획이 남는다. SessionEnd는 기본 1초·최대 3초라 신뢰할 수 없고, 한도 초과로 오류만 뜬 경우 프로세스가 종료되지 않아 SessionEnd 자체가 안 뜰 수 있다. 프로젝트 훅(<repo>/.codex/hooks.json)은 신뢰 승인이 필요하다.
- Claude Code 세션은 ~/.claude/projects/<project>/<id>.jsonl로 연속 저장되며 `--continue`/`--resume <id>`(어느 디렉터리에서든), `/branch`, `--fork-session`으로 재개·분기된다. 크래시 시 실행 중이던 도구는 재실행되지 않는다. JSONL 형식은 내부용이라 스크립트 파싱은 깨질 수 있으니 `/export` 또는 `claude -p --resume <id> --output-format json "요약"`을 써야 한다(단 Claude 할당량 소비).
- Claude autoMemoryDirectory는 공식 문서상 project·local 설정에서도 읽히지만 값은 절대경로여야 하고, 2026-03 버그(#36636: 시스템 프롬프트가 기본 경로를 계속 가리킴, duplicate로 닫힘)가 있어 CLAUDE.md에 경로를 명시하는 우회가 필요하다. 저장소 안에 두면 git diff 검토·타 벤더 열람이 가능해지지만, AGENTS.md의 '벤더 메모리에 프로젝트 사실 저장 금지' 규칙과 충돌하므로 규칙 변경 결정이 선행돼야 한다. 팀·조직 공유 자동 메모리 기능은 없다.
- Claude 체크포인트(/rewind)는 Claude 자신의 편집 도구 변경만 추적한다. Bash 변경, 다른 동시 세션(=Codex)의 편집, 백그라운드 서브에이전트 편집은 추적하지 않으므로 (가)의 git 변경 섞임 복구 수단이 아니다.
- Claude Agent Teams는 현재 사용자 설정에 켜져 있다(CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS="1"). 켜 두면 Claude가 이름 붙인 서브에이전트가 팀원으로 실행되어 토큰이 늘고, /resume 후 팀원은 복원되지 않는다. 팀원은 Claude 전용이라 (가)(나) 어느 쪽에도 도움이 없다.
- Antigravity 지식 항목은 문서·블로그 설명과 달리 이 설치에서 8개월·55개 대화 동안 0건이며(knowledge.lock만 존재), 포럼에서도 2026-01~03 다수 보고 후 미해결이다. 반면 brain/<conversation-id>/의 task.md·implementation_plan.md·walkthrough.md(+.resolved.N 버전)는 평문 마크다운으로 실제 존재하며, conversation_summaries.db(SQLite)에 제목·미리보기·단계 수·workspace_uris·status가 남는다. 대화 본문(conversations/, implicit/)은 암호화 .pb라 읽을 수 없다.
- Antigravity 훅 이벤트명이 확인됐다: PreToolUse, PostToolUse, PreInvocation, PostInvocation, Stop. 설정 ~/.gemini/config/hooks.json 또는 워크스페이스 .agents/hooks.json, 입력에 transcriptPath와 artifactDirectoryPath(brain 디렉터리)가 오므로 Stop 훅에서 task.md·implementation_plan.md를 저장소로 복사하는 자동 인수 기록이 가능하다(미검증).
- Codex 표면 동기화: CLI·데스크톱 앱·IDE는 같은 로컬 app-server 상태를 공유하지만(app-server가 꺼져 있던 동안의 CLI 세션은 목록 누락 가능), CLI 시작 스레드는 모바일·웹에서 재개되지 않고(#23351), ChatGPT 웹 메모리와 Codex 로컬 메모리는 별개 저장소다. 즉 '웹과의 동기화'는 (나)에 쓸 수 없다.
- Gemini CLI: /chat은 /resume 별칭이며 save/resume/list/delete는 ~/.gemini/tmp/<project_hash>/chats에 프로젝트별로 저장(Gemini 전용). 단 `/chat share <파일.md>`는 대화 전체를 Markdown/JSON 파일로 내보내므로 벤더 간 인수 자료로 쓸 수 있는 유일한 '내보내기' 명령이다. /memory에는 add가 없고(list/refresh/show), context.fileName으로 AGENTS.md를 컨텍스트 파일로 지정할 수 있다. 체크포인트는 settings general.checkpointing.enabled(플래그 제거)이며 그림자 git ~/.gemini/history/<hash>.
- Cursor Memories는 '프로젝트별·개인 수준'으로 Cursor 설정 안에 저장되어 저장소·버전 관리·팀·다른 기계 어디에도 안 보인다. 팀 규칙은 유료 플랜 대시보드. Cursor는 AGENTS.md를 네이티브로 읽으므로 이 저장소에 추가 설정은 불필요하다. 로컬 ~/.cursor는 2025-05 이후 변경이 없어 사실상 미사용이다.
- 저장소 파일 체계와의 중복·충돌: 벤더 메모리는 모두 '벤더가 골라서 쓰는' 비결정적 기록이라 Worklog(추가 전용, 사람이 규정한 형식)와 성격이 다르고, NOW.md와 같은 '현재 상태 한 장'을 대체하지 않는다. 충돌은 (1) Claude autoMemoryDirectory를 저장소 안으로 옮길 때 AGENTS.md 15절 규칙, (2) Codex/Antigravity 훅이 저장소 파일에 쓸 때 공용 파일 마지막 쓰기 승리 — 그러므로 훅 출력은 에이전트별 별도 파일(예: Docs/Worklog/.live/<agent>.md)로 분리해야 한다.

## 권장하지 않는 것
- **Codex memories 켜기( [features] memories = true )를 (나) 인수 수단으로** — 개발자 전역·프로젝트 구분 없음, 6시간 유휴·요율 잔여 25% 이상·다음 시작 시 처리 조건이라 할당량 소진으로 죽은 세션은 메모리가 생성되지 않음. 주입도 Codex 세션에만. 개인 선호 학습용으로만 의미 있고 저장소 Lessons와 중복.
- **Claude Agent Teams·세션 간 메시징을 (가) 조정 버스로** — 둘 다 Claude 세션끼리만. 팀원 미복원, 세션당 팀 1개, 토큰 배수. Codex와의 동시 작업에는 아무 효력 없음.
- **Claude 체크포인트(/rewind)를 (가) git 변경 섞임 복구 수단으로** — Claude 편집 도구 변경만 추적. Bash·다른 세션(Codex)·백그라운드 서브에이전트 편집 미추적. git이 유일한 복구 수단.
- **Codex ChatGPT 웹·모바일 동기화에 의존** — CLI 시작 스레드는 모바일·웹에서 재개 불가(#23351), 웹 메모리와 Codex 로컬 메모리는 별개. 데스크톱 앱도 app-server가 꺼져 있던 동안의 CLI 세션을 누락할 수 있음.
- **Antigravity 지식 항목(Knowledge Items)** — 이 설치에서 0건(55개 대화·8개월), 포럼 다수 보고 후 미해결. 대화 본문은 암호화 .pb. brain 마크다운과 conversation_summaries.db만 신뢰.
- **Cursor Memories·Team Rules** — 개인·프로젝트별로 Cursor 설정에만 저장, 저장소·팀·타 기계 비공유. 팀 규칙은 유료 플랜. Cursor는 AGENTS.md를 이미 읽으므로 추가 설정 불필요(로컬 사용 흔적도 2025-05 이후 없음).
- **Gemini CLI /chat save·checkpointing을 공통 인수 수단으로** — ~/.gemini/tmp/<hash> Gemini 전용. 부 경로라 투자 대비 이득 작음. 내보내기(/chat share)만 채택.
- **Claude 트랜스크립트 JSONL을 스크립트로 파싱** — 공식 문서가 '내부 형식, 버전마다 변경'으로 명시. /export 또는 claude -p --resume <id> --output-format json 사용.
- **SessionEnd 훅에 인수 기록 맡기기(모든 벤더)** — Claude 1.5초·Codex 1초(최대 3초)·Gemini best-effort 예산. 한도 초과·크래시 시 발화 보장 없음. Stop(턴 단위)으로 대체.

# 게임플레이 재미·시스템 공백 분석

작성: 2026-10-21 claude. 기준은 같은 날 작업 트리(미커밋 포함)이며 읽기 전용으로 조사했다.
방법: 1단계 영역 조사 9개(설계 의도·플레이어 행동·전투·적·월드·성장·화면 구성·콘텐츠·장르 비교) → 2단계 반박 검증 3개·완결성 비평 1개 → 3단계 설계안 3관점(수직 단면 slice·전투 깊이 depth·장기 동기 longterm) → 판정·통합 → 최종 검토. 검증에서 반박·보정된 사실은 검증을 따랐고, 핵심 코드 줄은 통합 단계와 최종 검토에서 다시 열어 확인했다(10절). 중간 보고서는 `Saved/AgentOps/20261021/gameplay-analysis/`(로컬, 커밋 안 됨)에 있다.
항목 ID: GP-nn = 게임플레이 항목, GF-nn = 지금 고칠 결함, GQ-nn = 사용자 결정 질문. 기존 대장 ID(`Docs/Tasks/decisions.md`의 D-, `Docs/AnimationAuthoring_Tasks.md`의 F-·G-)와 겹치지 않게 붙였다. 이 문서는 분석·제안이다. 대장(`Docs/MonsterAI_CombatSim/07-roadmap-and-tasks.md`·`Docs/Tasks/phase-*.md`) 등록과 결정 확정은 사용자 승인 뒤에 한다.
표기: [가정] = 측정으로 고칠 초안 수치, [추정] = 간접 근거. 출처 ID: SLICE-nn·DEPTH-nn·LONGTERM-nn = 3단계 설계안 항목, verify-* = 2단계 검증, critic = 2단계 비평.
약어: PIE = 에디터 내 플레이, HUD = 화면 정보 표시, GE = 게임플레이 효과(Gameplay Effect), UAF = 언리얼 애니메이션 프레임워크, WP = 월드 파티션, XP = 경험치, JSONL = 줄 단위 JSON 기록.

## 0. 한 줄 결론

**손맛·몬스터 AI·연속 세계는 이미 상급 재료다. 그런데 둘을 잇는 "놓기·보상·강해짐·저장" 네 고리가 없어서 아직 게임이 되지 못했다. 큰 새 시스템을 만들기 전에, 완성된 아레나 조우를 필드에 놓고 레벨·주문 해금·물약·성소·저장을 붙여 걸어서 이어지는 30분 수직 단면부터 닫아야 한다.**

- 세 설계안의 방향은 같다. slice는 "30분을 닫아라", depth는 "비용이 0이라 판단이 없다", longterm은 "10시간을 만들 반복 장치가 없다"이다. 통합 순서는 slice → depth → longterm이다(7절).
- 설계안 원본 88개를 63개로 병합했다. P0 12 · P1 23(결함 6 포함) · P2 22 · P3 6.
- 최소 슬라이스(P0 12개)는 약 5~7주로 본다[가정]. 에이전트가 구현하고 사람이 PIE로 판정하는 속도 기준이다(M3-36 한 사이클이 하루, `Docs/MonsterAI_CombatSim/07-roadmap-and-tasks.md:772`).
- 사람이 손으로 끝까지 플레이한 기록은 0이다(critic 2-6). 그래서 아래 체감 서술은 모두 [추정]이고, 측정 기록(GP-13)을 첫 단계에 만든다.

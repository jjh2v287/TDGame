# 01 갈래: 결정론 청크 생성 프로토타입 실측 (무한 생성 핵심 성질)

작성: claude 하위 에이전트, 2026-10-23. 범위: Python(numpy) 프로토타입으로 '무한 생성'의 생성 측 핵심 성질만 실측. 엔진 런타임(랜드스케이프·충돌·내비·PCG 스트리밍)과 저장(변형 수준 B·C)은 다른 갈래 몫.
근거 표기: [검증] = 원문을 직접 읽었거나 이 스크립트로 직접 측정함, [추정] = 원문 미확인·추론.

## 0. 결론 (요약)

1. **생성 측은 무한 세계의 걸림돌이 아니다.** 위치를 int64 정수 표본 색인(1 단위 = 0.5 m)으로만 다루고, 격자점 값을 (시드, 정수 격자 좌표)의 64비트 해시로 얻으면 다음이 모두 성립했다 [검증, 아래 3절].
   - 이웃 청크를 따로 생성해도 공유 가장자리 표본이 **비트 단위로 같다**(28개 시험, 최대 차이 0.0). 청크 색인 ±1e7, 2^40 에서도 같다.
   - 9x9 청크를 행 순서·무작위 순서·**81개 별도 프로세스**로 만들어도 합본 해시가 같다(원점·청크 1e7 두 곳).
   - 원점과 청크 1e7(6.4e10 cm) 부근의 품질이 같다: 격자 내부 좌표가 8개 옥타브 모두 비트 동일, 102 km 범위 바이옴 비율 차이 최대 0.7 %p(퍼센트포인트), 높이 표준편차 33.27 vs 33.45 m.
   - 512 m 지역 격자의 구조물(지름 최대 200 m)이 4청크에 걸쳐도, 청크를 따로 만든 결과가 한 번에 만든 결과와 비트 동일.
2. **비용은 걷는 속도에 비해 미미하다.** numpy 단일 스레드에서 64 m 청크(1 m 간격) 전체 생성 중앙값 13.5 ms, 128 m 52.5 ms, 64 m·0.5 m 53 ms. 이번 카메라 시야(약 35 m x 35 m, 세계 축 기준) + 청크 1개 여유로 잡은 적재 창에서 600 cm/s 보행 시 필요 생성률은 초당 0.27~1.33 청크, **한 코어의 1~3 %**다 [검증, 3.7절]. 실제 병목은 엔진 측(메시·충돌·내비메시·액터 생성)일 것이다 [추정].
3. **수치 한계는 생성기가 아니라 float32 경로에 있다.** float32 절대 좌표로 노이즈를 계산하면 1e8 cm(1,000 km, 보행 46.3시간)에서 표본 401개 중 위치가 51개로 뭉개져 8 cm 계단이 생기고, 1e9 cm 에서는 노이즈가 사실상 사라진다. float32로 위치를 누적하면 1e8 cm 에서 이동 속도가 프레임률에 따라 -20 %~+60 % 틀어지고 1e9 cm 에서는 멈춘다 [검증, 3.6절]. 엔진 내장 `FMath::PerlinNoise2D` 는 위치를 float로 깎고(`LWC_TODO: Precision loss`) 격자를 `& 255` 로 접어 256셀마다 반복하므로 무한 세계 생성에 쓰면 안 된다 [검증, UnrealMath.cpp:3629-3638].
4. **C++ 이식 시 새 함정 하나를 확인했다.** MSVC에서 Game 타깃 기본 부동소수 모드는 `/fp:fast`, Editor 타깃은(BuildSettings V7 이상) `/fp:precise` 다. TDGame 은 두 타깃 모두 V7 이므로 **에디터와 패키지 게임이 같은 생성 코드를 다른 부동소수 규칙으로 컴파일한다** [검증, VCToolChain.cs:1322-1335, Source/TDGame.Target.cs:11, Source/TDGameEditor.Target.cs:11]. 생성 결과를 저장 차분(변형 수준 B·C)의 기준으로 삼으려면 생성 모듈에 `FPSemantics = Precise`(ModuleRules.cs:784) 를 주거나, 저장·비교 대상 값을 정수(고정소수)로 양자화해야 한다. 실제 비트 차이가 나는지는 미측정 [추정].
5. 현재 잿빛 골짜기 생성기의 노이즈 방식(순차 난수 스트림 + 고정 크기 격자 확대)은 청크화할 수 없다. 같은 방식을 흉내 낸 음성 대조가 순서 시험과 이음매 시험을 모두 실패했다 [검증: 코드 generate_ashen_vale.py:104-108·1562, 대조 결과 3.3절].

## 2. 설계 (프로토타입이 실제로 한 일)

| 요소 | 구현 | 근거 |
|---|---|---|
| 좌표 | 모든 표본 위치 = int64 정수 단위(1 단위 = 0.5 m). 청크 원점 = 청크 색인 x 청크 단위 수(파이썬 정수 → int64). 부동소수 절대 좌표 없음 | chunkgen.py:10, 305-311 [검증] |

비트 동일성이 성립하는 이유: 값 경로가 원소별 연산(+, -, *, /, sqrt, floor, 정수 연산)뿐이고 합산 축약(reduction)·초월함수가 없다. IEEE-754 기본 연산은 정확 반올림이라 배열 모양·SIMD 경로와 무관하게 같은 입력이면 같은 출력이다 [검증: 측정 결과로 확인. 다른 기계·다른 numpy 판에서는 미측정이라 그 범위는 추정].

## 3. 측정 결과

측정 환경: AMD Ryzen 7 3700X, Windows 10, Python 3.12.10, numpy 2.2.5, 단일 스레드. **다른 에이전트 프로세스가 동시에 돌던 중**이라(재측정 시점 CPU 부하 83 %) 절대 ms 는 ±50 % 흔들린다. 상대 비교(원점 vs 먼 곳, 높이만 vs 전체)는 같은 실행 안의 값이라 유효 [검증].

- '높이만' = 왜곡 6 + 높이 8 + 대륙 2 = 16 옥타브. '전체' = 높이 + 기후 6 옥타브 + 바이옴 분류 + 구조물. 옥타브·표본당 약 146 ns(numpy) [검증: 9.88 ms / 4,225 / 16].
- **원점과 청크 1e7 의 비용이 같다**(64 m 전체 13.50 vs 13.53 ms) — 거리와 무관 [검증].
- 32 m 는 표본당 비용이 2배: numpy 호출당 고정 비용이 작은 배열에서 두드러짐 [검증: 측정값, 원인은 추정].
- 구조물이 걸친 청크: 메인 실행 32 m 9.87 / 64 m 17.02 / 128 m 71.21 / 64 m·0.5 m 94.05 ms. 부하 83 % 상태 재측정(51회)에서 구조물 있음/없음/높이만 = 64 m 22.84/19.76/14.28, 128 m 93.2/85.1/57.6, 64 m·0.5 m 87.9/79.3/54.5 ms. 구조물 1개 추가 비용은 3~9 ms 이고 그중 시작점 1점 높이 평가가 3.42 ms(numpy 고정 비용) [검증]. 지역 서술자는 순수 함수라 캐시해도 결정론이 깨지지 않는다 [추정: 설계 판단].
- C++ 이식 시 옥타브·표본당 10~30 ns 수준이면 64 m 전체가 1~3 ms 로 줄 것이다 [추정, 미측정].

### 3.2 이음매 시험 [검증: results.json `seams`]

## 4. 프로젝트 함의

1. **변형 수준 A(무한 생성 + 지형 변경 없음)의 생성 핵심은 성립한다** [검증: 3.1~3.5]. 필요 조건은 (a) 정수 위치·정수 격자 색인, (b) 위치 해시(순차 난수 금지), (c) 가장자리 표본 공유, (d) 청크보다 큰 개체는 상위 격자(지역)의 순수 함수로 서술, (e) float32 절대 좌표 경로 금지.
2. **비국소 지형(강·도로·이어진 던전·현재의 숨은 이음매 통로 D-42)** 은 위치 해시만으로는 안 된다. 구조물처럼 '지역 계획 → 각 청크가 조회'하는 계층 생성이 필요하다. 이번 시험은 원형 구조물까지만 확인했다 [추정]. 현 생성기는 강 되메움·연결로 같은 비국소 요소를 고정 지도 위에서 만든다(generate_ashen_vale.py:19-36 상수들) [검증: 상수 존재].
3. **변형 수준 B·C** 에서 저장은 '생성 결과 위 차분'이 된다. 차분을 기준값 위에 다시 얹으려면 재생성이 비트 단위로 같아야 한다(최소한 저장 단위로 양자화한 값이 같아야 한다). 위 0절 4번(Game `/fp:fast` vs Editor `/fp:precise`)이 직접 걸린다. 권장: 생성 모듈 분리 + `FPSemantics = Precise`, 또는 높이를 int16/고정소수로 저장하는 형식(현 R16 하이트맵과 같은 방식) [추정]. 참고로 Docs/MonsterAI_CombatSim/04-combat-simulator.md:394 는 "UnrealBuildTool 의 기본 부동소수점 모드는 미확인" 이라고 적고 있다 — 이번에 확인한 사실로 갱신 가능(교훈 후보, 장부 기록은 부모 세션 판단).
4. **엔진 내장 노이즈 대신 자체 구현**: `FMath::PerlinNoise2D` 는 256셀 주기·float 손실 [검증]. PCG 노드 노이즈의 주기·정밀도는 이 갈래에서 미확인 [추정].
5. C++ 이식 체크리스트: 해시·격자 좌표는 int64, 값 경로는 원소별 연산만(합산 순서 고정), 초월함수 금지 또는 자체 다항 근사, FMA 축약 금지(모듈 FP 설정), 청크 결과 SHA 같은 해시로 골든 시험(같은 빌드·다른 프로세스·다른 순서) — 전투 시뮬 D31 게이트와 같은 틀을 재사용할 수 있다 [추정].

## 6. 한계와 미검증

- 다른 기계·다른 OS·다른 numpy 판 사이의 비트 동일은 미측정 [추정: 기본 연산만 쓰므로 같을 가능성 높음].
- 절대 시간은 동시 부하로 ±50 % 흔들림. 다중 스레드 생성은 미측정.
- 바이옴 경계가 계단형(경계 섞기 없음), 침식·강 없음, 구조물 배치 규칙 없음.
- 옥타브 사이 회전이 없어 축 정렬 무늬가 남을 수 있다. 정수 피타고라스 회전((4,-3),(3,4), 배율 5)을 쓰면 정수 정확성을 유지하며 회전할 수 있다 [추정, 미구현].
- 비왜곡 옥타브는 격자점 해시를 표본마다가 아니라 격자점마다 한 번만 계산하도록 분리하면 더 빠르다 [추정, 미구현].
- 엔진 측(랜드스케이프 런타임 생성·월드 파티션·내비메시·PCG)은 이 갈래 범위 밖.

## 0. 결론 (요약)

1. **탑다운에서 '무한'의 가치는 면적이 아니다.** 현 카메라로 화면에 보이는 땅은 약 588 m²(앞 15 m·뒤 5.5 m)이고, 600 cm/s 직진 시 시간당 약 0.6 km²만 새로 본다(1절 계산). 8×8 km 유한 세계도 직진 시야 기준 100시간 이상이 걸린다. 무한이 주는 것은 '가장자리 없음'의 감각·시드(seed) 다양성·재방문 동기이고, 이는 **유한 대형 시드 지역을 필요할 때 이어 붙이는 방식**으로도 대부분 얻는다. Core Keeper 는 1.0 에서 "시드 기반 유한 세계"로 돌아갔다 [검증 Wikipedia].
2. **장르 정석은 '손 거점 + 절차적 바깥 + 무한은 메타 층'이다.** Path of Exile 2 아틀라스(모든 방향 무한 확장), Last Epoch 강화 타임라인(부패도 무한), Necesse 침공(incursion, 제단에서 여는 임시 지도) 모두 **무한을 지형이 아니라 인스턴스 노드·난이도 수치 축에 둔다** [추정·검색요약]. 단 사용자의 연속 보행 요구(D-42)와 충돌하므로 진입을 '걸어 내려가는 이음매 통로'로 만들어야 한다.
3. **절차적 단조로움(procedural oatmeal)이 탑다운에서 더 빨리 온다.** 지평선이 안 보여 랜드마크가 탐험을 끌지 못하고, 분당 3~6개 관심 지점을 소비하므로 손 템플릿 40개면 한 시간에 같은 것을 5~9번 본다(1절). 손 제작 조각 × 시드 조합(Spelunky·Minecraft Dungeons·Don't Starve·Hytale V2 방식)과 화면 밖 유도(지도 안개·소리·빛기둥)가 필수다.
4. **건설은 전투 고리에 직결될 때만 ARPG 에서 산다.** Torchlight III 요새는 "전투와 단절" 비판 [추정·검색요약], V Rising(쿼터뷰 액션 + 성 건설)은 구획된 성터·공성 규칙으로 성공 [추정·검색요약]. 자유 건설은 7 Days to Die 처럼 몬스터 길찾기 착취(킬 코리더)를 부른다 [검증 커뮤니티 위키].
5. **TDGame 고유 충돌 지점 3개:** ① 동적 내비메시 + 유틸리티 AI 에 '막힌 길 → 구조물 공격' 원시 행동이 없음(추정), ② 플레이어 건물 높이 H 가 화면 위쪽에서 2.66H 길이의 땅을 가리는데 현재 컷아웃은 플레이어 중심 반경 260 cm 뿐 [검증 설정값 + 계산], ③ 결정론 전투 시뮬레이터가 지형·구조물 변화를 모르면 밸런스 측정이 깨진다.
6. **권장 조합(재미 위험 기준):** S2(유한 시드 지역 고리, 걸어서 이어짐) 또는 S1(메타 무한 심연) + B1(거점 구획 격자 건설) + B3(전투용 시한 설치물) + C1(지형 변형은 파괴 가능한 바위 인스턴스로 흉내). 청크 무한(S3)과 실제 지형 변형(C2)은 측정 관문을 통과한 뒤에만.

## 1. 탑다운 화면 기하와 콘텐츠 밀도 (계산)

입력: 스프링암 1,100 cm, 피치 -50°, 요 45°, 수평 시야각 90°는 공통 맥락 제공값 [추정: 저장소에서 직접 확인 못 함 — `Source/TDGame` 에서 `TargetArmLength`/`FieldOfView` 검색 무적중]. 이동 속도 600 cm/s 는 `Source/TDGame/Characters/TDGameCharacter.cpp:122` `DefaultMaxMoveSpeed = 600.f` [검증]. 화면비 16:9 가정 [추정].

| 항목 | 값 | 계산 |
|---|---|---|
| 수직 시야각 | 58.7° | 2·atan(tan45°·9/16) |
| 카메라 높이 | 8.43 m | 11.0·sin50° |
| 화면 하단이 닿는 땅 | 플레이어 뒤 5.5 m | 8.43/tan(79.4°)=1.6 m (카메라 바로 아래 기준) |
| 화면 상단이 닿는 땅 | 플레이어 앞 15.3 m | 8.43/tan(20.6°)=22.4 m |
| 화면 폭(하단/플레이어/상단) | 14.9 / 22.0 / 41.7 m | 광축 깊이 z=0.643g+6.45 m, 반폭=z (폭은 지면 거리 g 에 선형) |
| 보이는 땅 면적 | 약 588 m² | 사다리꼴 (14.9+41.7)/2 × 20.8 |
| 화면 깊이 통과 시간 | 3.5 초 | 20.8 m ÷ 6 m/s |
| 새로 드러나는 면적 | 약 170 m²/s ≈ 1 ha/분 ≈ 17화면/분 | 평균 폭 28 m × 6 m/s |
| 1시간 직진 | 21.6 km, 0.6 km² | |

함의 [추정, 위 계산에서 도출]:
- **지평선 부재.** 앞쪽 시야가 15 m 에서 끝난다. 3인칭 오픈 월드의 "멀리 보이는 산·탑으로 간다"는 탐험 동기가 성립하지 않는다. 무한 세계를 걷게 만드는 힘은 지도 안개 걷기, 미니맵 표식, 화면 가장자리 방향 표시, 소리·빛기둥 같은 **화면 밖 신호**가 맡아야 한다.
- **면적은 병목이 아니다.** 64 km²(8×8 km) ÷ 0.6 km²/시간 ≈ 107시간. 전투·회수를 섞으면 더 길다. 따라서 '무한'을 택하는 이유는 면적 부족이 아니라 재방문·시드 다양성·"끝이 없다"는 약속이다.
- **밀도 요구.** 설계 가정 "10~20초마다 무언가"를 두면 경로상 60~120 m 간격, 즉 1 km² 당 약 70~280개 관심 지점이 필요하다(격자 간격 s 일 때 (1000/s)²).
- **반복 수학.** 분당 3~6개 관심 지점 소비 → 시간당 180~360개. 손 템플릿 40개면 각 템플릿을 시간당 4.5~9회 본다. 템플릿 하나에 변주 축(바이옴 장식 × 몬스터 무리 × 보상 규칙 × 지형 맞춤)을 곱해야 '지각적 고유성'에 닿는다.
- **가림 기하.** 높이 H 인 벽 뒤로 가려지는 땅 길이 = H/tanθ(θ=시선 내림각). 플레이어 위치 θ=50° → 0.84H, 화면 상단 θ=20.6° → 2.66H. 3 m 벽이면 플레이어 근처 2.5 m, 화면 위쪽 8.0 m 가 가려진다. 현재 가림 컷아웃 설정은 반경 260 cm·경계 120 cm·밑동 유지 40 cm·최대 절단 0.92 [검증 `Source/TDGame/Framework/TDTopDownSettings.h:24-34`], 머티리얼 파라미터 컬렉션에 모양·초점(폰 기준)을 넣는 구조 [검증 `Source/TDGame/Framework/TDTopDownOcclusionSubsystem.h:34-47`]. 초점이 폰 하나이므로 화면 위쪽의 플레이어 건물 뒤 적은 가려진다 [추정: 필드 이름·함수 시그니처 기준, .cpp 미열람].

## 3. 관점별 근거와 설계 규칙

### 3.1 절차적 단조로움과 화면당 밀도
- Kate Compton 의 '1만 그릇 오트밀': 수학적으로는 모두 다르지만 사람 눈에는 같다. 구분 가능(perceptual differentiation, 군중·지형에는 충분)과 고유(perceptual uniqueness, 기억에 남는 개성 — 수집·인물에 필요)를 나눈다 [추정·검색요약: CMU 강의 학생 요약 다수. 원문 galaxykate0.tumblr.com 은 403 차단].
- No Man's Sky 비판의 핵심은 "바이옴 1개 = 행성 1개"라 같은 자산이 길게 노출된 것 [추정·검색요약]. 탑다운은 화면이 작아 한 바이옴의 같은 자산이 더 짧은 주기로 반복된다(1절).
- Spelunky: 4×4 방 격자, 출발 방에서 무작위 보행으로 해답 경로 보장(1·2=왼쪽, 3·4=오른쪽, 5=아래), 경로 밖은 막힌 방 [검증 tinysubversions.com/spelunkyGen]. **구조는 절차, 방 내용은 손**이 오트밀을 피하는 가장 검증된 형태다.
- 규칙 R-밀도: (a) 바이옴 하나가 연속으로 화면을 채우는 시간을 상한으로 둔다(예: 90초 이내 경계·관심 지점), (b) 관심 지점은 '손 조각 × 변주 축' 조합, (c) '고유' 등급 콘텐츠(이름 있는 보스·랜드마크 던전)는 절차 생성하지 않고 손으로 만들어 배치만 절차로 [추정].

### 3.2 거리 기반 진행 구조
- 선례: Factorio(거리 ↑ → 기지 크기·웜 ↑, 시작 반경 무적) [검증], Core Keeper(멀수록 강한 적, 보스가 바이옴 관문) [검증], Minecraft 요새 고리 [검증], Valheim 바깥쪽 고난도 바이옴 [추정].
- ARPG 에서의 위험 [추정]: (a) 이동 빌드가 거리로 밀어붙여 레벨을 건너뛰는 문제 → 거리 고리마다 보스·열쇠 관문(Don't Starve 의 자물쇠·열쇠, Core Keeper 의 보스 관문), (b) 무한 거리 = 무한 수치 상승은 Last Epoch 부패도처럼 **명시적 난이도 손잡이**로 분리하는 편이 전리품 경제 관리에 낫다, (c) 귀환 비용: 거리가 곧 난이도면 거점 왕복 시간이 늘어 걷기 연속성(D-42)과 충돌 → 고리마다 걸어서 닿는 전진 기지(B1 구획)가 해법.
- 규칙 R-진행: 난이도 = f(고리 번호) + 선택적 손잡이(심연 깊이). 고리 경계는 지형·바이옴으로 눈에 보이게 [추정].

### 3.3 건설·지형 변경과 AI·전투 가독성·가림의 충돌
- **길찾기 착취:** 7 Days to Die 좀비는 이동+파괴 비용 최소 경로를 고르므로 플레이어가 경로를 설계한다(킬 코리더) [검증 커뮤니티 위키]. 이는 "몬스터 AI 가 판단한다"는 TDGame 의 전투 설계(유틸리티 + FSM)를 플레이어가 역이용하는 구조다.
- **길찾기 비용:** Factorio 는 설치물을 무시하는 추상 그래프로 원거리 탐색을 안내하고 실제 우회는 근거리 A* 가 맡아, 건설 때 추상 그래프를 다시 만들지 않는다 [검증 FFF-317]. TDGame 은 내비메시가 Dynamic 런타임 생성(D-06, 공통 맥락)이라 설치·철거마다 타일 재생성이 일어난다 — 엔진 비용은 엔진 갈래에서 측정 필요 [추정].
- **습격 규칙:** Valheim(플레이어 근처·2~3분), Necesse(규칙에서 끔), V Rising(골렘 없이는 벽 파괴 불가) — 모두 습격을 **조건·시간·도구로 제한**한다 [추정·검색요약 / Necesse 끄기는 검증].
- **가림:** 1절 계산대로 플레이어 건물은 화면 위쪽에서 높이의 2.66배를 가린다. Project Zomboid 는 건물 안에 커서를 두면 벽·지붕을 플레이어에게만 투명화하고 캐릭터 시야 판정은 유지한다 [추정·검색요약 Steam 토론]. 무릎 높이 절단 셰이더가 흔한 대안 [추정·검색요약 r/isometric].
- 규칙 R-건설 [추정]: (a) 모든 설치 가능 메시는 TDGame 가림 머티리얼 파라미터 컬렉션을 따르는 머티리얼만 허용, (b) 벽 높이 상한 또는 거점 구획 안 '지붕·벽 전체 투명화' 모드, (c) 몬스터에 '경로 막힘 → 가장 싼 구조물 공격' 원시 행동과 구조물 체력·파괴 비용, (d) 착취 방지는 Valheim·V Rising 처럼 규칙(시간·도구·구역)으로 하고 AI 를 매 패치 바꾸지 않는다(7DTD 불만 사례), (e) 결정론 시뮬레이터에 구조물·막힘 입력을 넣어 습격 밸런스를 측정.

### 3.4 손 거점 + 절차적 바깥 세계
- Diablo 계열 마을, Core Keeper 의 중앙 코어 방, Factorio 시작 지역(호수·기본 자원 보장, 절벽 없음) [검증], Necesse 정착지 [검증] — 출발점은 보장된 손 공간, 바깥은 절차.
- TDGame 은 이미 손 제작 메인 월드(잿빛 골짜기)와 걸어서 이어지는 이계 지역(D-42) 구조다 [추정: 공통 맥락]. 이 구조에 바깥 시드 지역을 덧대는 것이 가장 자연스럽다.
- Hytale V2 는 존을 타일로, 바이옴을 직소 조각으로 보는 계층 구조 [검증] — 손 거점(존 하나)을 절차 패치워크의 한 칸으로 끼우는 형태와 맞는다.

### 3.5 무한 세계에 손 설계 던전·보스 배치
| 방식 | 사례 | 장점 | 위험 |
|---|---|---|---|
| 시드 고리 | Minecraft 요새 [검증] | 거리 진행과 결합, 찾기 쉬움 | 고리 밖은 비어 보임 |
| 간격 격자(구역마다 하나, 무작위 오프셋) | Hytale 점 격자 + 패턴 스캔 [검증] | 밀도 균일, 무한 확장 | 지형 맞춤 실패 시 어색 |
| 그래프(자물쇠·열쇠) | Don't Starve [추정·검색요약] | 진행 순서 보장 | 무한에는 고리 단위로 반복 필요 |
| 방 조각 조립 | Spelunky [검증], Minecraft Dungeons [추정·검색요약] | 손맛 + 변주 | 조각 수가 적으면 반복 체감 |
| 메타 지도 노드 | PoE2 아틀라스, Last Epoch 웹, Necesse 침공 [추정·검색요약] | ARPG 반복 고리에 최적, 기술 위험 최소 | 인스턴스 진입이 D-42(연속 보행)와 충돌 |

TDGame 저장소에는 이미 "시드 던전 '심연'을 무한 반복 단위"로 둔 제안이 있다 [검증 `Docs/Gameplay_Fun_And_Systems_Analysis.md:175` GP-55, 같은 시드 같은 해시 기준]. 메타 층 무한(S1)의 출발점이 된다.

### 4.3 공통 위험 목록
- W1 오트밀(3.1): 시간당 같은 템플릿 노출 수를 지표로 둔다.
- W2 탐험 동기 부재(1절 지평선): 화면 밖 신호 체계를 세계 생성과 같은 단계에서 설계.
- W3 진행 곡선 붕괴(3.2): 고리 관문 + 명시적 난이도 손잡이 분리.
- W4 AI 착취·끼임(3.3): '막힘 → 구조물 공격' 원시 행동, 습격 규칙 제한, 시뮬레이터 검사.
- W5 가림(1절 2.66H): 설치물 머티리얼 강제, 구획 내 투명화 모드.
- W6 저장 폭증: 시드 + 변경 차분만 저장, 구획 밖 휘발.
- W7 사용자 선호 충돌: 포탈·암전 거부(D-42) — S1 의 인스턴스는 걸어서 들어가는 형태여야 함.
- W8 건설의 전투 단절(Torchlight III): 건설 산출물이 전투력·전리품·습격 보상에 직접 연결되어야 함.

## 5. 권장 순서 [추정]
1. 현 잿빛 골짜기에서 **관심 지점 간격·시간당 반복 지표**를 측정하는 도구부터(밀도 기준선). 무한 여부와 무관하게 필요.
2. S1(심연 메타 무한) 또는 S2(시드 지역 고리) 중 하나로 '끝없음'을 먼저 제공. 둘 다 기존 손 세계·연속 보행 구조를 깨지 않는다.
3. B3(전투 시한 설치물) → B1(거점 구획 건설) 순. B1 진입 전 가림 머티리얼 강제와 '막힘 → 구조물 공격' 행동을 결정론 시뮬레이터로 검증.
4. C1 으로 채굴·지형 변경 체감 제공. C2/S3 는 엔진 갈래의 비용 측정과 1~3단계 지표가 통과한 뒤 재검토.

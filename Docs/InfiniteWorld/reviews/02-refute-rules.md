## 중요

### R-01 0절 A 판정 "가능(남은 관문 2개)"·"60 fps 유지"가 본문 수치와 어긋난다
- 위치: 0절 표 A행(:16) 대 0절 2항(:23)·단계 0(:448-461)
- 문제: 0절은 남은 관문을 GPU·패키지 2개라 하지만 2항과 G0는 4개(ISM 충돌 정책, 내비 튐 포함)이고 G0는 넷 다 통과해야 한다(:457). 현재 측정값이 이미 G0 기준을 못 넘는다.
- 근거 [검증]: 내비 타일 반영 최대 프레임 24~39 ms(:134) > IW-04 기준 33.3 ms(:455). 충돌 켠 ISM 상태 15 m/s 프레임 CPU p99 8.7 ms(:126) > IW-03 기준 8 ms(:454). 스트리밍 측정은 모두 NullRHI(:105, `IW:bench/run_bench.ps1:21`)에 60 fps 제한이고, 50 m/s 최대 20.5 ms(:124)는 16.7 ms를 넘는다.
- 수정: A행을 "CPU·결정론 측면은 측정으로 유망, G0 4관문 통과 전까지 조건부"로 바꾼다. "60 fps 유지"는 "NullRHI 프레임 CPU p99 16.7 ms 미만(최대 20.5 ms)"으로 고친다.

### R-02 D-05는 확정 결정이 아니라 '미정·사용자 지시 보류'다
- 위치: 7절 바뀌는 결정 D-05 행(:581), 3.2 정합 근거(:200)
- 문제: 초안은 D-05의 현재를 "야외 바탕은 랜드스케이프"로 적고 "적용 범위 축소"를 기본값 진행 대상으로 둔다. 실제로 D-05는 확정된 적이 없고, 사용자가 명시적으로 보류시킨 항목이다.
- 근거 [검증]: `Docs/Tasks/decisions.md:42` "결정: (미정) … 사용자 확정 필요", `:43` "보류: 2026-09-18 사용자 지시로 미룸".
- 수정: "D-05는 미정·보류다. 무한 영역은 D-05 재개를 전제로 하므로 사용자 보류 해제가 필요하다"고 적는다. 사용자가 직접 보류시킨 항목이므로 '확인 없이 권장안 진행' 선호를 적용하지 말고 IWQ-06에 묶어 사용자 질문으로 올린다.

### R-08 D-47과 AGENTS 7절 "생성 결과에 쓰이는 데이터는 시작 전에 모두 불러온다"를 충족하지 못한다
- 위치: 4.1(:243-249), 4.5 준비 판정(:318), 4.7 L3 "세트피스 도장"(:348), 4.8(:357)

- 수정:

  - 조우 종은 기존 `AreSpeciesLoaded` 경로(`TDArenaEncounter.h:73`)를 쓴다고 명시한다.

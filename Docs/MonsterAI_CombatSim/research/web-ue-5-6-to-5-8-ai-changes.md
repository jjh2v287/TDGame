조사일: 2026-09-09. 설치 엔진: UE 5.8 (`C:/Program Files/Epic Games/UE_5.8/Engine`). 조사 방법:
- 공식 릴리스 노트 3종(5.6/5.7/5.8), Epic 공개 로드맵(productboard) 카드 본문, 플러그인 색인(PluginIndex), 포럼 공지·이슈 스레드, Epic 직원이 쓴 튜토리얼·지식 베이스를 WebFetch 또는 내장 브라우저로 열어 본문을 확인했다.
- 웹에서 상태 표식이 엇갈리는 항목은 설치된 5.8 엔진의 `.uplugin` 파일과 소스(파일:줄)로 재확인했다(엔진 근거는 "엔진:"으로 표기).
- 확인하지 못한 항목은 "미확인"으로 표기했다. 2차 출처(블로그)는 "2차"로 표기하고 공식 출처와 상충하면 채택하지 않았다.
- 릴리스 노트 주소 규칙: `dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-X-release-notes?application_version=5.X`. 5.6·5.7 노트는 자바스크립트 렌더링이라 WebFetch로는 목차만 수신되며, 브라우저로 열었을 때 한국어 번역 페이지가 표시됐다(하이라이트 절 제목이 한글).

## 결론 요약 (설계 결정에 바로 쓸 수 있는 문장들)

1. **스테이트 트리(StateTree)는 5.8에서도 유일하게 "표식 없음(정식)"인 AI 프레임워크이고, 5.6부터 "엔진 틱에 묶인다"는 우려가 구조적으로 해소됐다.** 5.6에 스케줄 틱(잠자기·이벤트 깨우기·상태별 커스텀 틱 간격), 5.7에 런타임 데이터·메모리 최적화, 5.8에 시작 상태 지정·비동기 컴파일·AI 모듈 의존성 제거가 들어갔다. 엔진: `FStateTreeScheduledTick::MakeSleep / MakeEveryFrames / MakeNextFrame / MakeCustomTickRate(float DeltaTime, …)` (`Plugins/Runtime/StateTree/Source/StateTreeModule/Public/StateTreeExecutionTypes.h:826-832`), 태스크 기본값 `bShouldCallTick(true)`, `bShouldCallTickOnlyOnEvents(false)` (`…/Public/StateTreeTaskBase.h:25-26`), 컴포넌트 스키마 CVar `StateTree.Component.DefaultScheduledTickAllowed` (`Plugins/Runtime/GameplayStateTree/Source/GameplayStateTreeModule/Private/Components/StateTreeComponentSchema.cpp:25`). 웹: 로드맵 카드 "StateTree Scheduled Ticks and Performance"(2025-05) https://portal.productboard.com/epicgames/1-unreal-engine-public-roadmap/c/2029-statetree-scheduled-ticks-and-performance ; Epic 직원 James Keeling 튜토리얼 "Tickless StateTree Changes"(2025-10-08) https://dev.epicgames.com/community/learning/tutorials/z3km/unreal-engine-tickless-statetree-changes ; 플러그인 색인 StateTree(5.8, 표식 없음) https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/StateTree ; 엔진 `Plugins/Runtime/StateTree/StateTree.uplugin`에 `IsExperimentalVersion` 키 없음, `IsBetaVersion: false`.
2. **Mass는 5.8에서 엔진 런타임 모듈(`Engine/Source/Runtime/Mass/{MassCore, MassEntity, MassSignals, MassEngine, MassDeveloper}`)로 승격됐지만, 게임플레이 스택(MassGameplay/MassAI/MassCrowd)은 여전히 Experimental이고 Epic은 "결정론적인 것은 프로세서 실행 순서뿐"이라고 답했다.** 5.8.0에는 `ParallelForEach`가 강제 인라인 실행되는 회귀가 있었고 5.8.1에서 수정됐다. 대량 몬스터 층으로 Mass를 쓰려면 5.8.1 이상 + 병렬 옵션을 끄고 결정론은 프로젝트가 보장해야 한다. (엔진: `ls Engine/Source/Runtime/Mass` 결과 5개 모듈; `Plugins/Runtime/MassGameplay/MassGameplay.uplugin`, `Plugins/AI/MassAI/MassAI.uplugin`, `Plugins/AI/MassCrowd/MassCrowd.uplugin` 모두 `"IsExperimentalVersion": true`, VersionName 0.4. 웹: 포럼 "Mass(Entity) RoadMap/Vision"(2025-04-25, James Keeling) https://forums.unrealengine.com/t/mass-entity-roadmap-vision-and-more-questions/2527030 ; 포럼 "MassEntity threading model in 5.8"(2026-06-19) https://forums.unrealengine.com/t/massentity-threading-model-in-5-8/2729956 ; 로드맵 카드 "Mass Framework: faster, modular, and built for scale"(2026-04-30) https://portal.productboard.com/epicgames/1-unreal-engine-public-roadmap/tabs/129-unreal-engine-5-8 )
3. **Learning Agents는 5.8에서도 Experimental(엔진 `LearningAgents.uplugin` VersionName 0.2, `IsExperimentalVersion: true`)이고 5.6~5.8 변경은 유지보수 수준이다.** 5.5 재설계(외부 Python 학습기 + TCP 소켓/공유 메모리, 학습 알고리즘 교체 가능)가 현재 구조이며, 5.8에서 `RemoveAgent` 후 `AddAgent` 시 경험이 영구히 버려지는 버그가 보고돼 있다(Epic 답변 없음). 강화학습은 "헤드리스 시뮬레이터 = 학습 환경, Learning Agents = 인터페이스, 학습기 = 외부 Python"으로 설계하고 에이전트 ID를 에피소드마다 재생성하지 않는다. (웹: 로드맵 카드 "Learning Agents"(2024-09) https://portal.productboard.com/epicgames/1-unreal-engine-public-roadmap/c/1654-learning-agents ; 포럼 버그(2026-08-17) https://forums.unrealengine.com/t/bug-report-learning-agents-addagent-after-removeagent-causes-permanent-non-matching-iteration-numbers-desync/2744464 ; 색인 https://dev.epicgames.com/documentation/unreal-engine/API/PluginIndex/LearningAgents )
4. **Mover는 5.8에서도 공식적으로 Experimental이다. "5.8에서 베타"라는 블로그 주장은 틀렸다.** 엔진 `Plugins/Experimental/Mover/Mover.uplugin`: `"IsBetaVersion": false, "IsExperimentalVersion": true`. 5.8 로드맵 카드 원문: "these changes continue the architectural work toward moving Mover out of Experimental status". Epic 직원(PyroJimmy, 2026-02~03): "I fully expect breaking API changes between now and Beta." TDGame 몬스터 이동은 Mover가 아니라 자체 결정론 이동(또는 Mass 프래그먼트)으로 한다. (웹: https://portal.productboard.com/epicgames/1-unreal-engine-public-roadmap/tabs/129-unreal-engine-5-8 카드 "Mover: Improved Physics, Animation, & Networking"; 문서 https://dev.epicgames.com/documentation/en-us/unreal-engine/mover-in-unreal-engine "Experimental"; 5.8 Experimental Features 목록 https://dev.epicgames.com/documentation/en-us/unreal-engine/experimental-features?application_version=5.8 에 Mover 포함; 포럼 https://forums.unrealengine.com/t/mover-plugin-roadmap-and-layering-issues/2712958 )
5. **결정론·고정 틱은 세 버전 릴리스 노트 어디에도 게임플레이 신기능이 없다. 대신 엔진에는 오래된 커맨드라인 스위치가 있다: `-Deterministic`은 `-UseFixedTimeStep -FixedSeed`의 축약이다.** 엔진: `Source/Runtime/Launch/Private/LaunchEngineLoop.cpp:2457-2462` (`FApp::SetUseFixedTimeStep(bDeterministic || FParse::Param(…, TEXT("UseFixedTimeStep")))`, `FApp::bUseFixedSeed = bDeterministic || FApp::IsBenchmarking() || …("FixedSeed")`), `FApp::SetFixedDeltaTime(double Seconds)` (`Source/Runtime/Core/Public/Misc/App.h:662`), 빌드 매크로 `WITH_FIXED_TIME_STEP_SUPPORT`는 UBT의 `bWithFixedTimeStepSupport`로 결정(`Source/Programs/UnrealBuildTool/Configuration/UEBuildTarget.cs:6447-6453`). 결정론적 전투 시뮬레이션은 이 스위치 + 프로젝트 고정 스텝 루프(`UWorld::Tick` 고정 DeltaTime, 시드 고정 난수, 단일 스레드)로 프로젝트가 소유한다.
6. **5.8의 공식 MCP(Model Context Protocol, 모델 컨텍스트 프로토콜) 서버 플러그인은 Experimental이며 HTTP+SSE 전용·루프백 전용·인증 없음이고, 툴 호출은 게임 스레드에서 직렬 실행된다.** 기본 툴셋은 SceneTools/ActorTools/MaterialInstanceTools/ObjectTools 계열이며 StateTree/비헤이비어 트리 전용 툴은 공식 문서에 없다(2차 출처는 "AIModuleToolset이 빈 스텁"이라 주장, 미확인). 생성형 AI 작업 흐름의 1차 경로는 "C++/텍스트 파일 편집 + 커맨드라인 자동화 테스트", MCP는 보조. (엔진: `Plugins/Experimental/ModelContextProtocol/ModelContextProtocol.uplugin` `"IsExperimentalVersion": true`. 웹: 문서 https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor ; VP Land 2026-06-24 https://www.vp-land.com/stories/unreal-engine-5-8-embeds-an-mcp-server-so-ai-agents-can-drive-the-editor ; 5.8.1 핫픽스 2026-07-28 https://forums.unrealengine.com/t/5-8-1-hotfix-released/2738864 )
7. **5.8은 "마지막 예정 UE5 메이저"이고 UE6 얼리 액세스는 2027년 말 목표("ish")다.** C++ + 텍스트 데이터 중심 설계는 이 방향과 부합한다. (웹: GamesBeat 2026-06-17 https://gamesbeat.com/epic-games-launches-unreal-engine-5-8/ ; CG Channel 2026-06-21 https://www.cgchannel.com/2026/06/10-things-cg-artists-need-to-know-about-unreal-engine-6/ "There won't be an Unreal Engine 5.9 – unless there is.")
8. **UAF(Unreal Animation Framework, 구 AnimNext)는 5.8에서도 Experimental이고 Epic 스스로 "정식까지 수년"이라고 밝혔다.** 헤드리스 시뮬레이터에서는 애니메이션을 돌리지 않고, 시각 계층만 AnimBP/UAF를 고른다. (웹: UAF FAQ 2025-06-04, Euan Carmichael https://dev.epicgames.com/community/learning/knowledge-base/nWWx/unreal-engine-unreal-animation-framework-uaf-faq "UAF is currently experimental and will take several years to reach production-ready status."; 색인 https://dev.epicgames.com/documentation/en-us/unreal-engine/API/PluginIndex/UAF )
9. **HTN Planner 플러그인은 5.8에서 `IsBetaVersion: true`이면서 설명은 "[EXPERIMENTAL] … UE4's AI module"이고 VersionName 0.01, 5.6~5.8 노트에 변경 0건이다.** 사실상 방치 상태로 보고 채택 후보에서 낮게 둔다. (엔진: `Plugins/AI/HTNPlanner/HTNPlanner.uplugin:4-15`. 웹: https://dev.epicgames.com/documentation/en-us/unreal-engine/API/PluginIndex/HTNPlanner )
10. **알려진 회귀(목표 관련):** 5.6.1 StateTree "On Tick 트랜지션 미발화"(5.7 수정), 5.6 스케줄 틱 정책 도입으로 "틱 태스크가 꺼진다" 혼란, 5.8.0 Mass 병렬 실행 회귀(5.8.1 수정), 5.8 StateTree 링크 에셋 서브트리 완료 트랜지션 실패(UE-384337, 5.8.2까지 잔존 보고), 5.8 Mass 복제(MassReplication) 회귀 3건(Epic: "더 이상 업데이트 없음, UE6 Main의 MassIrisReplication로 이전"), 5.8 Learning Agents Add/Remove 비동기화, 5.7.1 Mover 몽타주 복제 desync(UE-350214)·RollbackBlackboard 크래시(UE-350810).

## 프로젝트 적용 시사점 (TDGame)

### 쓸 것
1. **StateTree를 C++ 태스크/조건/고려사항(유틸리티 점수) 중심으로 사용하되, 자체 스키마를 만들어 틱을 우리 고정 스텝 루프에서 호출한다.** 5.6 노트 "The feature has to be implemented by each schema"와 엔진의 `FStateTreeScheduledTick::MakeCustomTickRate` 덕분에 `FTDScopedCombatWorld`처럼 `World->Tick` 고정 DeltaTime과 함께 StateTree를 전진시키는 경로가 성립한다. 커스텀 틱 간격은 "가장 작은 값이 이긴다"는 규칙 때문에 몬스터 등급별 간격을 루트 상태 하나에서만 정한다. 비동기 태스크·델리게이트 콜백은 시뮬 모드에서 금지(스레드 안전 책임이 개발자).
2. **몬스터 AI 정의는 "C++ 노드 + 얇은 StateTree 자산" 또는 "텍스트(JSON/DataAsset) → 자산 생성기"로 이원화한다.** 릴리스 노트 3종에 StateTree 텍스트 정의 기능은 없으므로 생성형 AI가 다루는 층은 C++/텍스트로 제한하고 자산은 생성 산출물로 취급한다. 5.8 "시작 상태를 게임플레이 태그로 오버라이드"는 밸런스 툴의 시나리오 시작점 지정에 바로 쓴다. 5.7 옵트인 "Re-Enter State"로 주기적 유틸리티 재평가를 구현할 수 있다.
3. **결정론 시뮬레이터는 엔진 신기능이 아니라 기존 스위치 + 프로젝트 루프로 소유한다.** `-Deterministic`(= `-UseFixedTimeStep -FixedSeed`, `LaunchEngineLoop.cpp:2457-2462`) 또는 `FApp::SetFixedDeltaTime`(`App.h:662`), 시드 고정 난수, 단일 스레드 실행, StateTree 비동기 컴파일 cvar 기본값(비활성) 유지, Mass 사용 시 `bRunInParallelMode`·처리 큐·타임 슬라이싱 해제. 빌드 타깃의 `bWithFixedTimeStepSupport`(`UEBuildTarget.cs:6447`)가 켜져 있는지 확인한다.
4. **강화학습·모방학습은 Learning Agents(Experimental)를 "인터페이스"로만 쓰고 학습기는 외부 Python로 둔다.** 헤드리스 시뮬레이터가 곧 학습 환경이 되도록 관측/행동/보상을 시뮬 데이터 구조에서 직접 뽑는다. 5.8 Add/Remove 버그 회피: 에피소드 재시작 시 에이전트 ID를 유지하고 상태만 리셋. 정책 추론은 NNE(`NNERuntimeBasicCpu`는 `.ubnne`, ONNX는 `NNERuntimeORTCpu`).
5. **대량 몬스터 계층 분리:** 근접·활성 몬스터는 StateTree(액터 또는 경량 UObject), 원거리·군중은 Mass 프래그먼트 + MassStateTree 프로세서(시그널 기반 틱, 5.6부터 병렬 옵션, 5.8부터 희소 프래그먼트·MassCore 분리). Mass 게임플레이 스택은 Experimental이고 5.8.0 회귀가 있었으므로 설치본이 5.8.1 이상인지 먼저 확인한다. MetaHuman Crowd(5.8)의 "근거리 액터 / 원거리 인스턴스 스킨 메시" 구조를 시각 계층 참고로 삼는다.

### 피할 것
1. **Mover에 몬스터 이동을 맡기지 않는다.** Experimental(엔진 .uplugin 확인), API 파괴 예고, RVO 미지원(5.8은 Detour Crowd 인터페이스만), 고정 틱 관련 버그 이력. 시뮬레이터용 이동은 자체 결정론 적분기.
2. **HTNPlanner 플러그인은 기본 후보에서 제외한다.** 3개 버전 노트에 변경 0, VersionName 0.01, 상태 표기 상충(Beta 플래그/Experimental 설명), "UE4's AI module" 문구. 계획형 AI가 필요하면 자체 C++ 계획기(HTN/GOAP)를 텍스트 정의로 구현하는 편이 생성형 AI 친화적이다(엔진 조사 문서 `engine-htnplanner-plugin.md`와 교차 검토).
3. **UAF·MetaHuman Crowd·Chooser 모션 매칭 통합은 시뮬레이터와 분리한다.** 모두 Experimental이며 헤드리스 결정론과 무관.
4. **MCP 서버를 필수 경로로 삼지 않는다.** 인증 없음·HTTP 전용·Experimental·게임 스레드 직렬 실행·툴셋 수동 활성화 필요. 생성형 AI 작업 흐름은 파일 편집 + 커맨드라인 자동화 테스트가 1차.
5. **Tick 트랜지션(On Tick 조건 평가)과 링크 에셋 서브트리 + 즉시 완료 태스크 조합에 핵심 로직을 두지 않는다.** UE-222632(5.6)·UE-384337(5.8) 이력을 따라 이벤트/델리게이트/태스크 완료 기반으로 설계하고 자동화 테스트로 회귀를 감시한다.
6. **블루프린트 로직 확대 금지.** UE6 전환 예고와 프로젝트 원칙(C++ 전용 로직)이 일치한다.

### 버전 고정 권고
- 5.8.1 이상 사용(Mass 병렬 회귀·MCP 트랜잭션 수정). 5.8.2(2026-08-25)는 Mass 프로세서 인스턴스 재사용·공유 프래그먼트 해시 수정 포함. 단 StateTree UE-384337은 5.8.2에도 잔존 보고.
- 5.6.x는 StateTree Tick 트랜지션 버그(UE-222632) 때문에 회피.

## 미확인·미해결 질문

1. **StateTree 스케줄 틱이 헤드리스 고정 스텝(`UWorld::Tick` 고정 DeltaTime)에서 "잠자기 → 깨어남" 시간을 어떤 시계로 재는지** — 릴리스 노트에는 없음. `FStateTreeScheduledTick`(`StateTreeExecutionTypes.h:826-832`)과 `UStateTreeComponent` 스케줄 틱 구현을 엔진 소스 담당 문서(`engine-statetree-runtime.md`)에서 확인.
2. **StateTree를 액터/컴포넌트 없이 순수 C++ 객체에서 실행할 때 필요한 최소 스키마 구성** — 5.8 "AI 모듈 의존 제거"가 어디까지 진행됐는지(`UStateTreeAIComponentSchema`의 AIController 요구 등) 소스 확인 필요.
3. **Mass 단일 스레드 강제 CVar의 정확한 이름과 5.8 처리 큐(`mass.UseProcessingQueue`)·`mass.ForceInlineProcessorExecution`의 상호작용** — 설치본(런처판 5.8)의 `Engine/Source/Runtime/Mass`에는 .cpp가 28개뿐이라 private 소스가 일부만 포함돼 있고, `ForceInlineProcessorExecution` 문자열은 `Engine/Binaries/Win64/UnrealEditor-MassEntity.pdb`(바이너리)에서만 검색됨 → 심볼은 존재하나 소스 줄 번호로 근거를 댈 수 없음(GitHub 소스판 필요). 결정론 목적의 공식 가이드 없음.
4. **5.6 릴리스 노트의 CVar 표기 `StateTree.Component.ScheduledTickEnabled` vs 5.8 소스 `StateTree.Component.DefaultScheduledTickAllowed`** — 5.6→5.8 사이 이름 변경 여부(5.7 소스) 미확인.
5. **Learning Agents 5.8의 LACombat** — 릴리스 노트에만 등장. 샘플 프로젝트인지 내부 모듈인지 웹에서 확인 불가.
6. **에디터 AI Assistant(5.7)의 5.8 상태** — 5.8 노트에 승격/변경 언급 없음. 5.8.1 노트에 "Assistant edit certain kinds of Blueprints" 크래시 수정만 존재.
7. **State of Unreal 2026 공식 본문** — unrealengine.com 뉴스·이벤트 페이지 403. UE6 시기·5.9 가능성은 CG Channel·GamesBeat(2차)로만 확인.
8. **unrealengine.com 5.7/5.8 공식 뉴스 페이지·Game Animation Sample 5.7 테크 블로그** — 403. 포럼 공지·로드맵으로 대체.

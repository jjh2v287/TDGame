# TD 데미지 오브젝트 시스템 설계

작성일: 2026-09-06

## 현재 상태

- 기본 데미지 엔티티, 상태이상, 이벤트 연계, 지연 액션과 호밍을 GAS 공통 전투 기반에 연결했다.
- 플레이어·동료·몬스터는 `ATDCombatCharacter`의 ASC와 AttributeSet을 사용한다. 피해, 상태 지속 시간과 시전 쿨다운은 GameplayEffect로 처리한다.
- 현재 구조와 사용 정책은 [GAS 기반 문서](TDGASFoundation.md)가 기준이다. 액터 풀은 아직 구현하지 않았으며 같은 문서에 적용 판단을 정리했다.
- DataAsset 12개와 C++를 상속하는 설정 전용 플레이어/컨트롤러/게임 모드 블루프린트를 제공한다. 기본 게임 모드는 `BP_TDCombatGameMode`다.
- 기존 자동화 테스트 21개 통과와 `Docs/Validation`의 PIE 관측 기록은 GAS 전환 전 결과다. 현재 GAS 코드의 실행 검증 결과로 간주하지 않는다.
- 사용자의 지시에 따라 이번 GAS 변경에서는 에디터 테스트와 자동화 테스트 실행을 하지 않는다. 기존 22개 및 GAS 5개 검사 소스를 컴파일에 포함한다.
- GAS 변경 후 에디터 대상 Development 빌드와 게임 대상 Development 빌드를 모두 통과했다. 빌드 성공을 런타임 검증으로 간주하지 않는다.
- 실행 방법은 [사용 안내](TDDamageSystemGuide.md)에 정리했다. 완성된 VFX, 대규모 성능, 배포 패키지는 별도 검증 대상이다.

## 목표와 범위

싱글 플레이에서 시전자의 능력치를 반영하는 투사체, 범위 공격, 장판, 지뢰, 확장하는 도넛 쇼크웨이브, 낙하 공격과 상태이상을 데이터로 조합한다. 파이어볼에서 화염 장판을 만들거나, 블리자드 누적 피해로 빙결을 발동하고 해제 시 추가 피해를 주는 연계를 지원한다.

게임 로직은 C++로 구현한다. 블루프린트는 컴포넌트 구성, 데이터와 시각 에셋 연결에만 사용한다. 이번 범위에는 네트워크 복제, 인벤토리, 스킬 트리, 마나 시스템 및 완성된 VFX 제작을 포함하지 않는다.

## 데이터 형식 선택

`UDataAsset`을 기준으로 한다.

- 데미지 정의에서 후속 엔티티, 상태이상, Niagara, 메시를 직접 참조할 수 있다.
- 에디터에서 구조화된 프로퍼티를 편집하고 저장 전에 유효성을 검사할 수 있다.
- 중첩 액션과 에셋 간 참조가 많은 이번 구조에서는 하나의 평면 DataTable보다 관계를 표현하기 쉽다.
- JSON 로딩, 에셋 경로 해석 및 런타임 스키마 변환 계층을 추가하지 않는다.
- 향후 대량 밸런스 수치 편집이 실제로 필요하면 능력치 곡선이나 수치 표만 별도 테이블로 분리한다.

원본 DataAsset은 실행 중 변경하지 않는다. 현재 목표, 적용된 호밍 설정, 남은 시간, 적중 기록은 각 실행 인스턴스가 보관한다.

## 책임 분리

| 구성 | 책임 |
| --- | --- |
| `FTDCombatStats` | 레벨, 진영, 체력, 공격력, 주문력, 방어, 치명타 입력값과 성장 계산 |
| `FTDScaledValue` | 기본값, 레벨 계수, 공격력 계수, 주문력 계수로 효과량 계산 |
| `UTDCombatComponent` | ASC 구현. GAS 능력치·피해·사망 알림, 상태이상 누적/이펙트 연결과 빙결 복원 |
| `UTDCombatAttributeSet` | 실행 중 체력과 전투 능력치의 기준 |
| `UTDDamageGameplayAbility` | 시전 조건, 사거리와 정의별 GAS 쿨다운, 최초 엔티티 생성 |
| `UTDDamageDefinition` | 형태, 수명, 판정 크기, 적중 간격, 이벤트 액션, 시각 설정 |
| `UTDStatusDefinition` | 누적 임계값, 지속 시간, 갱신 정책, 주기/해제 액션 |
| `ATDDamageEntity` | 한 엔티티의 이동, 충돌, 적중 이력, 이벤트 발생, 예약 액션과 호밍 상태 |
| `UTDDamageSubsystem` | 시전 문맥 생성, 엔티티 생성, 공통 액션 실행, 대상 등록과 진영 필터 |
| 공통 캐릭터/플레이어 컨트롤러 | ASC 초기화, 스킬 구성과 입력을 공통 GAS 시전 경로로 전달 |

호밍은 별도의 `HomingProjectile` 종류로 만들지 않는다. 기본 형태가 `Projectile`인 엔티티의 이동 기능으로 적용한다. 모든 동작을 가상 인터페이스나 UObject 상속 계층으로 나누지 않고, 현재 필요한 데이터 구조와 실행 함수로 구성한다.

## 시전 문맥과 성장

시전 시점에 능력치를 복사한 `FTDDamageContext`를 만든다. 후속 장판, 낙하체, 상태이상에도 같은 능력치 복사본과 원래 시전자 참조를 전달한다.

- 도중에 시전자 레벨이 바뀌어도 이미 시전한 효과의 세기는 바뀌지 않는다.
- 시전자가 사라져도 이미 생성된 효과는 복사된 능력치와 진영으로 계산한다.
- 시전자 참조는 약한 참조로 보관한다. 소멸한 시전자를 역참조하지 않는다.
- 레벨은 우선 1~1000으로 제한한다. 음수 수치와 비정상 실수 입력을 방어한다.
- 레벨 차이에 따른 별도의 숨은 피해 배율은 두지 않는다. 공격자 성장과 대상의 체력/방어로 차이를 표현한다.

계산식:

- 최대 체력 = 기본 체력 + 레벨당 체력 × (레벨 − 1)
- 유효 공격력/주문력 = 기본 능력치 + 레벨당 성장 × (레벨 − 1)
- 효과량 = 기본값 + 레벨 계수 × (레벨 − 1) + 공격력 계수 × 유효 공격력 + 주문력 계수 × 유효 주문력
- 피해 = 효과량 × 치명타 배율 × 100 / (100 + 방어값)
- 물리는 Armor, 나머지 속성은 MagicResistance를 사용한다.
- 실제 적용 피해는 남은 체력을 넘지 않는다. 누적 상태이상은 이 실제 적용 피해를 사용한다.

초기 계수와 예제 수치는 동작 확인용이다. 밸런스가 검증된 수치가 아니다.

## 형태와 판정

| 형태 | 기본 동작 |
| --- | --- |
| Projectile | 이동 구간을 스윕해 대상과 지형을 검사한다. 적중 시 소멸 또는 관통을 설정한다. |
| Area | 원통 범위 안의 대상을 활성화 시점과 이후 주기마다 검사한다. |
| Mine | 준비 시간이 지나면 감지 범위를 검사하고, 최초 대상 발견 시 Trigger를 발생시킨다. |
| Shockwave | 내부/외부 반경을 함께 확장한다. 이전 내부 반경부터 현재 외부 반경까지 검사해 큰 프레임에서도 지나친 띠를 판정한다. |

블리자드와 운석은 생성 액션으로 위 형태를 조합한다. 별도 블리자드 전용 런타임 클래스는 필요하지 않다.

범위 판정은 등록된 전투 컴포넌트의 소유 액터 중심과 높이를 기준으로 한다. 투사체는 충돌체 스윕도 사용한다. 기본 적중 대상은 적 진영이며 시전자 자신은 제외한다. 시야 차단 검사는 데이터에서 선택한다.

`MaxHitsPerTarget = 0`은 횟수 제한 없이 반복 적중하는 설정이다. 이 경우에도 `HitInterval`로 최소 간격을 제한한다.

## 이벤트와 액션

| 이벤트 | 의미 |
| --- | --- |
| Spawn | 실제 생성 시 1회. 생성 후 지연 동작의 기준 시간이다. |
| Activate | ActivationDelay가 지난 시점에 1회. 기본 판정과 주기 동작을 시작한다. |
| Hit | 유효한 대상에 적중했을 때 대상별로 발생한다. |
| Pulse | 활성화 직후 및 이후 설정 주기마다 엔티티 단위로 발생한다. |
| Trigger | 준비된 지뢰가 최초 대상을 감지했을 때 발생한다. |
| Kill | 해당 액션의 피해로 대상이 처음 사망했을 때 발생한다. |
| Expire | 수명이 자연 종료될 때 발생한다. |
| End | 정상적인 적중 소멸, 지뢰 발동 또는 수명 종료 시 1회 발생한다. |

Spawn과 Activate는 분리되어 있다. `생성 1초 후`와 `준비 완료 1초 후`는 서로 다른 기준 시간으로 동작한다. 상태이상의 Spawn은 해당 상태가 발동한 시점을 의미하며 Activate는 상태 정의에서 사용하지 않는다.

외부 Destroy, 맵 종료, 대상 사망으로 상태이상이 제거되는 경우에는 정상 만료 연계를 발생시키지 않는다.

액션 종류:

- Damage: 피해를 주고, 선택적으로 연결된 상태이상에 실제 피해량을 누적한다.
- ApplyStatus: 계산된 효과량을 누적량으로 사용해 상태이상을 적용한다. 임계값 0이면 즉시 적용한다.
- SpawnEntity: 지정한 후속 정의를 이벤트 위치/대상 위치/시전 목표 위치에 생성한다. 개수, 산포, 오프셋, 방향을 설정한다.
- ApplyHoming: 현재 엔티티에 호밍 설정을 적용하거나 교체한다.
- StopHoming: 현재 호밍을 해제하고 마지막 진행 방향으로 이동을 계속한다.

액션은 배열 순서로 실행한다. 한 피해 액션이 처치를 발생시키면 그 Kill 액션을 처리한 뒤 다음 원래 액션으로 돌아온다. 재진입 시 배열과 대상의 유효성을 다시 확인한다.

## 지연 액션과 예약 소유권

각 액션에 `DelaySeconds`를 둔다. 0이면 즉시 실행하고, 양수이면 해당 이벤트가 발생한 시점부터 예약한다.

- 예약은 이벤트를 발생시킨 엔티티가 소유한다.
- 이벤트 당시의 시전 문맥, 이벤트 위치, 약한 대상 참조를 저장한다.
- 예약 실행 시 현재 상태와 대상을 다시 검사한다.
- 대상이 사라졌다면 그 대상에 대한 피해/상태 적용은 생략한다. 저장된 이벤트 위치에 생성하는 액션은 엔티티가 살아 있다면 실행할 수 있다.
- 엔티티가 끝나거나 외부에서 파괴되면 남은 예약을 취소한다.
- 같은 시각의 예약은 등록 순서대로 실행한다.
- 같은 시각의 엔티티 이벤트는 활성화, 예약 액션, 주기 판정 순서로 처리한다. 수명 종료가 겹치면 종료가 우선한다.
- 수명 종료 시각과 같은 시각의 예약은 실행하지 않는다. 예약은 수명 범위 안에서만 유효하다.
- End와 Expire에는 양수 지연을 허용하지 않는다. 종료 후 동작이 필요하면 즉시 자식 엔티티를 생성하고 그 자식의 수명과 지연을 사용한다.
- 상태이상은 자체 주기와 만료 기능을 사용한다. 엔티티 이동 액션과 지연 액션은 상태 정의에서 허용하지 않는다.

지연 액션은 예약할 때 원래 시전의 액션 예산 1회를 소비하며, 실행할 때 중복으로 소비하지 않는다. 취소한 예약의 예산은 돌려주지 않는다. 실행 중 생성하는 자식은 같은 생성 예산을 사용한다. 긴 지연으로 제한을 우회하거나 이미 취소된 예약이 투사체를 되살리는 동작은 허용하지 않는다.

## 호밍 설정과 런타임 상태

호밍 설정은 액션에 포함하는 `FTDHomingSettings` 값 구조체로 시작한다. 재사용 수요가 확인되기 전까지 별도 호밍 DataAsset과 범용 이동 모듈 계층을 만들지 않는다.

| 설정 | 의미 |
| --- | --- |
| TargetSelection | 이벤트의 적중 대상 또는 현재 위치에서 가장 가까운 유효한 대상 선택 |
| SearchRadius | 목표 탐색 거리 |
| TurnRateDegreesPerSecond | 초당 최대 회전 각도. 즉시 방향 전환에 의한 비현실적인 추적을 피한다. |
| RetargetInterval | 재탐색 최소 간격. 모든 프레임에서 전체 대상을 검색하지 않는다. |
| TargetLossPolicy | 목표 상실 시 재탐색 또는 마지막 방향으로 직진 |
| bRetargetOnApply | 재적용 시 기존 목표를 유지할지 새로 선택할지 결정 |

런타임은 현재 목표의 약한 참조, 적용 중인 설정 복사본, 다음 탐색 시간, 활성 여부를 엔티티 내부에 보관한다.

- 추적 중에는 매 프레임 현재 목표 위치를 향해 설정된 회전 속도 안에서 방향을 변경한다.
- 실제 이동 속도는 기본 ProjectileSpeed를 유지한다. 가속과 속도 변경은 이번 호밍 요구와 분리한다.
- ApplyHoming 재실행은 현재 설정을 교체한다. 별도 호밍 인스턴스를 중첩해서 만들지 않는다.
- 목표가 살아 있고 진영 조건을 만족하면 유지한다. 탐색 범위는 초기 획득과 재획득에 사용하며 획득 이후에는 단순 거리만으로 해제하지 않는다.
- 유효한 목표가 없으면 현재 방향으로 이동한다. 재탐색 정책이면 다음 탐색 시각에 다시 찾는다.
- StopHoming은 이동 정지가 아니다. 호밍 활성 상태와 목표를 해제한다.
- C++ 런타임에서도 동일한 적용/중지 함수를 호출할 수 있다. 데이터 액션과 별도 로직을 중복 구현하지 않는다.
- 새 목표를 향해 휘어진 경우에도 해당 프레임 이동 구간의 충돌 스윕을 수행한다.

StopHoming은 이미 정의된 미래의 ApplyHoming 예약을 자동으로 취소하지 않는다. 예를 들어 2초에 중지하고 3초에 재적용하는 시퀀스를 그대로 표현할 수 있어야 한다. 예약 전체 취소가 필요하면 별도 취소 정책을 명시해야 하며, 현재 요구사항에서는 기본 동작으로 넣지 않는다.

설정 예:

| 이벤트 | 지연 | 액션 |
| --- | --- | --- |
| Spawn | 1.0초 | ApplyHoming: 가까운 적, 탐색 800, 초당 회전 180도 |
| Spawn | 2.0초 | StopHoming |
| Spawn | 3.0초 | ApplyHoming: 가까운 적 재선택, 탐색 1200, 초당 회전 360도 |
| Hit | 0초 | Damage |
| End | 0초 | SpawnEntity: FlameField |

위 예제를 사용하려면 투사체 수명이 3초보다 길어야 한다. 기본 파이어볼의 짧은 수명과 혼동하지 않도록 별도 예제를 제공한다.

## 상태이상과 빙결

- 누적 상태는 상태 정의와 원래 시전자별로 구분한다. 서로 다른 시전자의 누적량을 합치지 않는다.
- 일정 시간 새 누적이 없으면 미발동 누적량을 초기화한다.
- 임계값 도달 시 활성화하고 누적량을 소비한다. 초과량은 이월하지 않는다.
- 활성 상태에 다시 적용될 때는 기본적으로 무시한다. 데이터에서 지속 시간 갱신을 선택할 수 있다.
- 빙결 중에는 대상 액터와 이동을 정지한다. 적용 가능한 AI/컨트롤러 상태도 보존 후 정지한다.
- 상태 수명은 월드 시간을 기준으로 진행한다. 대상의 정지된 시간 배율에 의존하지 않는다.
- 여러 빙결이 동시에 있으면 마지막 빙결이 끝나기 전까지 복원하지 않는다.
- 자연 해제 시 이동 상태를 복원한 뒤 Expire 액션을 실행한다.
- 사망, 리셋 또는 맵 종료로 제거될 때는 해제 추가 피해를 발생시키지 않는다.

피격 후 다른 시스템이 이동 모드나 시간 배율을 변경할 수 있다. 복원은 이 시스템이 정지시킨 상태인지 확인하며 수행하고, 향후 별도 이동/군중 제어 시스템을 도입하면 소유권을 통합해야 한다.

## 예제 그래프

1. Fireball: Hit 피해 → End에서 FlameField 생성 → FlameField 반복 Hit 피해.
2. Blizzard: Pulse마다 상공에 IceShard 생성 → 낙하 적중의 실제 Frost 피해 누적 → 임계값에서 Freeze → 자연 Expire에서 Shatter 피해.
3. Mine: 준비 시간 → 적 감지 Trigger → 폭발 Area 생성.
4. Shockwave: 빈 중심을 유지하면서 띠 확장 → 대상별 1회 피해.
5. Meteor: 생성 시 상공에 낙하 투사체 생성 → 적/지형에 도달한 End에서 폭발 Area 생성.
6. DelayedHoming: 생성 후 직진 → 지연 호밍 → 중지 → 다른 설정으로 재적용.

6개 예제는 C++ 기본 설정과 편집 가능한 저장 에셋으로 제공한다. 지연 호밍 예제의 기본 속도는 350, 수명은 5초다. 현재 예제는 디버그 도형을 사용하며, 완성된 전투 연출로 보지 않는다.

## 제한과 절충점

- 최초 구현의 시전별 제한은 액션 2048회, 엔티티 생성 128개, 연계 깊이 32다. 호밍의 매 프레임 회전은 액션 횟수로 계산하지 않는다.
- 엔티티는 프레임당 주기 판정 최대 8회, 상태이상은 갱신당 주기 효과 최대 64회까지 따라잡는다. 그 이상 오래된 주기는 생략한다.
- 활성 엔티티는 Tick에서 자신의 시간 순서를 처리한다. 준비 완료, 지연 액션, 주기 시각 사이로 이동 구간을 나눈다. Area/Mine의 대상 검사는 매 프레임이 아니라 주기 시각에만 수행한다.
- 전투 대상은 컴포넌트 등록 집합에서 찾는다. 월드 전체 액터를 매번 수집하지 않지만 탐색 자체는 등록 대상 수에 비례한다.
- 호밍 탐색은 적용 시점과 목표 상실 후 재탐색 주기에 수행한다. 수천 대상 환경에 대한 성능 검증은 아직 하지 않았다.
- 오브젝트 풀과 공간 분할은 프로파일링 결과가 필요할 때 추가한다.
- 단순 선분 스윕으로 회전한 프레임의 경로를 판정한다. 매우 낮은 프레임에서 정밀한 곡선 이동이 필요하면 고정 이동 서브스텝을 후속 검토한다.
- 원래 시전자의 스냅샷 정책은 의도적이다. 지속 효과가 실시간 능력치 변화를 따라야 하는 요구가 생기면 데이터 정책을 추가한다.

## GAS 전환 전 검증한 동작

아래 항목의 실행 결과는 전환 전 기준이며, GAS 변경 이후에는 재실행이 필요하다.

- 레벨 경계값, 치명타, 방어, 체력 상한과 사망 1회 알림.
- 원본 시전자 능력치 변경/소멸 이후에도 자식 효과 스냅샷 유지.
- 투사체 → 장판, 누적 피해 → 빙결 → 해제 추가 피해.
- 관통, 지형 차단, 아군 무시, 지뢰 준비 시간, 도넛 중심 제외와 빠른 확장.
- 생성 1초 전 호밍 비활성, 이후 활성, 중지 시 직진, 재적용 시 설정/목표 정책 적용.
- 목표 사망/소멸 시 재탐색, 탐색 대상 없음, 진영 필터 유지.
- 종료/외부 파괴 후 예약 취소, 종료 시각과 예약 시각이 같은 경우, 같은 시각의 예약 순서.
- 상태이상 사망/리셋 해제에서 추가 피해가 발생하지 않음.
- 잘못된 에셋 입력과 순환 연계가 실행 제한을 우회하지 못함.
- 피격 콜백 중 리셋 또는 소멸한 대상에 오래된 사망 알림을 전달하지 않음.
- 자식의 피격 콜백이 원본 엔티티를 파괴하면 같은 생성 액션의 남은 자식도 생성하지 않음.
- 겹친 빙결의 마지막 상태가 끝날 때 외부에서 변경한 시간 배율과 이동 모드를 보존함.

에디터 화면에서의 키 입력과 VFX 품질, 패키지 쿠킹/배포 및 수천 대상 부하 측정은 자동화 테스트의 검증 범위와 구분한다. 게임 대상의 컴파일 성공을 배포 패키지 완성으로 간주하지 않는다.

기본 실행 검사에서 에디터용 Toolset 플러그인의 Python 시작 스크립트가 `-game` 모드에 없는 타입을 참조하는 기존 오류가 확인되어, 해당 검사 프로세스에만 `-DisablePython`을 적용했다. 프로젝트의 플러그인 설정은 변경하지 않았다.

# FluidFX 성능 실측·외부 나이아가라 구동 확인 (2026-10-18)

종류: 검증 증거 · 작성: 2026-10-18 claude · 결정: D-48

## 1. 결론

- **최적화 뒤(6절)**: 같은 조건 PIE 서브시스템 틱이 해상도 128 액터 4개 **1.24~1.35ms**(약 21배), 헤드리스 128 FluidSim 스텝 7.24 → 1.07~1.12ms. 결과는 변경 전과 비트 단위로 같다(해시 시험). 아래 1~5절은 최적화 전 기록이다.
- 해상도 128 유체 액터 4개가 모두 깨어 있으면 PIE 게임 스레드에서 서브시스템 틱이 **평균 26.5~28.8ms**(프레임 38.9~44.1ms, 약 23~26fps)다. 설계서 4절 예상(64~128 격자 0.1~0.25ms/프레임)보다 액터당 약 30배 무겁다.
- 원인은 솔버가 전부 게임 스레드 직렬이라는 점이다(설계는 `ParallelFor` 병렬 전제). 투영 2회 × Jacobi 8회 등 스텝당 전체 격자 약 32패스를 돌고, 셀 표본마다 경계 검사·인덱스 계산·범위 검사가 붙는다.
- 잠든 액터는 비용이 거의 0이다(0.0025ms). 실제 플레이에서는 거리로 깨우므로 보통 1개만 깨어 있다 — 그래도 해상도 128 FluidSim 1개는 약 6.6ms다.
- 외부 나이아가라: 태그 액터 구동과 프리셋 `ExternalNiagaraSystem` 스폰·구동이 동작한다. 프리셋 시스템은 그동안 불러오기만 하고 스폰되지 않던 죽은 설정이었고, 이번에 연결했다. 이 파라미터(`User.SimCenterWorld`·`User.SimExtentsCm`·`User.DensityPressureTexture`·`User.VelocityTexture`)를 읽는 나이아가라 VFX 에셋은 프로젝트에 아직 없다.

## 4. 외부 나이아가라 구동

- 헤드리스 시험(`TDGame.FluidFX.Niagara.*` 7개): 태그 액터의 나이아가라 컴포넌트(에셋 없음, 비활성)에 4개 User 파라미터가 매 스텝 들어가고(액터를 움직이면 Z가 따라감), 태그를 나중에 붙이면 약 1초 캐시 갱신 뒤 구동, 태그 액터 파괴에도 안전. 프리셋 `ExternalNiagaraSystem`(`NS_ArrowTrail_Water`)으로 소유 컴포넌트 1개 생성·액터 부착·구동, 시스템 교체·null이면 파괴. 구동 호출을 막는 변이에서 실패 확인.
- `-NullRHI`에서는 `UNiagaraFunctionLibrary::SpawnSystemAttached`가 null을 돌려주고(`FApp::CanEverRender` 거짓) 활성 상태도 볼 수 없어, 컴포넌트는 `NewObject`+`SetAsset`+부착+등록으로 만들고 활성 토글은 PIE에서 검증한다.
- PIE 검사(`pie_profile_fluid.py`의 나이아가라 단계): CombatPool에 `NS_ArrowTrail_Water` 프리셋을 넣자 소유 컴포넌트 정확히 1개 생성·활성 → `SetSimulationAwake(false)` 뒤 비활성 → 깨우면 다시 활성. 통과.

## 5. 최적화 권장 묶음 (분석·반박 거친 추정, 실측 아님)

목표: 해상도 128 액터 4개 PIE 게임 스레드 4ms 이하. 근거 `Saved/AgentOps/20261018/fluidfx/perf-review/`.

0. 기준선: 결과 바이트 해시 시험(여러 프리셋·비정사각·장애물·이동·경사 120스텝)과 패스별 `TRACE_CPUPROFILER_EVENT_SCOPE`로 실측 프로파일.
1. 투영 3패스(발산·Jacobi·기울기)부터 커널 정리 — 원시 포인터·지역 상수, 내부/테두리 분리, SDF가 바뀔 때만 고체 마스크 재계산, 연산 순서·double·나눗셈 유지로 결과 비트 동일. 예상 Water 128 7.7 → 약 2.8~3.7ms.
2. 액터 단위 병렬: 게임 스레드 앞단(전투 큐·겹침·스탬프) → 깨어 있는 액터를 `ParallelFor`로 스탬프·스텝·패킹 → 게임 스레드 뒷단(구동·지형 트레이스·풀). 예상 PIE 4개 26.5 → 약 3~3.8ms.
3. 여유: 이중선형 표본 융합, 테두리 페이드 1차원 표, 커널 정리를 와류·경계·경사로 확장. 예상 약 2.3~2.8ms.

제외: 고정 30Hz 스텝(지금 fps에서 이득 0, 스탬프 시험 위험), 투영 1회로 줄이기·RBGS+SOR(결과 변화로 시험 재조정), 해상도 낮추기(128 목표와 충돌), GPU 방식 B(이 목표에 과함, 헤드리스 수치 시험 근거 상실). 해상도 256 단일 액터는 이 묶음으로 약 8~12ms라 행 단위 `ParallelFor`가 따로 필요하다.

## 6. 최적화 결과 (2026-10-18, 5절 권장 묶음 0~3 적용)

### 6.1 바꾼 것

- 솔버 커널(`TDFluidGrid2DSolver.cpp`): 패스마다 원시 포인터·지역 상수, 고체 셀 마스크(`ObstacleSdf <= 0`)와 '그 행·위아래 행에 고체 없음' 행 표식을 SDF가 바뀔 때(초기화·래스터화)만 다시 만듦, 그런 행의 내부 셀은 이웃 대체 없이 직접 읽고 테두리·고체 근처만 원래 판정 경로. 투영은 발산·Jacobi·평균 압력·기울기 4함수로 나눔(평균은 double 직렬 합 유지). 테두리 페이드·감쇠는 1차원 표(최솟값 합성, 나눗셈·Clamp 단조성), 이중선형 표본은 좌표 계산 1회로 속도 2·밀도 3필드에 공유. 경사가 전부 +0.0이면 경사 가속, SDF 최솟값이 경계 띠(셀 1.5배)보다 크면 경계 처리를 건너뜀. 나눗셈·double 변환·연산 순서는 그대로.
- 액터 단위 병렬(`TDFluidLiveSubsystem.cpp`·`TDFluidLiveActor.cpp`·`TDFluidLiveComponent.cpp`): 게임 스레드 앞단 `BeginLiveActorStep`(전투 큐·겹침·근접·Shift·Rasterize·스탬프 정렬) → `ParallelFor(Unbalanced)`로 깨어 있는 액터의 `RunPreparedSolverStep`(브러시+스텝+패킹, UObject 없음) → 게임 스레드 뒷단 `FinishLiveActorStep`(구동·지형 큐·트레이스)과 수명 만료 풀 반환. 추적 이동(`SetActorLocation`)은 Shift 직후 앞단에서 해, 뒤에 도는 액터가 같은 프레임 위치를 보는 원래 순서 의미를 지킨다(다른 유체 액터를 따라가는 경우). 단계 사이에 파괴·풀 반환된 액터는 약한 포인터·풀 여부로 다시 걸러 건너뛴다. 솔버 스텝·브러시는 호출 스레드의 FTZ(비정규수를 0으로) 설정을 끄고 돌아 스레드와 무관하게 같은 비트를 낸다(엔진 병렬 애니 평가가 워커에서 FTZ를 켬). `AdvanceSimulationStep`·`StepLiveActor`는 세 단계를 차례로 부르는 그대로다. 콘솔 변수 `TD.FluidFX.ParallelActorSteps`(기본 1, 0이면 게임 스레드 직렬).
- 패스별 `TRACE_CPUPROFILER_EVENT_SCOPE(TDFluid_*)`, 벤치 경우 `TDFluidBench_Case`, 상태 체크섬 `FTDFluidGrid2DSolver::ComputeStateChecksum`(상태 배열 11개+경사+중심 CRC).

### 6.2 결과 동일성

- `TDGame.FluidFX.SolverRegression.GoldenStateChecksums`: Water(96, 1000×800, 장애물 4·슬라이딩·균일 경사)·Mud(64, 정사각, 고도 경사)·Fire(128, 1000×800, 장애물·슬라이딩·고도 경사)·Blood(48, 600×1000, 장애물, 페이드·와류·경사 0)·발자국(64, 장애물·슬라이딩) 120스텝(dt 1/60·1/30·1/45·0.15 순환, 고속 스탬프 포함) 뒤 상태·출력 픽셀 CRC. 기대값은 **변경 전 빌드**에서 얻었고(`Saved/AgentOps/20261018/fluidfx-perf-baseline-tests.log`) 최적화 빌드 2회 모두 5개 일치. 같은 시나리오 반복 실행 일치, 밀도·속도·고체 셀 존재도 단언.

- 해시 시험 안 불변식: 경사가 전부 +0.0이면 경사 중력 600과 0의 결과가 비트 동일(경사 패스 건너뛰기의 근거).
- 독립 정적 반박(td-refuter, `Saved/AgentOps/20261018/fluidfx/perf-opt/refute-static.md`): 솔버 비트 동일성·워커 데이터 경쟁은 반박되지 않음. 지적 5건(이름 TD 접두어, Begin/Finish 순서, 날 포인터, 시험 판별력, 워커 FTZ)은 위처럼 고침.
- 헤드리스 `TDGame.FluidFX.*` 68/68 통과(기존 65 + 위 3, 최종 `Saved/AgentOps/20261018/fluidfx-perf-opt3-tests.json`, 반박 수정 전 opt1·opt2는 67/67). `check_sync_loads.py`·`check_cook_coverage.py` 종료 0, FluidFX 위반 0.

- 병렬이라 4액터 틱(1.2~1.3ms)은 가장 긴 Water 액터 스텝(약 1.1ms)+앞뒤 단계에 가깝다. 다른 세션 빌드로 워커가 포화되면 게임 스레드가 직접 돌려 최악이 직렬(약 4ms) 수준이다(추정).

### 6.5 남은 것

- 해상도 256 액터 1개는 헤드리스 약 4.1ms라 여러 개를 동시에 쓰려면 행 단위 `ParallelFor`(결과 동일 가능, 평균 합만 직렬)나 방식 B가 필요하다.
- `ShiftOriginForSlidingWindow`는 이동마다 배열 9개를 새로 할당·복사하고, 장애물이 있으면 SDF 전체 재래스터화가 붙는다(이번 측정은 이동 없음, 미측정).
- 제외 유지: 고정 30Hz 스텝, 투영 1회·RBGS+SOR(결과 변화), 해상도 낮추기, GPU 방식 B.

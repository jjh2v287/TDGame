## 2. 지표 정의

- 팝 사건: 화면을 지형 높이 지도로 바닥 좌표(5cm 격자)에 펼쳐 연속 사진끼리 같은 땅(50cm 블록)을 견준다. 사진 i 에서 크게 바뀌고(차 ≥ T_pop), 다음 사진에서는 거의 그대로이며(≤ 0.5·T_pop), 앞뒤 사진끼리도 바뀐 채인(≥ 0.8·T_pop) 블록이 이웃끼리 2개 이상 붙은 덩어리 하나를 사건 하나로 센다. 비교 단위는 걷는 1분당 사건 수.
- 늦은 시간: 사건이 난 블록이 화면에 처음 보인 뒤 팝까지 걸린 초(중앙값·90분위).
- 응시 정착 시간: 도착(멈춤·순간이동) 뒤 마지막 사진과 견줘 1% 이상의 블록이 아직 다른 마지막 시각.
- 스트리밍: CSV 프로파일러 TextureStreaming(StreamingPool·WantedMips·CachedMips·PendingStreamInData·DesiredDataLoadedPercent), 대기 중 데이터가 0.5MB 를 넘는 시간 비율.
- 성능: FrameTime·GPUTime p50/p95/p99(걷기 구간), nvidia-smi 메모리 사용 최대.

## 3. 판정선 (측정 전 등록, 바꾸지 않는다)

- T_pop: 기준선 시운전 1회의 응시 잡음 바닥(마지막 두 사진 블록 차 95분위)의 2배와 0.06 중 큰 값으로 정하고, 정식 측정 전에 아래 5절에 시각과 함께 적는다. 정한 뒤에는 모든 실행에 같은 값을 쓴다.
- 기준선 = 같은 조건 2회의 평균, 실행 간 차이 = 두 회의 차.
- 원인 확정: 한 후보를 끄거나 바꾼 실행이 걷는 1분당 팝 사건을 기준선 평균보다 70% 이상 줄이고, 그 줄어든 양이 기준선 실행 간 차이의 3배보다 크며, 두 경로(`village_loop`·`teleport_spots`의 응시 정착 시간) 모두에서 같은 방향이면 그 후보를 원인으로 본다. 둘 이상이 각각 기준을 넘으면 함께 원인으로 적는다.
- 개선 판정(수정 뒤 같은 조건 2회 평균): 걷는 1분당 팝 사건 ≤ 기준선 평균의 30%, 순간이동 응시 정착 시간 중앙값 ≤ 기준선의 50% 또는 0.5초 이하, 늦은 시간 90분위가 줄어듦.
- 회귀 없음: 걷기 FrameTime p95 증가 ≤ max(5%, 1.5ms), GPUTime p95 증가 ≤ max(5%, 1.5ms), GPU 메모리 최대 ≤ 5,632MiB(6,144MiB − 512) 그리고 기준선 대비 증가 ≤ 1,024MiB, 100ms 넘는 프레임 수가 늘지 않음. 화질과 성능이 갈리면 화질을 우선한다는 사용자 답(`Docs/UserApprovalQueue.md` [1-1]·[2-1])에 따라, 메모리 기준을 넘는 수정은 넘는 양과 화질 이득을 함께 적어 결정 항목으로 남긴다.

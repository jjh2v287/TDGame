## ① 만든 파일과 구조 (모두 새 파일, `Tools/FluidFX/fog3d_ref/`)

| 파일 | 하는 일 |
|---|---|
| `fog3d_blend_patch.py` | 식 넷(B0·B1·B3·B4, 등록 2절 계산 꼴 그대로)과 섞기 함수 셋의 사본(`core.Sim`·`TerrainSim`·`TerrainSimR5` 의 `_apply_inputs`), 갈아 끼우기·되돌리기, 호출 수 세기. `python … fog3d_blend_patch.py check` 로 식 성질 점검 |
| `fog3d_blend_gates.py` | BL-1~5, 정보 1~7, 3절 T 사다리. `run --formula F --out-dir D --jobs N [--set all|bl|ladder|info|shake|smoke] [--bl-gains 1,3]` / `collect --out-dir D [--formula F]` |
| `fog3d_blend_regress.py` | 예전 판정선 다시 돌리기. `stage1 …` / `stage2a …` / `compare --out-dir D [--baseline-dir B]` |

갈아 끼우는 길:
- 사본 함수는 원본 본문을 그대로 옮기고 섞기 줄만 `blk + (G×목표 − blk) × k` 로 바꿨다. `W = band_weight(…) × strength` 의 곱 차례와 64비트 계산, `.astype(F32)` 저장, 깎기(erase) 코드는 원본과 같다. B0 은 k = W 를 같은 배열 그대로 돌려주고 G = 1.0 이므로 원본과 같은 연산이다(1.0 × 목표는 비트까지 같다). B0 에 1 이 아닌 배율이 오면 오류를 낸다.
- 2a 의 `_record_top_target` 에는 G×목표와 새 k 를 넘긴다(등록 2절).
- 배율 G 는 입력 구에 얹은 `wind_gain` 속성(없으면 1.0, 또는 그 경우의 기본 배율)으로 읽는다.
- 어느 식을 쓸지: 프로세스 전체는 `install(식)`(환경 변수 `TD_FOG3D_BLEND_FORMULA` 도 같이 정함), 계산 객체 하나만은 `sim.blend_formula = "B0"` 로 덮어쓴다(BL-5 의 'B0·몸 2.0' 견줌 실행과 T 기준 실행이 같은 실행 안에 있어야 해서).
- **병렬 작업 프로세스에 전하는 길**: 시작 파일(regress·gates) 맨 위에서 `blend_patch.install_from_environment()` 를 부른다. 윈도 spawn 은 작업 프로세스에서 시작 파일을 `__mp_main__` 로 다시 읽으므로, 부모가 정한 환경 변수의 식으로 작업 프로세스에서도 클래스 속성이 바뀐다. gates 는 경우마다 `install(case 의 식)` 을 다시 부르고 계산 객체에도 식을 적는다.
- 증거: 모든 조각에 '식 이름·호출 수(함수별)·pid·도구 파일 sha256' 을 남긴다. gates 는 조각 json 의 `calls`·`patch`, regress 는 `<폴더>/…/blend_calls/<조각>.json`(잠긴 도구가 쓰는 조각 파일은 건드리지 않으려고 따로 둠). 2a 는 `blend_calls.jsonl` 에 프로세스마다 첫 호출 줄도 남긴다(프로세스 끝의 'exit' 줄은 빠질 때가 있어 쓰지 않는다).

## ② 등록 문장을 읽은 방법 (둘로 읽힌 곳)

1. **BL-4 의 '직후'와 '목표'** — 저장된 바람(32비트)에서 64비트 G×목표를 뺀 값으로 읽었다(문장 그대로). 그런데 k = 1 인 면은 목표로 정확히 가지만 저장이 32비트라 `F32(목표) − 목표` 만큼 남고, 그 부호가 반대면 비가 −1e-8 쯤이 되어 '0 이상'을 기계적으로 어긴다. 연기 시험에서 B4·B1 칼 장면이 이렇게 26~36면 걸렸다(전부 32비트 간격 안 — 표의 '밖 면(그중 f32 간격 안)' 칸). B3 는 k < 1 이라 걸리지 않았다. 그래서 표에 두 읽기를 함께 둔다: '통과'(문장 그대로) / '목표 f32'(목표를 저장 형식으로 둔 비 — k ∈ [0,1] 이면 반올림 성질상 늘 [0,1]). **어느 쪽으로 판정할지는 감독이 정한다.** 지금 식(B0) 칼 s 2.5 는 두 읽기 모두 최소 −1.13 으로 떨어진다(가르는 힘은 같다).
2. **BL-4 의 '한 걸음'** — 서 있는 몸은 probe 의 `hand` 와 같은 걸음(서기 구간의 3/4 지점, 0부터 센 번호 moving + (전체 − moving)×3//4), 칼은 휘두르는 모든 걸음(12·6걸음)을 잰다(더 엄격한 쪽). 구가 여럿이면 구마다 따로 잰다(계산 사본에서 구 하나씩 적용, 본 실행은 그대로). 걷기 장면의 걷는 걸음과 사다리·정보 경우는 재지 않는다.
3. **BL-1** — 면 바람 최대 = `field_metrics` 의 `face_max`(창 안 모든 유체 면). (가) 마지막 round(0.5/dt)개 기록의 최대 ≤ 0.85 × 그 앞 같은 개수의 최대. (나) ≤ 0.15 × `records[:moving]` 의 최대.
4. **BL-2** — 0절·4절의 지금 식 값(0.446 등)이 probe 의 `alt_ring_max`(둘레 최대의 번갈아)와 맞으므로 **둘레 최대(ring_max)** 의 `alternation()` 으로 읽었다. 걷기 `[warm:moving]`, warm = round(10×(1/60)/dt), 칼 `[:moving]`. (면 최대의 번갈아는 쓰지 않는다.)
5. **BL-3** — `max(face_max[:moving]) ÷ (G × 속도)`, 속도는 걷기 520·칼 800 cm/s(probe 의 `face_max_over_speed` 와 같은 양). 지금 식 칼 2.5·60걸음에서 1.342952 로 probe 와 같은 값이 나왔다.
6. **BL-5** — `shake_run.py` 의 흔들기를 옮겨 적었다(`shake_debug` 는 Saved 아래 스크립트라 불러 쓰지 않고 같은 코드로 복사: ±1e-4cm, xyz, 씨앗 20261113, 구마다 a·b 차례로 rng.choice). 계산 객체도 그 스크립트와 같이 `TerrainSimR4`(F0 해석식, 128칸, TUNING_S2A, 정지 78). 초당 30걸음: 걷기 round(70×(1/60)/dt)=35걸음, 정지 39걸음, 74걸음째에 잰다. 견줌 'B0·몸 2.0·같은 dt' 는 같은 도구 실행 안의 다른 경우로 함께 돈다.
7. **T(3절)** — `gates_s2a.column(sim)` 과 '상태 0 인 같은 계산'의 차 = 걸음 0 의 column(창은 따라가지 않아 같은 창)과의 절대 차를 창 전체로 더함. 계산 객체는 probe 와 같은 `make_sim`(TUNING_S2A, 얼룩·잔 잡음 포함). 시각의 '연속 두 걸음' 은 (t−1, t)(1부터 센 걸음 번호)로 읽었다: 걷기 끝 = (69, 70), 칼 끝 = 휘두름의 마지막 두 걸음, 멈춘 뒤 x초 = t = moving + round(x/dt). '마지막 선 자리' 가운데는 걷기 = 걸은 끝 자리(−300 + 520×dt×moving, 0), 칼 = 칼 길의 끝점(−40, 0).
8. **사다리 고르기** — 같은 |log| 이면 작은 G, (최대−최소)÷평균 < 5% 면 1.0, 모든 T 가 지금 식보다 작으면 `all_below_B0` 로 표시(가장 가까운 값은 그대로 고름). '규칙대로 고른 G' 는 기계적 계산 열이다.
9. **정보 항목** — 1: 정본 몸 3.0·G 1 걷기, B0·B1·후보, 60·30. '반으로 줄어드는 시간' = 멈출 때(걷기 마지막 기록)의 면 최대의 절반 이하가 처음 되는 때까지. 2: 정본·s 1.0, 60걸음, G 1, 걷기·칼 모두, 3절 시각들의 밀려남(dx·dy·dz)·채움(g) 장 차이 비(probe 의 `group_ratio`). 5: +x 35걸음 뒤 +y 35걸음(서기 없음, 걷는 70걸음 전체가 '움직이는 동안'). 6: 2a 의 `R5_WALK_S30_up`·`R5_G4_CLIFF_a` 장면을 덧붙임 2 의 조각 함수 그대로, 그 경우의 모든 구(몸과 칼)에 G = 3.0. 7: dt 1/144 걷기(168걸음 + 서기 480걸음).
10. **6절 1단계 목록** — 지시대로 `stage1d/jobs.txt` 의 N2 필수 조각 20개(걷기 5방향·v2·g12·t·v3·k4hash 두 번·g14·g15·leak·g16 다섯)를 '필수'로 둔다. 6절 (가)·(나)·(다)에 있는 D-G2·G4·G5·G6·G7·G8·G9·G10·G11·G13·D-V1 은 **N2+S9 최종 구성의 기록이 없다**(r2·r3 기록은 A1·A3·S4 등 옛 구성). 그래서 `--set extra` 로 따로 돌릴 수 있게 했고, 기록 대신 같은 틀에 B0 를 끼운 실행(`--baseline-dir`)과 견준다. 도구 자체의 통과(조각의 `passed`)도 함께 적는다.
11. **D-S1·S2(다)** — 걷기 네 방향 조각에서 기계적으로 계산: D-S1 각 치우침 ≤ 0.03, D-S2 네 크기의 (평균 대비 최대 벗어남) ≤ 5% 이고 넷 모두 치우침 ≤ 0.03(k7-design 표와 같은 꼴).
12. **2a 묶음** — 조각 이름의 판정선으로 가른다: (가) G9 전부와 G6 의 `_k1_60`(캡슐 ㄱ, 1/60) / (나) G2·G3·G8. 걷기 조각(G5·G7·정보)은 이름에 판정선이 없어 '다·라·정보'로 센다. (다)·(라)는 새 `results.json` 의 판정선 통과와 값을 기록과 나란히 적는다.

1. **BL-1~5·정보 1~7·T 사다리(후보 B4)** — `$env:PYTHONUTF8=1; python -B Tools/FluidFX/fog3d_ref/fog3d_blend_gates.py run --formula B4 --out-dir Saved/AgentOps/20261116/fog3d/blend/official_b4 --jobs 6`

   - 2절 갈래(G 3.0 에서만 떨어짐)로 위 끝을 줄일 때: 같은 폴더에 `run --formula B4 --set bl --bl-gains 2.5`(그다음 2.0 …) 뒤 collect. 3.5(강)도 `--bl-gains 3.5`.
   - B3 로 넘어갈 때: 같은 폴더에 `--formula B3`(B0·B1 짝은 이미 있어 건너뜀).
2. **예전 판정선 1단계** — `python -B Tools/FluidFX/fog3d_ref/fog3d_blend_regress.py stage1 --formula B4 --out-dir Saved/AgentOps/20261116/fog3d/blend/regress_b4 --jobs 6`

   - 이어 하기: 끝난 조각(출력 json 있음)은 건너뛴다. 중간에 끊긴 조각은 처음부터(잠긴 도구의 체크포인트는 하위 장면 경계에서만 남는다).
3. **예전 판정선 2a(R5 와 견줌용 R3·R4·평지)** — `python -B Tools/FluidFX/fog3d_ref/fog3d_blend_regress.py stage2a --formula B4 --out-dir Saved/AgentOps/20261116/fog3d/blend/regress_b4 --jobs 6`
   - 덧붙임 2 의 `run`(조각 130개: R5 91·R3 13·R4 13·평지 13) 뒤 `collect` 를 같은 폴더(`regress_b4/stage2a/`)에서 부른다. 기록은 병렬 8·빌드와 겹쳐 192분·CPU 1527분. 오늘 걷기 조각이 약 1.7배 빨라 예상 벽시계 약 2.5~3.5시간(가장 긴 조각 G6 S60 1/144·G9 고정 창 약 45~70분).
   - 이어 하기: 같은 명령 다시(덧붙임 2 실행기가 있는 조각을 건너뜀).
   - 끝난 뒤: 위 2 의 `compare` 한 번이 1단계와 2a 를 함께 견준다(`regress_b4/compare.md` 의 '2a (stage2a)' 절).

동시 실행: 셋을 함께 띄우면 프로세스가 18개가 되므로, 다른 세션 빌드를 생각해 한 번에 하나(또는 합 6 이하가 되게 `--jobs` 를 나눔)를 권한다.

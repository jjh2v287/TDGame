## 2. 물체 옆(S1) [실측: obstacles.json]

옆 카메라에서 물체 면 20~120cm 띠의 휘두른 뒤 2.5초 장과 기준 장(계산 끔)의 8비트 밝기 차이 평균. 열 실행 모두 유효(장 63·73 전부, 이벤트 5/5, 제출 거부 0, 3D 안개 경고·오류 0).

| 물체 | 가까운 쪽 평균 | 먼 쪽 평균 | 먼 ÷ 가까운 | 휘두르기 없는 조절 실행(가까운/먼) |
|---|---|---|---|---|
| 낮은 상자 | 10.13 | 3.57 | 0.35 | 3.19 / 0.32 |
| 높은 상자 | 5.19 | 8.74 | 1.69 | 2.58 / 0.29 |
| 얇은 벽 | 9.06 | 10.27 | 1.13 | 0.68 / 0.37 |

- 잡음 0.3~0.6. 가까운 쪽 띠는 폰이 안에 서 있어 띠 화소의 약 60% 가 폰 몸으로 빠졌다.
- 높은 상자와 벽도 먼 쪽 값이 가까운 쪽 이상이다. 휘두르기 없는 조절 실행의 먼 쪽은 0.3~0.4 라 이 값은 휘두르기 탓이다.
- 낮은 상자 휘두르기 뒤, 휘두른 자리에서 약 800cm 떨어진 높은 상자 아래쪽 칸 차이 평균 18.0(휘두르기 없는 조절 실행 같은 칸 0.27).

## 4. 비용(S2, 정보) [실측: cost.md]

에디터 안 PIE, 화면 1612×715, RTX 2060, 클럭 고정, `t.MaxFPS 60`. 숫자는 GPU 프레임 시간 중앙값(ms), 두 번 중 첫 번째/두 번째, 프레임 300 이상. 두 번 중앙값의 차이는 0.03~0.21 ms.

| 조건 | 서 있음 | 걷기·휘두르기 되풀이 |
|---|---|---|
| 구역 숨김 | 10.30 / 10.40 | 10.39 / 10.45 |
| 계산 끔(그리기만) | 10.21 / 10.23 | 10.64 / 10.60 |
| 낮음 | 10.72 / 10.60 | 10.80 / 10.69 |
| 보통 | 11.34 / 11.15 | 11.26 / 11.10 |

- 3D 안개 계산 범위(계산이 도는 프레임만, 중앙값): 낮음 0.29, 보통 0.99, 높음 1.00 ms. 낮음·보통은 한 프레임 걸러 돈다.
- 엔진 볼륨 안개 패스: 구역 숨김 0.56 ms, 구역 켬 0.67~0.69 ms.
- 계획의 3단계 목표(걷기만 0.3, 보통 싸움 0.8, 최악 1.5 ms)와 나란히 `cost.md` 에 적었고, 이 글은 판정하지 않는다. 싸움 장면은 이 무대에 없어 안 쟀다.

## 5. 2D 안개와 나란히(S3)

촬영 조건 [실측: Saved/FluidFX/fog3d_calib/F2D_sw·F2D_wk, 3D 쪽은 앞 작업의 기준 실행 c_px]:

- 같은 시각표: 앞(+X)을 보고, 뒤 카메라 팔 400cm·내려봄 12도, 휘두르기 0~6.0초 61장 + 걷기 0~7.0초 71장(걷기 600cm), 0.1초 간격. 유효 점검: 장 63/63·73/73, 늦음 최대 0.017초, 이벤트 1/1, 3D 안개 경고 0.
- 2D 쪽은 `LV_TDFluidFogStage` 구역 10(지형을 따라가는 타일 안개 FogTileSim, 정본 켬)의 평지 띠에서 폰 시작 (10600, 71000). 휘두르기와 걷기는 각각 새 PIE 로 따로 찍었고, 시작 5초 전에 안개 상태를 다시 초기화하고 폰을 옮겨 놓은 뒤 기다렸다(장 3.0·4.9초는 시작 전 확인용). 3D 쪽은 한 실행에서 휘두르기 6.3초에 안개 계산을 껐다 6.6초에 다시 켠 뒤 7.3초에 걷기를 시작한다 [확인: c_px run.json 이벤트]. 그래서 걷기 시작 때 안개 상태가 2D 와 완전히 같다고는 못 한다 [추정].
- 걷는 길의 기복: 없음. 폰 높이가 시작 98.15cm, 걷기 끝(x=11223) 98.15cm 로 같다 [실측]. 평지 띠 범위 안(X 7500~13500, Y 70300~71500) [확인: editor_make_fluid_fog_stage.py RELIEF_TILE_FLAT_BAND_BOUNDS]이고 가까운 언덕 둘의 중심은 길에서 y로 1600cm 옆(밑지름 1000cm)이다 [확인: RELIEF_TILE_HILL_SPECS].
- 폰은 두 무대 모두 +X 를 본다(휘두르기 뒤 시작 자리가 36cm 앞으로 밀리는 것도 같다).

## 6. 찾은 흠 목록 (S1·S2·S3 에서 눈으로 본 것과 숫자로 확인한 것, 판정 아님)

1. 상자·벽 옆 안개 띠: 높은 상자 옆 걷기(걷기 시작 뒤 1.9~2.5초)에서 폰 뒤 흐림이 상자 아래 옆면에 닿아 허리가 잘록한 밝은 띠로 남음. 벽 아래에 가는 띠. 벽 휘두르기(1.3초 이후)에서 벽 먼 쪽 아래에 밝은 덩어리. 높은 상자 휘두르기(2.4초 이후)에서 상자 오른쪽 아래 삼각 덩어리(상자 그림자 가장자리와 겹침). 실행 이름: HIGH_wk_s, WALL_sw_s·b, HIGH_sw_s.
2. 먼 곳의 쐐기: 낮은 상자 휘두르기(LOW_sw_b) 0.8초 이후 약 800cm 떨어진 높은 상자 아래쪽에 밝은 쐐기. 숫자 18.0 대 0.27, 원인 모름.
3. 높은 상자와 벽이 안개를 막지 않는 것으로 보임: 먼 ÷ 가까운 = 1.69·1.13 (낮은 상자 0.35). 칼 입력 구가 벽 너머에 닿는 문제와 함께 2단계 항목일 수 있음 [추정].
4. 창 가장자리 숫자: 여섯 모두 표시용 문턱 1.0 보다 큼. 대조선도 같은 크기라 숫자만으로 보임·안 보임을 못 가름. 눈으로는 곧은 경계·밝기 계단 없음(±Y 1:1 확대는 안 봄).
5. 비용: GPU 프레임 시간 차이에는 계산 범위 환산값보다 0.3~0.5 ms 더 얹혀 있고 원인 모름. 3D 안개 계산 열이 CSV 에 없어 프레임 하나씩 뽑은 표(6~8개)로만 가름. 보통·최악 싸움 장면은 안 쟀음. 높음 비용 1회는 시운전이라 조건 순서 영향이 있을 수 있음.
6. 낮음 품질의 휘두르기 자국이 보통·높음보다 약간 거칠고 작음(눈으로).
7. 2D 와 나란히: 같은 휘두르기·걷기 자국이 2D 구역 10 에서는 이 빛(역광)·노출에서 눈으로 거의 안 보임. 차이 8배 그림에서도 몸·그림자·언덕 윤곽만 남고 안개 자국은 눈에 띄지 않음. 3D 는 휘두르기 자국이 폰 왼쪽 앞의 큰 어두운 타원으로, 걷기 자국은 폰 둘레의 흐림으로 또렷함. 다른 2D 구역(7A·9·6)도 휘두르기 시운전에서 자국이 약했고, 구역 6(연기 대리)만 폰 가까이 밝은 조각이 보였다(시운전 장 4개씩, 이 폴더에는 넣지 않음). 2D 쪽 안개 자체가 약한 것인지 이 빛에서 안 보이는 것인지는 가르지 못함 [추정].
8. 안 찍은 것: 내려찍기와 높이가 다른 베기는 공격 동작이 하나뿐이라 못 찍음. 움직이는 그림 재생과 깜빡임은 사람 눈으로는 못 봄(깜빡임은 수치로: 띠 안 평균 밝기 2차 차이 3초 이후 평균 0.008~0.031, 최대 0.066).
9. 환경 주의: 비용 측정 뒤 콘솔 값을 엔진 기본값으로 되돌렸는데 원래 값을 미리 읽지 않아 이전 값과 다를 수 있음(특히 `r.DynamicRes.OperationMode`).

## 독립 확인이 바로잡은 점과 흠 목록 (2026-11-14, 감독이 덧붙임)

- 창 가장자리 밝기 차 숫자는 화소를 고르는 법에 따라 달라지고(높음 500·1000 은 같은 값이 다시 나오지 않음) 창 안쪽 대조선과 같은 크기다. 판정에 쓰지 않는다. 눈으로는 곧은 경계가 없다(±Y 가장자리 1:1 확대 포함).
- 비용의 "곱셈 값보다 더 얹히는 몫"은 서 있을 때만 0.26~0.33 ms 이고 되풀이에서는 없다(`cost.md` 를 고쳤다).
- 물체 옆의 "먼 쪽 ÷ 가까운 쪽"은 카메라 길에 따라 달라진다(같은 낮은 상자가 옆 카메라 0.37, 뒤 카메라 1.09). 얇은 벽은 벽 뒤 안개가 실제로 바뀐 것이 받쳐지고(벽 뒤 10.39 대 옆 3.66), 높은 상자는 이 숫자로 막힘 여부를 가를 수 없다.
- 흠 목록과 근거는 `Saved/AgentOps/20261114/fog3d/stage1w/v16-check.md`, 판정과 옮겨 적은 할 일은 `Docs/VolumeFog3D/progress.md` 의 '1단계 마무리 결과와 판정'.

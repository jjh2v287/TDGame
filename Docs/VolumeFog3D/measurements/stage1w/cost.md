## 읽는 법과 한계

- 3D 안개 계산 패스는 CSV 의 GPU 통계 열로는 가를 수 없다(계산 패스가 GPU 통계 이름을 따로 갖지 않음 [확인: Source/TDFluidGpu/Private/TDFluidGpuFog3D.cpp:627 에 RDG_EVENT_SCOPE 뿐, DECLARE_GPU_STAT 없음]). 그래서 ProfileGPU 표(프레임 하나)에서 "TDFluidGpuFog3D 128/256" 범위의 포함 시간을 읽었다. 이 범위 안 패스 이름(Advect·PressureColumn·Divergence·Gradient 등)의 합은 범위 합과 같았다(표 위 "패스 이름 합").
- 초당 30회 조건(낮음·보통)은 한 프레임 걸러 계산이 돈다. 표 시각이 60프레임 간격과 겹쳐 처음 실행(r1·r2)의 표는 계산이 안 도는 프레임만 잡은 경우가 있었다(표에 "-"). 그래서 표 시각을 한 프레임 엇갈린 보강 실행(r3, 낮음·보통)을 더 돌렸다. 보강 실행 값은 같은 표 위 "보강 실행" 칸에 있다.
- 계산이 도는 프레임 하나의 비용(ProfileGPU, 중앙값): 낮음 0.29 ms, 보통 0.99 ms, 높음 1.00 ms. 높음의 패스별(중앙값): Advect 0.43, PressureColumn 0.45, Gradient 0.08, Divergence 0.05 ms. 짝수·홀수 프레임 차이(CSV)도 같은 크기다(보통 약 0.96 ms, 낮음 약 0.14~0.27 ms).
- 프레임당 평균으로 환산하면(60프레임 기준, 계산이 도는 프레임 비용 × 초당 횟수 ÷ 60) 낮음 약 0.15, 보통 약 0.50, 높음 약 1.00 ms [추정: 곱셈]. 전체 GPU 프레임 시간 평균 차이(조건 − 계산 끔)는 서 있음 0.41/0.82/1.33, 되풀이 0.14/0.41/0.84 ms 로 같은 순서다. 다만 서 있을 때는 그 차이에 이 곱셈 값보다 약 0.26~0.33 ms 가 더 얹혀 있고(예: 서 있음 보통 0.82 대 0.50) 원인은 가르지 못했다. 걷기·휘두르기 되풀이에서는 남는 것이 없다(0 또는 음수) — 독립 확인(2026-11-14)이 앞 문장 "0.3~0.5 ms 더"를 이렇게 바로잡았다. 조건 사이 실행 순서·흔들림이 크기가 이 정도(숨김−계산 끔이 −0.21~+0.16 ms)라 이보다 작은 차이는 믿지 않는다.
- 그리기: 엔진 볼륨 안개 패스(CSV `GPU/VolumetricFog`)가 구역 숨김 0.56 ms, 구역을 켜면(계산 끔 포함) 0.67~0.69 ms 로 약 +0.11 ms 늘었다. 계산 끔과 높음 사이 엔진 볼륨 안개 값은 거의 같다(0.67~0.69). 3D 안개 구역은 엔진 볼륨 안개의 복셀화 단계에서 그려지는 것으로 보인다 [추정].
- 최악 조건(안개 칸 전부 깨어 있는 장면, 여러 상호작용 입력이 겹치는 싸움)은 이번 무대에 없어 재지 않았다. "보통 싸움"·"최악" 칸은 비어 있다. 되풀이 구간(휘두르기 1.85초 + 500cm 걷기 두 번)은 폰 하나가 입력 구를 몇 개 넣는 정도다.
- 측정 환경: 에디터 안 PIE(에디터 화면 그리기·게임 스레드 일 포함), 1612×715, RTX 2060, 클럭 1935 MHz 로 고정, `t.MaxFPS 60`. 게임 빌드 값은 다를 수 있다. 실행 순서: 높음 1회(맨 처음 시운전 실행) → 숨김 → 계산 끔 → 낮음 → 보통 → (2회차 반대 순서) 높음 → 보통 → 낮음 → 계산 끔 → 숨김. 낮음·보통 보강(r3)은 맨 끝.
- 두 번 잰 차이: 중앙값 기준 0.03~0.21 ms(표의 "두 번 중앙값 차이"). 구역 숨김은 계산·그리기 모두 없는 조건이라 3D 안개 값이 없다.
- 시험 환경 복구: 측정 뒤 콘솔 값을 TD.Fog3D.Quality·Mode -1, t.MaxFPS 0, r.VSync 0, r.GPUCsvStatsEnabled 0, r.DynamicRes.OperationMode 1, r.ProfileGPU.ShowUI 1 로 되돌렸다(원래 값을 미리 읽지는 않아 엔진 기본값으로 되돌린 것).

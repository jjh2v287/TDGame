## 0. 원칙

1. 1a 가 판정하는 것은 "GPU 구현이 기준 모의(파이썬 참조 계산)와 같은 계산을 하는가"이다. 설계가 좋은지는 설계 판정선이 기준 모의로 이미 판정했다.
2. 설계 판정선의 GPU 값은 따로 재지 않는다. 장면 가~아의 장 차이가 0.2% 안이면 설계 지표도 그만큼 안에 있다. 다만 장면 나(낮게 휘두르기)의 대조가 통과해도 감독은 1b 를 시작하기 전에 높이 구분 장면의 GPU 덤프를 한 번 본다(여유 5%).
3. 구조상 늘 맞을 수밖에 없는 확인은 "자명한 확인"으로 따로 적고 통과 근거로 세지 않는다.
4. 사용자 지시(2026-10-25)대로 칸마다 빌드·회귀·결정론·오프스크린만 본다. 시간은 정보다.

## 1. 공통

- 시험 이름 `TDGame.FluidFXRhi.Fog3D.*`. 실행 `python Tools/build_and_test.py --filter FluidFXRhi.Fog3D --label fog3d --rhi offscreen`.
- 장면은 재생 파일을 C++ 시험이 그대로 재생한다. 입력 위치는 "위치 + (기준 칸 − 창 최소 칸) × 칸 크기"를 64비트로 계산해 32비트로 넘긴다. 처음 계산과 다시 시작한 계산의 구도 파일에 쓰인 그대로 쓴다.
- 판정은 두 갈래다. (가) C++ 자동화 시험이 직접 판정: A1, A2, A4, A6, A7, A14. (나) C++ 시험이 덤프(`Saved/FluidFX/Fog3D/gpu/`)를 쓰고 대조 도구 `python Tools/FluidFX/fog3d_ref/fog3d_compare.py --extras` 가 판정: A3, A5, A8~A13, A15(와 A4·A7 의 다시 확인).
- 같음 판정(A2·A4)은 "정규화한 상태"의 바이트 비교다: 바람 u·v·w, 밀린 거리 3성분, 채움의 32비트 값을 창 순서(지역 x 가 가장 바깥, 높이가 가장 안쪽)로 늘어놓고, 막힌 칸은 0, −0 은 +0 으로 바꾼다.
- "값이 0" = +0 또는 −0. 대조는 유체 칸만 본다.
- 장 차이 = (두 장의 차)의 제곱합 제곱근 ÷ (기준 장)의 제곱합 제곱근. 따로 적지 않으면 창 가장자리 띠 8칸은 뺀다. 바람·밀린 거리·채움을 따로 잰다.
- 대조 허용값 X = max(0.2%, 민감도 × 3). 민감도(입력 위치를 1e-4cm 흔든 기준 모의와의 장 차이)는 모든 장면에서 5e-6 이하라 **X 는 모든 장면에서 0.2%** 다.
- "차이값" = max(0, 1 + g) × B(칸 가운데 − d 의 높이) − B(칸 가운데의 높이).

# 1d 뒤 — 남은 좌우 치우침의 원인 찾기(창 이음매 가설)와 고치기 (등록본)

등록: 2026-11-14 claude(감독·결정). 정확한 시각은 이 파일의 수정 시각이다. 진단 촬영(`prereg-1d-diag.md` 251081e9763cff47)의 결과를 본 뒤, 다음 촬영 전에 썼다. 판정선 숫자(세기 ±15%, 치우침 차 0.10, 치우침 크기 0.15)는 그대로다.

## 0. 진단 결과 (규칙 1 불만족, 값 맞추기 안 함)

- 세기: 얼룩을 끄자 세 방향의 걷기 자국이 6.50 / 6.19 / 5.77(평균 ±6%)로 고르다. 세기의 방향 차는 얼룩(자리 차) 때문이었다.
- 치우침: 얼룩을 꺼도 +0.152 / −0.382 / −0.111(차 0.534)로 남는다. 같은 조건을 다시 찍은 차이는 0.002 라 잡음이 아니다.
- 무늬 씨앗만 바꾼 +X 의 값은 8.19 / 6.43 / 7.10(퍼짐 24%, 정한 30% 에 못 미침).
- 사용자가 본 "중" 구성을 새 방식으로 찍으면 걷기 7.30(옛 10.63, −31%), 휘두르기 10.35(옛 26.0, −60%), 치우침 +0.141(옛 +0.41).
- 바로잡음: `prereg-1d-diag.md` 1절에 "세계의 +Y 쪽이 세다"고 쓴 것은 부호가 틀렸다. +X 로 걸을 때 화면 왼쪽은 세계 −Y 다. 두 X 걷기 모두 세계 −Y 쪽이 세다.

## 1. 읽기와 가설

치우침을 "폰과 함께 도는 몫 p"와 "세계에 고정된 몫 w"로 나눈다(+X 값 = p + w, −X 값 = p − w). 얼룩 끈 값으로 p = −0.115, w = 0.267 이다. +Y 걷기의 −0.111 은 p 와 같다(세계 몫 0). p 는 기준 모의가 미리 낸 값(−0.107, 오른손과 칼 쪽)과 같다. 곧 남은 문제는 **X 방향으로 걸을 때만 세계 −Y 쪽으로 쏠리는 w = 0.27** 이고, 화면에서 띠의 가운데가 약 10cm(반 칸~한 칸) 옮겨진 크기다.

- 가설 "이음매": 3D 안개 격자는 창이 플레이어를 따라가도 내용을 옮기지 않으려고 칸 번호를 창 크기로 나눈 나머지 자리에 저장한다(돌려 쓰는 저장). 그래서 세계 좌표가 창 크기(256칸 × 15.625cm = 4000cm)의 배수인 선마다 저장 자리가 끝에서 처음으로 넘어가는 이음매가 있다. 시험 무대의 시작점은 y = 0 이라 지금까지의 모든 X 방향 걷기는 정확히 y = 0 이음매 위를 걸었고, +Y 걷기(x = −964 선) 옆에는 이음매가 없다. 이음매를 건너는 읽기(계산이든 그리기든) 어딘가가 틀렸다면 지금 본 모양이 나온다. 기준 장면 대조(E1~E3)는 이음매가 내용 한가운데에 놓이는 경우를 다루지 않았을 수 있다.
- 가설 "칸 경계": 걷는 선이 칸 경계에 정확히 놓일 때의 가름 처리.
- 가설 "y = 0 선": 무대·구역의 가운데 선에 놓인 무엇.
- 가설 "축": Y 축 전체의 어긋남.

## 2. 가르는 촬영

모두 얼룩 끔, 프리셋 값, 뒤 카메라를 걷는 방향에 맞춤, 해를 걷는 방향과 함께 돌림(방향 100 + 걷는 방향, 높이 35도). 걷는 선만 바꾼다. 쌍마다 w = (정방향 치우침 − 역방향 치우침) ÷ 2.

| 쌍 | 걷는 선 | 격자 | 이음매 위인가 | 칸 경계 위인가 |
|---|---|---|---|---|
| P0(이미 찍음) | y = 0 선을 ±X 로 | 256칸 | 예 | 예 |
| P1 | y = 500 선을 ±X 로 | 256칸 | 아니오 | 예 |
| P2 | y = 507.8 선을 ±X 로 | 256칸 | 아니오 | 아니오(칸 가운데) |
| P3 | x = −2000 선을 ±Y 로 | 128칸(품질 0, 창 2000cm) | 예 | 예 |
| P4 | x = −2000 선을 ±Y 로 | 256칸 | 아니오 | 예 |

P0 의 w 는 0.267 이다. 걷는 선의 실제 자리는 목표에서 ±3cm 안이어야 한다(벗어나면 그 쌍은 무효).

## 3. 판정 규칙

- "이음매": |w(P1)| ≤ 0.07, |w(P2)| ≤ 0.07, |w(P3)| ≥ 0.15, |w(P4)| ≤ 0.07.
- "칸 경계": |w(P1)| ≥ 0.15 이고 |w(P2)| ≤ 0.07.
- "축": |w(P1)| ≥ 0.15 이고 |w(P2)| ≥ 0.15.
- "y = 0 선": |w(P1)|, |w(P2)|, |w(P3)| 가 모두 ≤ 0.07.
- 그 밖은 "가르지 못함".

## 4. 고치기 (미리 정한 범위)

"이음매"나 "칸 경계"로 판정되면 그것은 "같은 내용을 창과 함께 옮겨 놓아도 결과가 같아야 한다"는 성질이 깨진 것이다. 이 성질은 명세의 수식이 뜻하는 바이므로 수식을 바꾸지 않고 구현을 고친다.

1. 코드에서 어긋난 곳을 찾는다(계산 셰이더, 게임 쪽 입력 묶기와 창 값, 그리는 식과 재질의 견본기).
2. 먼저 실패하는 시험을 만든다: 같은 장면을 창과 입력을 함께 창의 반(두 축 모두)만큼 옮겨 다시 돌려, 창 기준으로 본 결과가 원래와 같은지(장 차이 ≤ 0.01%) 본다. 결함이 있는 층(계산 모듈, 그리는 농도 탐침, 게임 층)에 만든다. 고치기 전에 실패해야 한다.
3. 가장 작게 고친다. 새 시험이 통과하고, 기존 통과 기준(`prereg-1d.md` 의 E1~E6: 장면 대조, 자동화 시험, 회귀, 셰이더 검사, 쿠킹)이 그대로 통과해야 한다.
4. 그리는 식의 정본 파일을 고쳐야 하면 고치고 잠금 기록(지문)을 새로 남긴다. 파이썬 기준 도구가 같은 결함을 가졌으면 잠긴 파일은 두고 새 파일로 고친 판을 만든다. 수식 자체를 바꿔야 하거나 원인이 "이음매·칸 경계"가 아니면 고치지 않고 멈춘다.
5. 독립 반박: 고친 곳을 되돌리면 새 시험이 실패하는지, 시험이 실제로 이음매를 내용 한가운데에 놓는지, 128칸·256칸과 음수 좌표에서도 성립하는지.

## 5. 화면 확인 (고친 뒤)

처음 조건으로 돌아가 y = 0 선에서 얼룩 끄고 세 방향(+X·−X·+Y)을 찍는다: Wk(12.1) 가 평균 ±15% 안, 치우침이 서로 0.10 안, 방향마다 치우침 크기 ≤ 0.15. 그리고 P3 를 다시 찍어 |w| ≤ 0.07. 만족하면 `prereg-1d-diag.md` 4절(값 맞추기)로 넘어가되, 기준 조건의 "지금 값"은 고친 뒤 다시 찍은 값으로 시작한다.

## 6. 남는 위험

조건을 네 번째로 손대는 것이다. 다만 이번에는 재는 조건을 바꾸는 것이 아니라 결함을 찾아 고치는 일이고, 고친 뒤의 확인은 처음 조건(y = 0 선의 세 방향, 같은 판정선)으로 한다. 가설이 틀리면 3절의 다른 가지로 멈춘다.

# 1d 바람 옮기기 방식 교체 — 설계 판정과 구현 통과 기준 (등록본)

등록: 2026-11-14 claude(감독·결정). 정확한 시각은 이 파일의 수정 시각이다. 새 방식의 GPU 코드를 한 줄도 돌려 보기 전에 썼다. 잠근 뒤에는 고치지 않는다.

## 0. 설계 판정 (등록본 `prereg-1d-design.md` 7d5ab8a1658b125e 에 따른 결과)

- 규칙대로 N2(밀린 거리·채움은 칸 가운데의 평균 바람으로, 바람 세 성분은 면마다 따로 거슬러 올라감)를 고른다. 좌우 치우침 0.2046 → 0.00003, 네 방향 세기 차 ±13.1% → ±0.00%, 기존 설계 판정선 전부 통과. N1 은 탈락(0.1849, ±7.7%).
- 독립 반박(따로 짠 구현)이 같은 값을 냈다(7장면 장 차이 0). 바람이 스스로 옮겨지는 막힌 벽 12장면에서 반대편은 정확히 0, 끝이 열린 벽에서 넘어가는 비율은 지금 방식 0.66~0.70 → N2 0.54~0.55.
- 내 등록 실수: 판정선 D-S3(45도 걷기)은 격자 대칭 때문에 어떤 방식에서도 0 이 나와 아무것도 가르지 못했다. 반박이 대신 잰 비스듬한 방향의 치우침은 11.25도 0.052, 22.5도 0.044 다(지금 방식 0.198, 0.099). 곧 N2 로 크게 줄지만 비스듬한 방향에 약 5% 가 남는다. 대각으로 걸을 때의 자국은 네 방향보다 약 35% 약하다. 이 둘은 한계로 받아들이고 기록한다(더 줄이려면 옮기기의 보간 차수를 올려야 하고 이번 범위가 아니다).
- 구현 계약 검토에서 나온 꼭 고칠 것 다섯(열린 윗면의 w 면 식, 면 축 이동 상한 미기재, 면 이어짐 규칙이 결과를 바꾸지 않아 시험할 수 없음, 명세 덧붙임 누락, 기준 숫자의 지문)은 구현 전에 계약 확정 작업에서 닫는다. 면 이어짐 규칙은 "어떤 경우에도 결과를 바꾸지 않음을 증명하면 뺀다. 증명하지 못하면 남기고, 결과를 바꾸는 장면을 찾아 검증 장면에 넣는다"로 정한다.

## 1. 기준 자료를 잠그는 법

새 방식의 기준 덤프·기준 숫자·새 장면은 계약 확정 작업자가 만든다. 그 작업자는 GPU 를 돌리기 전에 `Saved/AgentOps/20261114/fog3d/stage1d/ref-v2-lock.txt` 에 새 기준 모의 파일, 새 도구, 기준 숫자 파일, 새 장면 파일들의 sha256 과 기준 덤프 목록의 지문을 적는다. 그 뒤에는 이 파일들을 고치지 않는다. 틀린 것을 알게 되면 고치지 말고 멈춰서 보고한다.

## 2. 통과 기준

| 번호 | 무엇 | 기준 |
|---|---|---|
| E1 | 기존 장면 62개(1a 의 59 + 1b 보강 3)를 새 기준과 대조 | 바람·밀린 거리·채움의 장 차이가 각각 ≤ 0.2%, 유체 표시가 같음, 숫자형 검사는 새 기준 숫자 ± 등록 때의 허용. D3D12 와 D3D11 모두 |
| E2 | 새 장면(대칭 걷기 네 방향, 비스듬히 11.25도·22.5도, 벽 옆에서 바람이 스스로 옮겨지는 장면, 열린 윗면의 w 면을 가르는 장면) | 장 차이 ≤ 0.2%, 유체 표시 같음 |
| E3 | GPU 덤프로 다시 잰 대칭 | 네 방향 각각 좌우 치우침 ≤ 0.03, 네 방향 세기가 평균의 ±5% 안. 비스듬한 방향의 치우침은 기준 모의 값 ± 0.01 |
| E4 | 판별력(기준 모의로 미리 증명) | "한 성분만 옛 방식으로 남긴 것"과 "맨 위 층 w 면 식을 계약 초안대로 틀리게 한 것"이 각각 어느 한 장면에서 허용값의 3배 이상 차이를 낸다. 구현 뒤 독립 반박이 셰이더에 같은 종류의 변이를 넣어 대조가 실패하는지 확인하고 원래대로 되돌린다 |
| E5 | 기존 자동화 시험 | `TDGame.FluidFXRhi.Fog3D.*` 15개와 `TDGame.FluidFX.Fog3D.*` 23개가 통과. 방식이 바뀌어 기대값이 달라지는 시험은 목록과 까닭을 적고 고친다(기준을 느슨하게 하지 않는다). 결정론·먼 원점·창 이동·밀폐 칸(모든 덤프에서 유한, 바람 ≤ 3000cm/s)은 그대로 통과 |
| E6 | 회귀와 빌드 | 셰이더 검사 종료 0(Fog3D 셰이더가 FXC·dxc 에서 실제로 검사됨), `TDGame.FluidFXRhi` 전부 통과, `TDGame.FluidFX` 는 등록된 예외 `TDGame.FluidFX.CloudSource.WindCurtainStamps` 말고 전부 통과, 전역 셰이더 쿠킹 오류 0, 시험 무대 맵 쿠킹 오류 0 |
| E7 | 시간(정보) | 128칸·256칸 한 번 계산 시간을 앞 값(0.18ms·0.72ms)과 나란히 적는다. 256칸이 1.6ms 를 넘으면 통과와 별개로 감독에게 알린다(품질 단계 표를 다시 정해야 한다) |

판정: E1~E6 을 모두 만족하면 통과. 실패하면 원인을 고치고 다시 잰다. 기준은 바꾸지 않는다. 옛 방식의 기준에 묶인 1a·1b 의 대조(86검사·12검사)는 방식이 바뀌어 더는 쓰지 않으며, 그 기록은 그대로 남긴다.

## 3. 그 뒤

통과하면 에디터에서 걷는 방향을 바꿔 가며 한쪽 치우침이 화면에서도 사라졌는지 다시 찍고, 3인칭 프리셋의 값을 다시 확인해 기본값으로 넣는다.

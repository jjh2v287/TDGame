## 0. 목표와 범위

- 성공 조건(plan.md): 무대의 물체를 손으로 등록하지 않아도 안개가 막히고, 얇은 벽 뒤 안개가 칼에 바뀌지 않는다.
- 범위 밖(2c): 움직이는 물체·파편, 부분 다시 굽기. 범위 밖(2d): 일괄 촬영·전체 비용·눈 판정 묶음.
- 지키는 것: 새 동작은 모두 데이터 스위치이고 **기본값은 끔**(지금 그림 그대로). 스위치를 끄면 지금과 바이트까지 같아야 한다(2a·B4 와 같은 방식). 게임 로직은 C++, 에셋 동기 로드 금지(AGENTS.md 7절), 정본 기본값 변경은 사용자 결정.

## 1. 지금 상태(지도 요약)

- 물체는 액터에 손으로 단 `UTDFluidObstacleComponent` 로만 들어온다(`TDFluidObstacleComponent.cpp:61-70`). 충돌 도형을 읽는 곳은 프로젝트에 없다.
- 3D 안개는 **서 있는 상자(요 회전만)** 만 받고 구·기운 상자는 버린다(`TDFog3DLayer.cpp:578-595`). 최대 32개, 창 중심 거리 순. GPU 는 칸 중심 점 하나로 막힘을 판정(`TDFluidGpuFog3D.usf:66-73, 127-149`)하고, 얇은 물체는 반두께 하한(가로 7.9cm, 세로 15.1cm)으로 부풀린다.
- 칼·몸 입력 구는 막힌 칸을 보지 않는다(`usf:840·854·1082`) → 흠 ①(벽 뒤 10.39 대 옆 3.66)의 구조적 원인. 기준 계산에도 입력 가림이 없다.
- 기준 계산은 구·서 있는 상자·`cells` 마스크를 알지만 재생·GPU 는 상자만 안다(`fog3d_replay.py:371`). 기준은 64비트, GPU 는 32비트로 안팎을 판정한다 — 지금은 경계에 칸 중심이 걸리지 않는 장면만 있어 '유체 표시' 대조가 0 으로 맞는다.
- 덮인 빈 곳: 그리는 식 `TDFog3DBaseCurve` 가 땅 아래 높이를 `max(높이, 0)` 으로 가장 짙게 둔다(`TDFluidGpuFog3DDensity.ush:37`). 땅 태그를 단 다리·판 밑이 꽉 차는 까닭.
- 흠 ②(물체 옆 띠)·④(먼 상자 아래 쐐기): 관찰뿐, 원인 가르기 실험 없음. 흠 ③(높은 상자 뒤): 옆 카메라 숫자로 막힘과 입력 넘어 닿음을 못 가름.

## 2. 항목별 결정 (선택지 → 권장 → 까닭)

### 2.1 물체 모으기 (자동)

- 선택지: (가) 구역 시작 때 한 번 구역 전체를 모아 두고 창마다 고르기 (나) **창이 한 칸 단위로 움직일 때마다 창 + 여유 상자 안을 겹침 질의로 모으기** + 변경 알림(액터 생성·제거, 정적 물체의 변환 바뀜)으로 다시 모으기 (다) 매 걸음 질의.
- 권장 (나). 까닭: 월드 파티션 스트리밍이 자연스럽게 따라오고(올라온 것만 질의에 보임), 구역이 커도 비용이 창 크기에 묶인다. 매 걸음 질의(다)는 낭비, 구역 전체(가)는 오픈월드에서 수천 개와 스트리밍 갱신이 문제.
- 질의: `UWorld::OverlapMultiByObjectType`(WorldStatic·WorldDynamic, `bTraceComplex=false`) — 창 사각형 × 구역 높이 + 여유 1칸.
- 거르기(넣는 것): 질의 결과 컴포넌트 가운데 `GetCollisionEnabled` 가 질의를 포함하고 **폰 채널에 Block** 인 것(캐릭터가 지나갈 수 없는 단단한 것 = 안개도 막는 것). 빼는 것: 랜드스케이프(`ALandscapeProxy` 소유)·땅 태그(`TDFluidTerrain`) 액터(땅 캡처가 맡음), 폰·캐릭터, 이동성 Movable(2c), 액터 태그 `TDFog3DIgnore`, 손 부품(`UTDFluidObstacleComponent`)이 붙은 액터(손 등록이 이긴다 — 중복 방지).
- 도형 읽기: `GetBodySetup()->AggGeom` 의 원소를 컴포넌트 변환으로 월드 도형으로 바꾼다 — 구 → 구, 상자 → 방향 상자(3축 회전), 캡슐(Sphyl) → 캡슐, 테이퍼 캡슐 → 큰 반지름 캡슐(보수), 볼록 → 그 원소의 지역 상자(`ElemBox`)를 방향 상자로(보수), 단순 충돌이 없는 컴포넌트 → 컴포넌트 지역 경계 상자를 방향 상자로 + 경고 1회. 비균일 크기는 원소의 `GetFinalScaled` 결과를 쓰고, 거울(음수 크기)은 절댓값.
- 스레드: 질의·도형 읽기는 게임 스레드, 결과는 값 복사로 프레임 입력에 싣는다(지금 장애물 길과 같음).

### 2.2 도형과 칸 굽기

- 선택지: (가) **GPU 굽기 셰이더가 도형 목록을 칸 중심 점으로 판정**(지금 방식 확장) (나) CPU 에서 층별 막힘 비트맵으로 굽고 올리기 (다) 일반 메시를 삼각형으로 복셀화.
- 권장 (가). 까닭: 2a 땅 따라가기에서 칸 높이가 GPU 의 땅 높이(`ColumnTerrain.x`)로 정해지므로 CPU 비트맵(나)은 땅 높이를 CPU 로 되읽어야 한다. (다)는 쿠킹·CPU 접근 문제(`bAllowCPUAccess`)와 비용 때문에 1차 범위 밖.
- 도형 종류(GPU 구조체에 종류 필드): ① 서 있는 상자(지금 코드 그대로 — 끄면 같음을 지키려고 길을 나누지 않는다) ② 방향 상자(3×3 회전) ③ 구 ④ 캡슐(선분 + 반지름).
- 부풀림(얇은 것이 칸 중심 사이로 빠지지 않게): 방향 상자는 지역 축마다 `max(반치수, 7.9 + 7.2·|축·위|)` — 기준 `inflate_half(half, axis_up_dot)` 가 이미 이 꼴을 예정해 둔 식(지금은 0·1 만 씀). 구·캡슐 반지름은 `max(r, 18.7)`(기준의 구 하한).
- 한도: GPU 상수 32 → 256(설정 `MaximumObstacleCount` 의 검증 상한도 256, **기본값 32 그대로**). 고르기는 창 중심에서 **도형까지 가장 가까운 거리** 순(긴 벽이 중심 거리 때문에 밀려나지 않게), 넘치면 먼 것부터 버리고 수를 경고로 남긴다.
- 32비트 대 64비트 경계: 기준 장면은 모든 칸 중심이 부풀린 도형 경계에서 0.01cm 넘게 떨어지게 만들고(기준 도구가 장면마다 최소 거리를 계산해 어기면 장면을 거절), 그 위에서 '유체 표시' 대조는 정확히 0 을 요구한다.

### 2.3 책상 밑·덮인 빈 곳 (2a 넘김 ①)

- 책상 밑: **충돌 도형을 그대로 따른다** — 상판·다리로 나뉜 단순 충돌이면 밑의 층이 비고, 통짜 상자면 막힌다(계획 3절의 기본 생각). 통과로 치는 최소 빈 높이는 따로 두지 않고 '칸 중심이 부풀린 도형 밖인가'로 정해진다(층 30cm 에서 예: 두께 3cm 상판이 72~75cm 면 0·1층 열림, 2층 막힘). 기준·GPU 대조 장면에 넣는다.
- 덮인 빈 곳(다리·처마·판): 선택지 (가) **규칙: 밑으로 지나갈 수 있는 구조물에는 땅 태그를 달지 않는다 → 자동 수집이 물체로 막고, 땅은 그 아래 실제 땅을 캡처** (나) 그리는 식에서 땅 아래를 0 으로(밑이 텅 빔 — 다리 밑 안개가 사라져 어색) (다) 땅을 두 겹(윗면·밑면)으로 캡처(계획 4절 D안, 비쌈). 권장 (가) + 알려진 한계 기록: 위를 걷는 데크를 태그하지 않으면 그 위 안개가 얇아진다(안개층이 아래 실제 땅 기준) — 걷는 데크와 밑 공간을 둘 다 살려야 하는 곳이 실제로 생기면 (다)를 그때 연다. 이 규칙은 무대 도구·문서에 적고, 땅 태그 액터가 위에서 본 높이 아래에 빈 공간을 가지면 경고하는 점검은 만들지 않는다(비용 대비 이득 작음).

### 2.4 벽 너머 입력 막기 (흠 ①)

- 선택지: (가) 칸마다 입력 구의 중심선까지 곧은 선을 칸 단위로 따라가며 막힌 칸을 만나면 가림(DDA) (나) **이어짐 가림: 입력 구의 중심선이 지나는 열린 칸에서 시작해, 열린 면으로만 이어진 칸에만 입력을 준다(구의 영향 상자 안에서 6방향 채우기)** (다) 기준 R4(땅 기울기 좌표 가림)만 쓰기 — 평지 얇은 벽을 못 막는다(2a 문서가 2b 몫으로 넘김).
- 권장 (나). 까닭: ① 막힘·면 표식만 쓰는 정수 계산이라 GPU 와 기준이 비트까지 같게 맞출 수 있다(DDA 는 32비트·64비트 경계 차로 칸이 갈릴 수 있음) ② 시뮬레이션이 이미 쓰는 '열린 면으로 이어짐' 규칙(S9)과 같은 뜻 ③ 벽 끝이 구 영향 안에 있으면 끝을 돌아 들어가는 자연스러운 감쌈, 벽이 영향보다 길면 완전 차단.
- 세부(계약에서 확정): 씨앗 = 중심선(지난 걸음 위치 → 이번 위치) 위 고정 표본 점들이 든 열린 칸(점 위치는 32비트로 계산하고 기준도 같은 32비트 흉내), 씨앗이 모두 막혔으면 그 구의 입력 없음. 채우기 범위 = 구 영향 상자(반지름 + 붓 여유) 안. GPU 는 구마다 그룹 하나가 공유 메모리에서 채우기를 끝까지 돌리고(한 번 디스패치), 결과 비트를 입력 단계가 읽는다. 땅 벽 기둥도 막힌 칸이므로 절벽 너머 입력도 같은 규칙으로 막힌다(켬일 때 2a 절벽 장면 결과가 바뀜 — 기준과 함께 바뀌는지 대조).
- 몸 구도 같은 규칙(벽에 붙어 걸을 때 벽 너머로 새지 않게).
- 스위치 `bOccludesInputBehindObstacles`(기본 끔). 켬이어도 영향 상자 안에 막힌 칸이 없으면 모든 칸이 이어져 있으므로 결과가 끔과 바이트까지 같아야 한다(구현은 '막힌 칸이 있을 때만 곱한다'가 아니라 이어짐 비트 0/1 로 고르기 — 1 이면 지금 값 그대로).

### 2.5 흠 ②(띠)·④(쐐기) 원인 가르기

- 고치기 전에 원인부터: 가설 셋을 숫자로 가른다 — (H1) 시뮬레이션 값(막힌 칸 옆 밀린 안개) (H2) 막힌 칸의 '그리기용 값 채우기'(stage1/spec.md:216)가 경계에서 섞여 생긴 띠 (H3) 그림자·시선 합 같은 그리기 쪽.
- 방법: ① 기존 1단계 GPU 덤프(`k3_box_high`·`still_600`·`k4_run` 등, 기준과 대조 통과한 것)에서 상자 옆 칸의 장 값과 먼 칸을 견준다 — 값에 띠가 있으면 H1 ② 같은 장면의 그리기 입력(채움 포함)을 덤프에서 다시 만들어 띠가 채움에서 생기는지 — H2 ③ 1단계 무대에서 그림자 끔·조명 끔 짝 촬영과 휘두르기 없는 대조 실행, 위 카메라 — H3. 쐐기(④)는 `LOW_sw_b` 를 다시 재서 재현부터 확인(지난 값 18.0 대 0.27, 미검증).
- 산출: 원인 분류와 증거(판정선 없음). 고치기는 원인이 나온 뒤 따로 정한다.

### 2.6 흠 ③ (높은 상자 뒤, 위에서 본 확인)

- 2.4 를 넣은 뒤, 1단계 무대의 높은 상자 옆 휘두르기를 **위 카메라**로 켬·끔 찍어 상자 뒤 띠의 변화 ÷ 휘두르기 없는 대조를 잰다(숫자 문턱은 판정선 등록 때 1단계 값 기준으로 정함).

### 2.7 구역 상자 높이 규칙 (2a 넘김 ②)

- 선택지: (가) 손으로 잡되 **땅 캡처 뒤 '상자 밖이라 무효가 된 땅 기둥 수'를 세어 경고**(+ 문서의 규칙: 바닥은 가장 낮은 땅 아래, 윗면은 가장 높은 땅 + 안개 두께 위, 폰 세로 여유 200) (나) 창을 따라 상자 높이를 땅 경계에 자동으로 맞추기.
- 권장 (가). 까닭: 오픈월드 구역을 실제로 쓰는 단계가 아직 없고, 2a-4 의 세 곳(높낮이 54m 포함)은 60m 상자로 문제가 없었다. (나)는 월드 파티션·높은 상자 비용(못 잼)과 함께 오픈월드 구간에서 연다.

### 2.8 바뀜 감지

- 자동 수집은 창 걸음마다 다시 모으므로 '바뀜'은 도형 목록(고른 순서 그대로)의 키 비교로 충분하다(지금 방식). 키에 도형 종류·회전 3축·반지름을 더한다. 정적 물체만이므로 걸음마다 다시 굽는 일은 창 이동·생성/제거·변환 바뀜 때뿐이다.

## 3. 기준 계산·재생·대조 틀에 더할 것

- 기준(`fog3d_core.py` 계열, 잠긴 파일은 고치지 않고 새 파일이 갈아 끼움 — 섞기 B4 와 같은 방식): 방향 상자·캡슐 판정, 부풀림 `inflate_half(h, 축·위)`, 이어짐 가림(정수 채우기), 장면 경계 여유 점검.
- 재생 json: `obstacles` 항목에 `kind` = `box`(지금) | `obox`(중심·반치수·사원수) | `sphere`(중심·반지름) | `capsule`(a·b·반지름), 상한 256. 최상위 `input_occlusion`(false 기본). C++ 재생 읽기도 같이.
- 새 재생 장면(초안): 기운 판(30°), 책상(상판 + 다리 넷, 단순 충돌 다섯), 통짜 책상(상자 하나), 구 바위, 캡슐 기둥, 창 안 낮은 다리 상판, 얇은 벽 휘두르기(`k7_thin_swing` 의 켬 판), 벽 끝 감쌈(짧은 벽), 절벽 칼(2a `s2a_cliff_walk_blade` 의 켬 판), 물체 256개 비용 장면, 몸이 벽에 붙어 걷기.
- 대조 항목 추가: 이어짐 비트(구마다)의 기준·GPU 같음, 벽 뒤 칸의 입력 영향 칸 수(켬이면 0).

## 4. 순서와 끊는 곳

1. **2b-0 등록**: 이 설계를 반박받고 판정선을 `prereg-2b-design.md` 로 잠금. ②④ 원인 가르기(2.5 ①②, 덤프만 쓰는 오프라인 분석)는 바로 시작할 수 있다(코드 안 바꿈) — 2b-1 과 나란히.
2. **2b-1 도형·굽기**: 기준·재생·GPU 의 새 도형과 한도 256 — 끔 = 바이트 같음, 새 도형 장면 = 기준과 같음.
3. **2b-2 자동 수집**: 게임 쪽 모으기·거르기·도형 읽기 + 단위 시험(임시 월드에 도형 컴포넌트를 둔 시험). 스위치 `bCollectsCollisionObstacles`(기본 끔).
4. **2b-3 입력 가림**: 기준 실험(가림 판정선) → GPU → 대조.
5. **2b-4 화면 확인**: PIE 에서 손 부품 없는 물체를 띄워(에셋 저장 없음) 막힘·책상 밑·얇은 벽·위 카메라(흠 ③), 켬·끔 나란히 그림 → 사용자 눈 판정. ②④ 의 그리기 쪽 짝 촬영(2.5 ③)도 여기서.
6. **2b-5 구역 상자 경고**와 문서 규칙.
- 끊는 곳: 각 번호 끝(빌드 통과·끔 = 지금).

## 5. 판정선 초안 (등록 때 숫자 확정)

- B2-1 끔 = 지금: 스위치 둘 다 끔·새 도형 없음에서 기존 GPU 덤프 다섯 폴더와 `gpu_blend_b4` 가 RHI 마다 바이트 같음, 기존 대조 모두 그대로.
- B2-2 새 도형: 새 장면들에서 GPU 대 기준 '유체 표시' 다른 칸 0(장면 경계 여유 ≥ 0.01cm 점검 통과가 전제), 장 차이는 s2a 규칙(X = min(3%, max(0.2%, 3×민감도))).
- B2-3 자동 수집 단위 시험: 도형 종류·중심·크기·회전이 기대값과 1e-3cm·1e-5rad 안, 거르기(땅·폰·Movable·무시 태그·손 부품 중복) 모두.
- B2-4 입력 가림(기준): 얇은 벽 휘두르기에서 벽 뒤 칸의 입력 영향 칸 수 0 이고 벽 뒤 장 변화가 끔 대비 1% 이하, 막힌 칸 없는 장면(평지 R5 13장면 + 새 B4 장면)은 켬 = 끔 바이트 같음, 짧은 벽 끝 감쌈은 정보.
- B2-5 입력 가림(GPU): 이어짐 비트 기준과 같음, 장 차이 s2a 규칙.
- B2-6 비용(정보 + 문턱): 품질 2 에서 물체 256개 굽기 ≤ 1.0ms, 입력 가림 ≤ 0.2ms(넘으면 타일 묶기 등 고치기 판단).
- B2-7 화면: 위 카메라 높은 상자 뒤 띠 변화(켬) ÷ 대조 ≤ 1.5, 얇은 벽 뒤 ÷ 옆 비가 1단계 2.8 에서 ≤ 1.2 — 등록 때 1단계 원값으로 다시 잡는다. 눈 판정은 사용자.
- B2-8 변이(독립 반박): 도형 종류 하나 빠뜨림, 부풀림 축 바꿈, 가림 씨앗 무시, 가림 켬인데 땅 벽 무시, 손 부품 중복, 땅 태그 미제외 등이 위 검사에 잡히는지.

## 6. 위험·모르는 것

- 무대 메시들의 단순 충돌 실제 꼴(통짜 상자인 가구가 많을 수 있음 — 그러면 책상 밑이 막힘). 촬영 전에 수집 결과 목록을 로그로 확인.
- 겹침 질의에 스트리밍 액터가 보이는 시점, 채널 설정이 다른 지형.
- 굽기 비용: 칸 524K × 도형 256 전수 판정(추정 1ms 안팎) — 넘으면 타일 묶기.
- 이어짐 가림의 공유 메모리 크기(구 영향 상자 최대 칸 수)와 긴 휘두르기(한 걸음에 먼 이동)의 영향 상자.
- 흠 ②④가 시뮬레이션 성질(H1)이면 고치는 일이 2b 범위를 넘을 수 있다 — 그때 따로 정한다.

# 2a 땅 높이 따라가기 — 구현 통과 기준 (등록본)

등록: 2026-11-15 claude(감독·결정). 구현 계약 `impl-2a-contract.md` ⓪절 10 에 따라, 기준 덤프를 뽑은 뒤·GPU 덤프를 기준 덤프와 견주기 전에 잠근다. 해시는 `Docs/VolumeFog3D/progress.md` '사전 등록 잠금'에 적는다. 잠근 뒤에는 고치지 않고, 바꿀 것은 다음 측정 전에 덧붙임으로 등록한다.

## 0. 이 문서를 쓸 때 감독이 이미 본 숫자 (있는 그대로)

- 기준 모의끼리의 숫자: 기준 덤프와 "입력을 1e-4cm 흔든 기준 덤프"의 차(구현 단계 2 넘김 글 7절, 원인 조사 메모 `Saved/AgentOps/20261115/fog3d/stage2a/impl/shake-sensitivity.md`). GPU 가 들어가지 않은 숫자다.
- GPU 의 단위 시험 숫자(GPU 대 시험 코드의 64비트 식, 재생 장면이 아닌 시험용 입력): 기둥 굽기의 기울기 최대 오차 5.5e-8, 입력 틀의 자리 2.9e-6cm·기울기 1.9e-7, 균일 비탈 대 평지 정보 시험(바람 최대 차 ÷ 평지 바람 최대 = 1.9e-7), 변환 패스 불일치 0, 그리는 식 농도 최대 차 1.85e-6.
- 탐침 P1 의 결과(최대 오차 0.0156cm)와 재질 명령 수(평평한 변형 284, 땅 변형 312, 텍스처 표본 1 → 2). 아래 I4·I5 의 문턱은 이 측정보다 먼저 계약(⑨절 P1 "0.5cm", ⑩절 "표본 +1, 명령 +40 이하")에 적혀 있던 값 그대로다.
- **보지 않은 것**: 재생 장면 12개의 GPU 덤프와 기준 덤프의 차. 구현 단계 4 의 구현자에게 견주지 말라고 못박았고(넘김 글 `step4-handoff.md`), 대조 도구는 실제 GPU 덤프 폴더에 돌린 적이 없다. I7·I8·I9 의 측정도 아직 하지 않았다.

## 1. 대조 방식 (1단계 1d 와 같은 잣대)

- 재생 장면 12개·덤프 38개(`Tools/FluidFX/fog3d_ref/replays_s2a/`, 기준 덤프 `Saved/FluidFX/Fog3D/ref_s2a/`, 목록 sha256 은 넘김 글 `step2-handoff.md` 5절). 후보는 R4(덧붙임 2 가 R5 를 고르면 I1 을 R5 기준 덤프로 다시 잰다 — 4절).
- 장 차이 = 잠긴 `fog3d_compare_v2.group_diffs` 그대로: 묶음(바람 u·v·w / 밀린 거리 dx·dy·dz / 채움 g)마다 "두 쪽 차의 제곱합 제곱근 ÷ 기준의 제곱합 제곱근", 기준 덤프의 유체 칸 전체(가장자리 띠를 빼지 않는다). 기준 묶음이 모두 0 이면 GPU 도 정확히 0 이어야 한다.
- 한계 X = min(3%, max(0.2%, 3 × 민감도))(1단계 1a 의 식 그대로). 민감도 = 기준 덤프와 흔든 기준 덤프의 같은 장 차이. 계산해 보니 모든 덤프·묶음에서 민감도 ≤ 4.02e-4(가장 큰 것은 s2a_box_on_slope 끝 시점의 바람)라 **X 는 모든 덤프·묶음에서 0.2%** 다. 숫자 파일 `Docs/VolumeFog3D/measurements/stage2a-impl/prereg-2a-impl-numbers.json`(민감도 표 포함).
- 알아 둘 것(원인 조사): 세기 3.0 걷기 장면의 흔든 차가 평지 세기 2.0 장면보다 100배쯤 큰 것은 비탈 때문이 아니라 1단계부터 있던 섞기 식의 성질이다(무게 × 세기가 2 를 넘는 면에서 목표와의 차가 걸음마다 부호를 바꾸며 커진다. 같은 조율의 평지 걷기도 같은 크기다). 그래서 이 장면들에서는 GPU 의 32비트 반올림도 같이 불어난다. 그래도 위 식의 X 는 0.2% 로 남는다.

## 3. 떨어졌을 때

- I1·I2·I6 이 떨어지면 구현을 고친다(코드가 계약의 식이나 기준 모의와 다른 곳을 파일:줄로 기록). 문턱·장면은 바꾸지 않는다. 고친 뒤 I1·I2 를 모두 다시 잰다.
- 코드가 식과 같은데 I1 이 떨어지면(32비트 반올림이 섞기 식의 증폭을 받아 0.2% 를 넘는 경우 등) 그 덤프·묶음과 근거를 적고, 덧붙임을 다음 측정 전에 등록한다. 그때까지 2A-I1 은 미통과다.
- I7·I8 이 떨어지면 값을 그대로 적고, 줄이는 일을 3단계(비용) 할 일로 넘길지 지금 고칠지를 감독이 결정으로 적는다(2a 의 기능 통과와는 따로 본다).
- I9 가 떨어지면 지연 설정이나 캡처 방식(독립 렌더러)을 계약 ⑨절의 물러설 길대로 바꾸고 다시 잰다.

## 4. 덧붙임 2 의 판정과의 관계

- R5 가 골라지면: 구현 단계 7 에서 R5 덧층을 넣고, 기준 덤프를 `fog3d_replay_s2a.py --candidate R5` 로 다시 뽑아(민감도도 다시 계산, X 의 식은 같음) I1·I3 을 R5 로 다시 잰다. R4 로 잰 I1 은 "R5 덧층을 넣기 전의 본체 확인"으로 남긴다.
- R5 가 골라지지 않으면: R4 로 잰 I1 이 최종이다.

## 5. 이 등록이 가리지 않는 것

- 화면에서 어떻게 보이는지(2a-3, 따로 등록).
- 랜드스케이프 위의 캡처(상세 단계), 주 렌더러 안 캡처의 정렬(2a-3 과 2a-4 에서 본다).
- 섞기 식의 넘침(세기 3.0 에서 가만히 선 몸이 바람을 계속 만드는 것): 1단계부터 있던 성질이고 2a 의 범위 밖이다. 따로 보고한다.

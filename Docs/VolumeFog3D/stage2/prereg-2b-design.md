## 1. 결정

### 1.1 스위치 둘 (둘 다 기본 끔)

- `bCollectsCollisionObstacles`: 물체 모형 전부 — 자동 수집, 손 부품의 기운 상자·구 받기, 일반 도형 종류, 새 고르기, 얇은 바닥면 건너뛰기. 끔이면 지금 그대로(`ReadUprightYaw` 건너뜀·`LastSkippedObstacleCount`·창 중심 수평 거리 정렬·서 있는 상자만).
- `bOccludesInputBehindObstacles`: 입력 가림(1.2). 끔이면 입력 셰이더 결과가 지금과 바이트까지 같다.
- 한도: GPU 상수 32 → 256, 설정 `MaximumObstacleCount` 검증 상한 256, **기본값 32 그대로**(켜면 바로 넘칠 수 있음을 문서·경고로).

### 1.2 입력 가림 — 닻 채우기

- **닻**: 구를 낸 캐릭터의 골반 월드 위치(골반 뼈가 없으면 폰 위치). 구 구조체는 바꾸지 않고 **별도 버퍼**(구마다: 닻 칸 i·j 정수 둘, 닻 높이 z(창 cm, float), 표지). 버퍼는 `PackSpheres` 의 건너뜀과 같은 순서로 채운다. 재생 json 의 구 필드 이름은 `occlusion_anchor_cm`(최상위 `anchor_cell` 과 헷갈리지 않게).
- **닻 칸 정수식**: i·j 는 CPU 에서 64비트로 (닻 − 창 원점)/15.625 의 floor 를 구해 [0, n−1] 로 자른다(재생 C++·기준도 64비트 같은 식). k 는 GPU 가 floor((z − T)/30) 를 [0, 7] 로 자른다 — T 는 자른 (i, j) 열의 `ColumnTerrain.x`(땅 따라가기 끔이면 0). 재생 장면은 '닻 z − T 가 30 의 배수에서 0.01cm 넘게 떨어짐'을 점검한다.
- **채우기 상자**: 그 구의 거르기 술어 상자(지금 32비트 비교, 8층 전부)와 닻 칸을 **모두 담는 가장 작은 축 정렬 상자**를 창 안으로 자른 것. 걷기는 이 상자 안에서만 한다.
- **규칙**: 닻 칸에서 열린 면으로만 6방향으로 걷는 너비 우선 거리 d(c)(바이트, 255 에서 포화). 칸 c 가 이어짐 = d(c) ≤ 맨해튼(c, 닻 칸) + **2**. 정수만 쓰고 변화가 없을 때까지 돈다. 상자 안에 막힌 칸이 없으면 상자가 볼록하므로 모든 칸에서 d = 맨해튼 → 전부 이어짐(켬 = 끔).
- **허용(가림 없음, 수를 셈)**: 닻 칸이 막힘 / 상자가 창으로 자른 뒤 48×48×8 을 넘음. 닻이 없는 구(옛 재생)도 가림 없음.
- **비트의 뜻**: 채우기 상자 밖 칸의 이어짐 비트는 0, 허용(가림 없음) 구는 술어 상자 안 칸이 모두 1. 판정과 집합 비교는 그 구의 술어 상자 안 칸만 본다.
- **적용**: 바람 넣기(`ComputeFog3DSweptBrushWeight`·`ComputeFog3DFramedBrushWeight` 의 결과)와 깎기(`ComputeFog3DDwellAmount`·`ErodeFog3DFill`) 모두 '이어짐 비트가 0 이면 그 구의 몫을 건너뜀'(곱하지 않음).
- GPU: 구마다 그룹 하나가 공유 메모리(칸당 1바이트, 최대 18KB)에서 채우기를 끝까지, 디스패치 하나. 결과 비트는 칸마다 16비트(구마다 한 비트) 묶음으로 남겨 덤프한다.
- 땅 벽 기둥도 막힌 칸이라 절벽·턱 너머도 가린다(켬에서 `s2a_slope_curb60` 같은 낮은 턱 위 칸은 칼이 턱보다 위여도 가려짐 — 받아들이고 사용자 그림에 넣는다).

### 1.3 도형과 굽기

- 종류: ① 서 있는 상자(지금 코드·길 그대로) ② 방향 상자(사원수) ③ 구 ④ 캡슐. ②③④ 는 `bCollectsCollisionObstacles` 켬에서만. 자동 수집 상자가 서 있음 허용(`Fog3DUprightTolerance`) 안이면 ① 로 넣는다.
- 부풀림: ② 는 지역 축마다 `max(반치수, 7.9 + 7.2·|축·위|)`, ③④ 반지름은 `max(r, 18.7)`.
- 얇은 바닥면 건너뛰기: 자동 수집 도형에 '부풀리기 전 윗면 높이'와 표지를 싣고, 굽기에서 그 열의 땅(땅 따라가기 끔이면 구역 바닥) + 10cm 이하이면 그 열에서 건너뛴다. 손 부품 도형에는 표지가 없다(끔 = 지금).
- 고르기(켬): 창 + 1칸과 겹치는 도형만, 창 중심에서 도형까지 가장 가까운 수평 거리 순, 같으면 (컴포넌트 이름, 원소 번호, 인스턴스 번호) 순. 한도를 넘으면 먼 것부터 버리고 경고.
- 비용 고치기(필요할 때만): 굽기 그룹(8×8×4)마다 AABB 미리 거르기 — OR 결과가 같아 바이트도 같다.

### 1.4 물체 모으기 (켬)

- 언제: 창이 움직인 걸음과 '다시 모아야 함' 표시가 선 걸음. 표시는 `FWorldDelegates::LevelAddedToWorld`·`LevelRemovedFromWorld`, 실행 중 생성(`OnActorSpawned`)·제거. 정적 물체 변환 알림은 걸지 않는다.
- 어디서: 지금 창 + 둘레 16칸(창 한 걸음) × 구역 높이.
- 질의: `OverlapMultiByObjectType`(WorldStatic·WorldDynamic, `bTraceComplex=false`, `bSkipNarrowPhase=true`), 결과 (컴포넌트, ItemIndex).
- 넣음: 질의를 포함한 충돌이고 폰 채널에 Block.
- 뺌: 랜드스케이프, 땅 태그 `TDFluidTerrain`, 폰, Movable, `AVolume` 파생과 InvisibleWall 계열 프로필, 태그 `TDFog3DIgnore`, 손 부품 액터, 복잡 충돌을 단순으로 쓰는 메시·단순 충돌 없는 메시(경고 1회, 태그 `TDFog3DBlockBounds` 면 지역 경계 상자로 넣음).
- 도형 읽기(순수 함수 '컴포넌트 → 도형'): 원소 `GetFinalScaled`(크기 적용된 컴포넌트 지역) → 크기를 뺀 컴포넌트(또는 인스턴스) 변환으로 월드. 구 → ③, 상자 → ①/②, 캡슐 → ④, 테이퍼 캡슐 → 큰 반지름 ④, 볼록 → 원소 변환 공간 `ElemBox` 를 ②. 거울: 크기 절댓값은 반치수에만, 중심은 부호 있는 크기, 회전은 축 하나를 뒤집어 고유 회전으로. 인스턴스 메시는 `GetInstanceTransform(ItemIndex, …, true)`. 컴포넌트당 원소 32 넘으면 빼고 경고.
- 결과는 3D 전용(2D 와 같이 쓰는 `ObstacleSources` 에 안 넣음). 파괴 물체는 한계.

### 1.5 책상 밑·덮인 빈 곳

### 1.6 구역 상자 높이

- 손으로 잡고, CPU 에서 캡처 사각형 안 랜드스케이프 컴포넌트·땅 태그 액터 경계의 z 범위가 구역 상자 세로 범위를 벗어나면 경고(수·최저·최고). 문서 규칙: 바닥은 가장 낮은 땅 아래, 윗면은 가장 높은 땅 + 안개 두께 위, 폰 세로 여유 200. 자동 맞추기는 오픈월드 구역을 실제로 쓰는 구간에서.

### 1.7 흠 ②(띠)·④(쐐기) 분류 규칙

- **면 띠 대비**(1.9·B2-7 의 '벽 뒤 띠'와 다른 값): 물체 장면 안에서, 물체 면에 닿은 열린 칸 한 줄의 평균 채움 − 면에서 2~3번째 열린 칸의 평균 채움. 물체 없는 쌍둥이 값은 정보로만 남긴다.
- 재현 먼저: 1단계 PIE 경로를 본뜬 재생(높은 상자 안 칼끝 11.6cm, 얇은 벽 관통, 낮은 상자 옆 휘두르기와 먼 높은 상자)을 GPU 덤프로(가림 끔). **재현됨(= H1 시뮬레이션 값)** = |면 띠 대비| ≥ 같은 대비의 흔든 민감도 × 5. 재현되지 않으면 '시뮬레이션 값에서 재현 안 됨'으로 적고 H2·H3 을 본다.
- H2 그리기 채움: 덤프로 그리기 입력을 다시 만들 때 막힌 칸 채움(`usf:388-404` 이웃 평균)을 넣은 것과 뺀 것의 면 띠 대비(같은 자리, 그리기 입력에서) 차가 넣은 쪽의 50% 이상.
- H3 그리기·빛: PIE 짝 촬영(그림자 켬·끔, 같은 카메라)에서 같은 자리 화면 띠 대비가 50% 이상 달라짐.
- H4 입력 관통: 가림 켬에서 면 띠 대비가 80% 이상 줄어듦.
- 여럿이 함께 참일 수 있다. 2b 안에서 고치는 것은 H2·H4, H1·H3 은 따로 정한다.

- **앞조건**: W1·W2·W4 가림 끔에서 세는 영역 입력 영향 칸 수 > 0. 성립을 확인하면 장면 해시를 진행 기록에 적고(그 뒤 장면 불변) 켬을 계산한다. 성립하지 않으면 기하를 실측 쪽으로 고친다(문턱 불변).
- **주 판정**: 가림 켬에서 (1) W1·W2·W4 세는 영역 입력 영향 칸 수 = 0(바람·깎기 모두) (2) **과다 가림 없음** — 같은 장면에서 각 구의 술어 상자 안 칸 가운데 벽 앞쪽(부풀린 앞면보다 닻 쪽) 칸과 벽 y 범위 끝에서 2칸 넘게 바깥인 칸의 이어짐 비트가 모두 1.
- **켬 = 끔 묶음(지금 이름으로 등록)**: 닻 붙인 판의 B4 평지 13장면(`b4_walk_stand_*` 5·`b4_blade_*` 4·`b4_turn_stand_*` 4)과 `b4_slope_walk_up_h60_g125`, `s2a_flat_offset`·`s2a_slope_walk_up`·`s2a_slope_walk_down`·`s2a_slope_y_walk`·`s2a_frame_at_edge`. 앞조건: 기준 도구가 '모든 걸음·모든 구에서 채우기 상자 안 막힌 칸 0'을 확인(아니면 등록 오류로 적고 덧붙임으로만 옮긴다). 판정: 기준 켬 = 끔 바이트 같음.
- **바뀜 묶음**: W1~W5, 닻 붙인 판의 `s2a_box_on_slope`·`s2a_cliff_at_edge`·`s2a_cliff_walk_blade`·`s2a_slope_curb60`·`s2a_hill_run_window`·`s2a_still_rough`·`s2a_slope_curb`·`s2a_curb30_cross`, 1단계 물체 장면(`k3_box_high`·`k4_run`·`k7_thin_swing`·`still_600`·`mixed_dt_120`)의 닻 판 — B2-3 으로 본다.
- **나눔 확인**: `check-gates` 는 `replays_s2a/R5`·`replays_blend_b4`·새 2b 재생 폴더의 모든 장면이 두 묶음 가운데 정확히 하나에 있는지 확인한다. 1단계 재생 폴더는 위 다섯 물체 장면의 닻 판만 대상이고 나머지는 가림 판정 밖이다.
- **닻 붙이는 규칙(옛 장면, 장면별 표를 기준 도구가 내고 진행 기록에 적는다)**: ① 걷는 캐릭터 장면 = 반지름 60 구(골반 구) 중심 ② 구 하나만 움직이는 칼 장면(`b4_blade_*`, 1단계 칼 캡슐 장면) = 첫 걸음 구 중심에서 움직임 반대쪽 60cm, z − T = 105(층 가운데) ③ 경로 구만 있는 장면(`s2a_frame_at_edge` 등) = 구마다 가장 가까운 창 가장자리 밖 20cm, z − T = 105(창 밖 닻의 자르기를 시험한다). 1.2 의 0.01cm 닻 점검에 걸리는 걸음이 있으면 그 장면의 닻 z 에 0.5cm 를 더하고 표에 적는다.

### B2-3 입력 가림 — GPU 대 기준
- 바뀜 묶음: 덤프마다 유체 표시 0, 장 차이 ≤ X(s2a 규칙, 새 숫자 파일), 이어짐 비트 묶음 기준과 같음, 검사 수·덤프 수·건너뜀 0(L-repo-38).
- 켬 = 끔 묶음: GPU 켬 = GPU 끔 바이트 같음.
- 허용 수는 장면마다 적는다(정보).

### B2-4 도형·굽기 — GPU 대 기준
- 장면: 30°·45° 기운 판(두께 3), 법선 (1,1,1)/√3 판, 벽 위 30° 지붕(이음매), 구 바위(r 60), 선 캡슐 기둥(r 25·높이 200), 누운 캡슐, 나뉜 책상(상판 3cm 72~75 + 다리 넷), 통짜 책상, 창 안 낮은 다리 상판(150~165), 땅 위 2cm 판(건너뜀)과 20cm 턱(안 건너뜀), 도형 256개 격자.
- 장면 점검(기준 도구가 거절): 칸 중심이 부풀린 도형 경계에서 0.01cm 넘게 떨어짐.
- 판정: 덤프마다 유체 표시 0, 장 차이 ≤ X, 검사 수·덤프 수·건너뜀 0. 막음(기준만): 기운 판·지붕 이음매로 나눈 두 영역에서 한쪽 채움의 반대쪽 최대 비가 1단계 `leak_thin` 판정선과 같은 문턱 아래. 책상: 나뉜 책상 밑 0·1층 열림, 통짜 책상 막힘.

### B2-5 자동 수집 — 게임 단위 시험
- 순수 함수 '컴포넌트 → 도형': 회전 + 비균일 크기 상자, 비균일 구, 캡슐, 테이퍼 캡슐, 볼록(원소 변환), 거울 + 중심 밖 원소, HISM 인스턴스 둘(회전·비균일), 복잡 충돌을 단순으로(뺌 + 경고), 단순 충돌 없음(뺌), `TDFog3DBlockBounds`. 기대값은 엔진 `CalcAABB` 나 손 계산으로 따로 만들고 모서리 점 8개(또는 안팎 표본점)로 1e-3cm 안.
- 거르기: 랜드스케이프·땅 태그·폰·Movable·볼륨·InvisibleWall·무시 태그·손 부품 중복·질의 꺼짐·겹침만.
- A/B: 같은 큐브를 손 부품 액터와 맨 액터로 → 포장 GPU 물체 바이트 같음(종류 ①).
- 층 시험: 게임 포장 = 재생 읽기(새 종류, 바이트).

### B2-6 비용 (RHI 마다, GPU 이름 기록, 품질 2, 데우기 5회, 20회 가운데값)
- 게임 스레드 모으기: 도형 256개에서 창 걸음당 ≤ 0.5ms.
- GPU 굽기: 도형 256개 ≤ 1.0ms(D3D12 로 판정, D3D11 정보). 창 걸음마다 튀는 비용으로 적는다.
- 입력 가림: 구 16개 ≤ 0.2ms.
- 넘으면 1.3 의 미리 거르기 등으로 고친 뒤 다시(문턱 불변).

### B2-7 화면 (2b-4, 1.9 와 같은 법; σ = max(σ̂, 0.1 밝기 단계))
- 앞조건: 시운전(끔)에서 (벽 뒤 띠 − μ) ≥ 10σ.
- 주 판정(가림 켬): (켬 − μ) ≤ 0.2·(끔 − μ). μ + 3σ 는 정보.
- 흠 ③(위 카메라, 끔·켬): 높은 상자 뒤 띠 ≤ μ + 3σ — 넘으면 정보로 적고 따로 본다.
- 자동 수집 켬(손 부품 없는 큐브·책상·기운 판을 에디터 월드에 두고 저장하지 않은 채 PIE): 수집 목록 로그가 기대(개수·종류)와 같음, 위 카메라에서 물체 자리 막힘. 눈 판정은 사용자.

### B2-8 구역 상자 경고
- 단위 시험: 합성 랜드스케이프 경계가 상자 세로 범위 밖이면 경고 수 > 0, 안이면 0.

### B2-9 변이 (독립 반박)
- 잡혀야 하는 것: 닻 무시(구 자신에서 씨앗), 상자를 술어만으로(닻 섬 — 과다 가림), 여유 없앰(−1, 과다 가림), 여유 무제한, 깎기 가림 빠뜨림, 닻 창 자르기 없앰, 상자 넘침 규칙 뒤집음, 굽기 도형 종류 하나 빠뜨림, 부풀림 축 바꿈, 얇은 바닥면 건너뛰기를 손 부품에도, 끔에서 기운 손 상자 받음, 끔에서 새 정렬, 인스턴스 변환 무시, 땅 태그 안 뺌, 손 부품 중복 안 뺌. 살아남으면 실패 → 잡는 장면·시험을 더해 다시(문턱 불변). 변이가 있는 동안 빌드 보류.

## 7. 알려진 한계 (2b 에서 고치지 않음)

- 벽 끝: 닻 줄 = 끝 줄이고 채우기 상자가 끝 너머 줄을 담는 걸음에서는 그 벽 뒤 상자 안 칸이 모두 이어짐 — 끝을 돌아 휘두르는 것과 같다. 닻이 벽 가운데 쪽이면 끝에서 한 줄 안 칸만 이어진다(B2-2 손 식).
- 닻이 막혀 가림이 꺼지는 실제 경우: 30cm 넘는 턱·절벽의 높은 쪽 끝 열(벽 기둥이 되어 8층 모두 막힘), 키 약 2.1m 넘는 수집 물체 위에 설 때. PIE 로그에 수를 남긴다.
- 땅 따라가기에서 열 사이 땅 높이 차가 큰 곳(약 17cm/열 이상)의 얇은 기운 판은 칸 사이로 샐 수 있다.
- 복잡 충돌만 있는 메시·파괴 물체는 모으지 않는다(태그로 경계 상자만).
- 걷는 데크를 땅으로 태그하면 밑이 짙게 차고, 태그하지 않으면 위 안개가 얇다.
- 움직이는 물체·부분 다시 굽기는 2c.

## 1. 만드는 것 (뜻만, 꼴은 계약)

- 데이터 스위치 `bUsesClampedTimeWindBlend`(기본 false = 지금 식)와 배율 `BodyWindGain`·`BladeWindGain`(기본 1.0, 스위치를 켰을 때만 쓴다). 정본 설정 파일에는 기본값 그대로 적는다.
- 켜면: 섞는 양 k 는 `prereg-blend.md` 2절의 B4 그대로다(k₆₀ = min(W·s, 1). 60·dt 가 1 이면 k = k₆₀, 아니면 k = −expm1(60·dt × log1p(−k₆₀)), 단 k₆₀ = 1 이면 1). GPU 의 '한 걸음' 판정은 C++ 이 64비트로 |60·dt − 1| ≤ 1e-6 을 본다. 목표 바람 = G × 입력 속도(윗면은 지금처럼 비탈을 뺀 목표에 G 가 같이 실린다).
- **속도 상한 3000 의 자리(결정)**: 배율을 곱한 **뒤**에 건다 — 목표 바람의 크기는 늘 `MaximumInputSpeedCmPerSec`(3000) 이하다. 까닭: 상한의 뜻이 '섞어 넣는 바람의 크기'를 묶는 것이고, 기준 계산의 D-G4 한계(면 바람 최대 ≤ 3000)와도 같은 뜻이다. 배율 1.0 에서는 지금과 같다. 재생 시험 길에는 지금처럼 상한이 없다(기준 계산과 같음).
- 끄면: 셰이더의 지금 식 줄과 C++ 의 속도 셈이 지금과 같은 계산이어야 한다 — 아래 BG-1 이 바이트로 확인한다.
- 게임에서 안개 상태를 읽는 개발용 명령은 이번에 만들지 않는다. 대조는 재생 시험으로, 촬영 조건 확인은 설정이 적용될 때 남기는 로그 한 줄(품질 단계·초당 걸음·식·배율·땅 따라가기)로 한다.

## 4. 재생 장면 (BG-5·BG-6)

- **(가) 2a 의 R5 장면 13개 그대로**(`fog3d_replay_s2a.py --candidate R5` 의 장면·걸음·덤프 41개, 배율 1.0, 식만 B4). 땅 따라가기 길에서 몸 3.0·칼 2.5 의 자르기를 덮는다.
- **(나) 새 장면**: 평지 F0, 128칸, 2a 조율(`TUNING_S2A`, 옮기기 N2), 후보 R5, 입력은 섞기 실험 도구 `fog3d_blend_probe.py`·`fog3d_blend_gates.py` 의 것과 같다.
  - 걷다 멈춰 서기: 몸 구 셋, +x 로 초속 520cm 70/60초 걷고 200/60초 서기, 몸 세기 3.0. 덤프: 걷기 끝, 멈춘 뒤 0.5초, 1.5초, 끝.
  - 칼 휘두른 뒤: 칼 구(반지름 35, 세기 2.5, 깎기 초당 30, 높이 100)가 (−200, 0)에서 (−40, 0)까지 초속 800cm, 그 뒤 1초 꼬리. 덤프: 휘두름 끝, 0.25초 뒤, 끝.
  - 걷다가 직각으로 꺾기: +x 로 35/60초 → +y 로 35/60초(멈추지 않고 꺾음) → 서기 120/60초, 몸 세기 3.0. 덤프: 꺾는 걸음, 꺾은 뒤 걷기 끝, 그 1초 뒤, 끝.
  - 셋 각각 초당 60걸음·30걸음 × 배율 1.0·1.25(열둘), 걷다 멈춰 서기의 초당 144걸음·배율 1.0 하나, 2a 의 30도 비탈 오르막 걷기(`s2a_slope_walk_up` 의 입력과 지형)에 배율 1.25 하나 — 모두 열넷. 덤프 시각은 초당 걸음 수와 무관하게 같은 초다(그 초에 가장 가까운 걸음).
  - 평지 장면(비탈 하나를 뺀 열셋)은 BG-6 의 대상이다. 단 그 땅 높이가 모두 0 이어야 한다 — 아니면 생성 도구가 알리고 감독이 정한다.
- **(다) 생성 도구의 틀 확인(B4 를 만들기 전에)**: 같은 도구를 지금 식(B0)으로 돌려 (가)의 장면 둘이 기존 `ref_s2a/R5` 덤프와 바이트까지 같아야 한다. 다르면 멈춘다. 새 도구는 잠긴 파일(`Tools/FluidFX/fog3d_ref/` 의 기존 `fog3d_*.py`)을 고치지 않고 새 파일로 만든다.

## 5. 판별력 (BG-9, 독립 반박에서)

독립 반박자가 결함을 하나씩 넣어(끝나면 원복하고 sha256 확인) BG-1~8 가운데 하나 이상이 잡는지 본다. 변이 여덟: (가) 자르기 없음(k = W·s) (나) 거듭 지수를 거꾸로(1 ÷ (60·dt)) (다) 시간 거듭 없음(늘 k₆₀) (라) 배율을 수평 성분에만 곱함 (마) 스위치를 꺼도 배율을 곱함 (바) 상한을 배율 앞에 둠 (사) 스위치를 무시하고 늘 새 식 (아) 땅 따라가기를 켰을 때만 새 식. 여덟 모두 잡혀야 한다. 살아남는 변이가 있으면 BG-9 는 실패이고, 그것을 잡는 장면이나 시험을 더한 뒤 다시 본다(문턱은 바꾸지 않는다). 변이가 작업 트리에 든 동안에는 빌드 보류(`Saved/AgentOps/build_hold.json`)를 건다.

- 실행 18개. **실행마다 로그로 품질·초당 걸음·식·배율·땅 따라가기 꺼짐을 확인해 표에 적는다** — 하나라도 뜻과 다르면 그 실행은 무효이고 다시 찍는다.
- 찍는 것: 0.1초 간격 프레임. 장면 × 품질마다 세 판을 나란히 놓은 움직이는 그림(S1 은 멈추기 0.5초 전부터 멈춘 뒤 4초, S2 는 휘두르기 시작부터 4.5초, S3 는 걷기 시작부터 멈춘 뒤 2초), 그리고 멈춘 뒤(S2 는 휘두름 끝 뒤) 0.5·1.5·3초의 정지 그림 나란히.
- 페이지(한 파일, 쉬운 말, 판정 낱말 없음): 무엇이 바뀌었나 / 왜 — **"승인하신 그림에는 서 있는 동안의 끝없는 휘저음이 들어 있었다"**(지금 식은 몸 세기 3.0 에서 서 있는 몸 주변 바람이 잦아들지 않고 걸음마다 뒤집히며 안개를 계속 휘저었고, 승인하신 그림의 자국에도 그 휘저음이 섞여 있었다) / 새 식에서는 낮음 품질도 높음만큼 빨리 따른다(되돌릴 수 있는 결정) / 보는 법 / 물음: 어느 쪽이 나은가, 중과 강 가운데 어느 쪽인가, 정본 기본값을 새 식으로 바꿀 것인가.

## 7. 떨어졌을 때

- BG-1~4·6·8 이 떨어지면 구현을 고친다(코드가 계약과 다른 곳을 파일:줄로 적는다. 끔 길의 바이트가 컴파일 탓으로 달라지면 지금 식 길을 컴파일 시점 갈래로 나누는 것도 고치는 방법에 든다). 문턱·장면은 바꾸지 않는다. 고친 뒤 BG-1~8 을 모두 다시 잰다.
- BG-5 가 떨어지면: 코드가 계약·등록의 식과 다른 곳을 고치고 다시 잰다. 코드가 식과 같은데 32비트 반올림 탓으로 보이면 근거(덤프·묶음·값)를 적고 덧붙임을 다음 측정 전에 등록한다. 그때까지 BG-5 는 미통과이고 그림은 올리지 않는다.
- BG-7 이 떨어지면 시험의 기대값 식과 셰이더 식을 등록 식과 견주어 틀린 쪽을 고친다.

## 8. 이 등록이 가리지 않는 것

- 화면에서의 모양 — 사용자 눈 판정이다.
- 계산 비용(새 식의 거듭 계산) — 재지 않는다(초당 60걸음에서는 자르기 하나, 30걸음에서는 로그·지수 각 하나가 더해질 뿐이다).
- 게임 안의 실제 프레임 간격이 흔들릴 때의 따라감 — 재생 시험의 dt 셋(1/60·1/30·1/144)으로만 본다.
- 정본 기본값을 새 식으로 바꾸는 것 — 사용자 결정이다.

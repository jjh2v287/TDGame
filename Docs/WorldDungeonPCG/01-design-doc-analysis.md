# 1. 설계서 분석 (UE5_탑다운_ARPG_월드_던전_PCG_설계서.docx)

원본: `Docs/UE5_탑다운_ARPG_월드_던전_PCG_설계서.docx` (문서 기준일 2026-09-09, 17개 장 + 부록 2개). 이 파일은 설계서를 "요구사항 항목"으로 분해한 것이다. 각 항목에 식별자(R-번호)를 붙여 할 일 목록과 아키텍처 문서가 참조한다.

## 1.1 한 문장 요약

하나의 World Partition 월드(`World_Main`) 안에 야외 필드와 멀리 떨어진 던전 아틀라스를 두고, 필드는 손으로 정한 뼈대 위에 PCG로 환경을 채우며, 던전은 손으로 만든 방 모듈을 흐름 그래프로 자동 조립하고, 던전 입구에서 목적지 스트리밍 소스를 선로딩한 뒤 같은 월드 안에서 이동해 로딩 화면을 없앤다. 생성은 런타임이 아니라 "에디터에서 생성 → 검증 → 선택 → 수동 보정 → 베이크"다.

## 1.2 핵심 결정 (설계서 1장·17장)

| ID | 결정 | 설계서 근거 | 신뢰도(부록 B) |
|---|---|---|---|
| R-01 | 단일 Persistent World + World Partition. 필드와 던전이 같은 UWorld | 1장 표, 17장 | 엔진 기능: 높음 |
| R-02 | 필드 뼈대(지역 연결, 마을, 메인 던전, 랜드마크)는 수작업, 반복 POI·보조 도로·전투 공간은 생성기, 환경은 PCG | 4장 | 설계 제안 |
| R-03 | 던전은 Room Module + Flow Graph 조립 + PCG 드레싱 | 6장 | 설계 제안 |
| R-04 | 던전은 필드 지하 Z 적층이 아니라 수평으로 떨어진 Dungeon Atlas 슬롯에 배치 | 7장 | 설계 제안 |
| R-05 | 생성 시점은 에디터 타임(Generate + Bake). 런타임 PCG는 소형 디테일만 제한적으로 | 1장 표 | 설계 제안 |
| R-06 | 가장 먼저 만들 것은 "입구 → 스트리밍 소스 → 던전 슬롯 → 출구" 왕복 프로토타입 | 17장 | 설계 제안 |

## 1.3 요구사항 목록

### 월드 파티션 (3장)
- R-10 `World_Main` 하나를 런타임 기준 월드로 유지한다.
- R-11 Enable Streaming을 켜고 패키지 빌드에서도 확인한다(Top Down 템플릿은 기본 비활성일 수 있음).
- R-12 런타임 그리드는 1개로 시작한다. 셀 크기·로딩 범위는 고정값을 두지 말고 프로파일링으로 정한다(탑다운은 가시거리가 짧으므로 보수적으로 시작).
- R-13 필드·던전 환경 액터는 공간 스트리밍(Spatially Loaded) 대상으로 둔다.
- R-14 스트리밍 소스는 플레이어 + 던전 목적지 선로딩 소스 두 종류를 쓴다.

### 야외 필드 생성 (4장)
- R-20 수작업 항목: 지역 간 연결 관계, 메인 마을, 메인 퀘스트 지점, 보스 던전, 랜드마크, 주요 동선, 지역별 고도·시야 방향.
- R-21 생성기 항목: 지역 내 사이드 던전 입구 후보, 반복 POI(Camp, Shrine, Ruin, Graveyard, Event Area), 보조 도로 스플라인, 전투 공간(Clearing/Arena), POI 주변 배제 영역과 드레싱 범위.
- R-22 월드 정의 데이터 에셋(`DA_WorldDefinition`)에 지역별 Town/MainDungeon/SideDungeon/POI/EventArea 수량과 바이옴 프로파일을 둔다.

### PCG (5장)
- R-30 그래프를 기능별로 분리한다: Biome/, Roads/, POI/, Common/ 서브그래프. 단일 마스터 그래프 금지.
- R-31 바이옴 데이터 에셋(`DA_Biome_*`)에 에셋 세트(나무·바위·덤불·잔해)와 밀도·최소 간격·최대 경사·도로/POI 이격을 둔다. PCG Biome Core는 참고만(Experimental).
- R-32 배치 알고리즘: 거리/배제 마스크, 포아송(블루 노이즈) 간격 제약, 경사·고도·레이어 필터, 노이즈(밀도 미세 변동), 스플라인 샘플링.
- R-33 대형 영역은 Partitioned/Hierarchical Generation으로 재생성 비용을 줄인다.

### 던전 (6장)
- R-40 흐름 템플릿 5종: Linear, Branch, Loop, Hub, Key/Lock.
- R-41 테마당 구조 모듈 10~15개(초기 8개). 바닥·벽·출입구·큰 구조물만 손으로, 소품은 PCG 드레싱과 인카운터 데이터로 변형.
- R-42 변형 축: 방 지오메트리 × 드레싱 시드 × 인카운터 세트 × 소품 세트 × 라이팅 변형 × 데칼/손상 변형.
- R-43 자동 검증 후 실제 플레이로 좋은 시드만 채택한다.

### 던전 아틀라스 (7장)
- R-50 슬롯 간 로딩 범위가 겹치지 않도록 간격을 둔다.
- R-51 슬롯 데이터: DungeonID, WorldTransform, Bounds, EntryTransform, ExitTransform, Theme, FlowTemplate, Seed, ValidationResult.

### 심리스 전환 (8장)
- R-60 진입 시퀀스: 입구 선로딩 범위 진입 → 목적지 스트리밍 소스 활성 → 셀 로딩 완료 확인 → 전환 구간(통로·문·암전·카메라 가림) → 같은 월드 안 EntryTransform으로 이동 → 선로딩 소스 비활성 → 필드는 거리 기준 자연 언로드.
- R-61 입구 액터 책임: DungeonID, TargetEntryTransform, PreloadDistance, 스트리밍 소스 컴포넌트, TransitionState, 귀환/출구 정보.
- R-62 목적지 로딩이 끝나기 전에는 절대 이동시키지 않는다. 저사양 디스크 조건을 전환 통로나 입력 제한으로 흡수한다.

### 레벨 인스턴스와 데이터 레이어 (9장)
- R-70 룸 모듈, 반복 POI, 마을 블록은 레벨 인스턴스를 제작 단위로 쓴다. 런타임은 Embedded 모드 중심, Level Streaming 모드는 특수한 경우만.
- R-71 데이터 레이어는 던전별 로딩 제어가 아니라 퀘스트·진행·월드 상태 변형(예: DL_Town_Normal / DL_Town_Destroyed)에 쓴다.

### 상태 저장 (10장)
- R-80 스트리밍으로 사라지는 액터의 영속 상태(보스 사망, 상자 열림, 이벤트 활성)는 DungeonID/POIID와 안정 ID(StableID)를 키로 별도 계층에 저장한다.
- R-81 액터가 다시 로드될 때 안정 ID로 상태를 조회해 적용한다.
- R-82 세이브에는 영속 데이터만 저장하고 일시적 배치는 시드/정의로 재생 가능하게 한다. 출시용 결과를 고정할 때는 시드와 생성기 버전을 함께 저장한다.

### 검증과 시드 선택 (11장)
- R-90 던전 검증기: 연결성(입구→보스), 필수 방 존재, 바운드 충돌, 방 수 범위, 막다른 길 비율, Key/Lock 진행 논리, 주요 경로 내비메시 단절.
- R-91 월드 검증기: 던전 입구 간격, POI 밀도, 도로 도달성, 지형 적합성(절벽·물 위), 슬롯 간 로딩 범위 중첩, 무콘텐츠 이동 구간 길이.
- R-92 후보 생성 방식: N개 시드 생성 → 자동 검증 → 점수/탈락 → 상위 후보만 플레이 확인 → 선택 → 수동 보정 → 베이크.

### 에디터 툴 (12장)
- R-100 Outdoor / Dungeon / Validate / Bake 기능을 분리한 툴. 시드·지역 수·사이드 던전 수·POI 밀도 입력, 테마·흐름·크기·시드 입력, 선택 슬롯/전체 슬롯 생성, 검증, PCG 재생성, 베이크, 검증 리포트 빌드.
- R-101 핵심 기능: 시드 재현성, 부분 재생성(지역/슬롯 단위), 잠금(Lock)으로 재생성 제외, 실패 위치 클릭 이동이 되는 검증 리포트, 생성기 버전 추적.

### 규모·마일스톤·QA (13~15장)
- R-110 초기 목표: 필드 500m×500m, 지역 1, 마을 1, 테마 1, 룸 모듈 8, 흐름 3, 던전 3, POI 원형 4~5, 배치 POI 8. 확장 목표: 1.5~2km, 지역 4, 던전 15~25, 룸 모듈 테마당 10~15 등.
- R-111 Phase 1 심리스 스트리밍 프로토타입 → Phase 2 던전 버티컬 슬라이스 → Phase 3 야외 생성기 → Phase 4 프로덕션 규모(HLOD/내비/라이팅/스트리밍 프로파일링, 시드 고정·베이크).
- R-112 QA 체크: 패키지 빌드에서 선로딩 완료, 필드 언로드 확인, 다른 슬롯 동시 로드 금지, 스트리밍 후 내비 데이터 가용, 언로드/재로드 후 상태 복구, Embedded 모드 액터 유지, 데이터 레이어 전환 정확성, HDD/프레임 드랍 상황에서 빈 공간 노출 없음, 생성기 버전 변경 후 시드 보호.

### 권장 클래스·폴더 (16장)
- R-120 클래스 후보: WorldGenerationSubsystem(오케스트레이션·시드·버전), WorldGraphGenerator, RoadGenerator, DungeonGenerator, DungeonValidator, WorldValidator, DungeonEntrance 액터, DungeonStateSubsystem, WorldStateSubsystem. 이 프로젝트에서는 AGENTS.md 3절에 따라 모두 `TD` 접두어를 붙인다.
- R-121 콘텐츠 폴더: World/(Maps, Definitions, Regions, DataLayers), PCG/(Biomes, Roads, POI, Common), Dungeon/(Definitions, Flows, Themes, Rooms, Encounters), POI/(LevelInstances, Definitions), Editor/(WorldGenerator, Validators).

## 1.4 설계서에서 보강이 필요한 지점

설계서가 정하지 않았거나 이 프로젝트 규칙과 맞춰야 하는 부분이다. 아키텍처 문서(03)에서 결정한다.
- 설계서의 클래스 이름은 접두어가 없다(`UWorldGenerationSubsystem`). 이 프로젝트는 `UTD…`를 쓴다.
- 생성기가 "에디터 전용"인지 "런타임에서도 재생 가능"인지가 모호하다. 결정론(시드 → 동일 결과)을 보장하려면 생성 코드가 에디터 모듈이 아닌 런타임 모듈에 있어야 검증 테스트와 커맨드릿이 같은 코드를 쓸 수 있다.
- 안정 ID(StableID)가 무엇인지 정의하지 않았다. 런타임 빌드·레벨 인스턴스·복제 액터에서도 안정적인 식별자를 정해야 한다.
- 룸 모듈의 출입구 규격(도어 소켓 크기·방향·그리드 단위)이 없다. 조립 알고리즘의 전제이므로 먼저 정해야 한다.
- 검증기의 "점수" 산식과 후보 N의 기본값이 없다.
- 세이브 파일 형식과 버전 마이그레이션 방침이 없다.
- 스트리밍 완료 판정의 구체 API와 타임아웃 시 동작(무한 대기 금지)이 없다.
- Dungeon Architect(R6)는 "선택 툴"로 언급됐다. 이 프로젝트는 C++ 자체 구현이 원칙이므로 참고만 한다.

# TD 전투 애니메이션 품질

자연어 요청을 실제 캐릭터에 맞는 전투 동작으로 만들고 시각적으로 검토한다. MCP 연결과 FBX 변환의 성공은 애니메이션의 자연스러움이나 전투 감각을 보장하지 않는다. 전용 text-to-motion 서비스가 설치된 것으로 가정하지 않는다.

## 프로젝트 도구

- 연결·교환 절차가 필요할 때 [BlenderAnimationWorkflow.md](C:/Project/TDGame/Docs/BlenderAnimationWorkflow.md)를 읽는다. 작업 루트는 `C:/Project/TDGame`이다.
- Blender는 `Tools/BlenderMCP/call_tool.py`의 실제 MCP `execute_blender_code`로 `bpy` 스크립트를 실행한다. 현재 프로젝트의 Blender MCP 세션은 공유되므로 다른 에이전트와 씬 편집을 동시에 수행하지 않는다.
- Unreal 교환 도구는 `td_blender_animation_tools.TDBlenderAnimationTools`의 `export_fbx`, `import_animation_fbx`, `sample_animation_poses`다. 연결된 스키마와 `Content/Python/td_blender_animation_tools.py`에서 실제 인수를 확인한다.
- 기존 `Tools/BlenderAnimation` 스크립트는 특정 캐릭터의 예제다. 고정된 본 이름·프레임·발 고정·미리보기용 무기를 다른 요청의 정답으로 재사용하지 않는다. 몽타주 작업이 필요할 때만 [AnimationAuthoring.md](C:/Project/TDGame/Docs/AnimationAuthoring.md)를 추가로 읽는다.

## 동작의 근거부터 선택

사용 손, 무기, 캐릭터 기준 공격 방향, 타격 횟수, 이동 여부와 앞뒤 연결 동작을 정리한다. 기존 애니메이션 개선 요청이면 원본의 어느 구간이 문제인지 먼저 재생해서 확인한다. “묵직하게”는 전체 속도를 일괄 낮추는 명령으로 해석하지 않는다. 지지와 준비, 타격 가속, 몸통의 반작용, 회수의 리듬을 함께 본다.

현재 프로젝트에서 실제로 사용할 수 있는 참고 애니메이션을 검색하고, 메시·무기·Skeleton과 공격 형태가 맞는지 재생해 판단한다. 적합한 기존 전신 모션이 있으면 그 스텝, 골반 높이 변화, 피벗, 루트 이동과 리듬을 보존하면서 필요한 공격 궤적을 수정하는 방식을 우선 검토한다. 특정 `MM_Attack_01`이나 사람형 모션을 모든 공격의 기본값으로 삼지 않는다. 다른 Skeleton의 참고 모션은 본 대응과 리타게팅 검증이 필요하다.

참고 자료가 없거나 요청과 맞지 않으면 실제 체형에 맞는 주요 포즈와 접지 구간부터 작성한다. 근거가 없는 관절 각도나 고정 타이밍을 사실적인 동작으로 단정하지 않는다. 선택한 참고, 보존한 부분, 바꿀 부분을 짧게 기록한다.

## Blender에서 편집할 때

실제 Armature 계층과 레스트 포즈, 본의 방향, 단위와 오브젝트 변환을 확인한다. 변형 본과 컨트롤·IK·보조 본을 구분한다. 필요한 경우 Blender의 Graph Editor, Dope Sheet, Motion Paths, IK 제약, NLA 등의 사용 가능한 기능을 선택해 편집하고, 최종 변형 본에 베이크한다. 설치된 애드온과 버전 호환성을 먼저 확인하고, 존재하지 않는 플러그인이나 자동 리깅 기능을 전제하지 않는다. 에셋에 이미 적합한 제어 리그가 있으면 그것을 우선 활용하며, 전투 동작 하나를 위해 원본 Skeleton을 다시 만들지 않는다.

발은 구간별 역할로 다룬다. 발을 딛는 구간, 뒤꿈치나 발끝을 축으로 회전하는 구간, 발을 떼어 옮기는 구간, 다시 착지하는 구간을 구분한다. 모든 프레임에서 발 위치와 회전을 잠그거나 골반 높이를 고정하는 방식으로 미끄러짐을 숨기지 않는다. 피벗 동안 발 전체가 정지할 필요는 없으며 접촉점이 기준이다. 공중 공격이나 의도적인 미끄러짐에는 다른 접촉 조건이 필요하다.

참고 동작에 맞으면 하체의 지지와 골반 움직임이 몸통·어깨·팔·무기의 가속으로 이어지도록 위상 차이를 유지한다. “골반 → 몸통 → 무기”는 검토 기준이며 모든 공격에 강제하는 고정 순서나 시간차가 아니다. 몸체를 지지하는 다리의 무릎, 발목, 골반 높이와 체중 이동을 함께 확인하고 팔 궤적만으로 무게감을 만들지 않는다.

준비, 가속, 타격, 후속 동작, 회복의 속도 차이를 Graph Editor와 재생으로 확인한다. 모든 키 구간에 독립적인 `smoothstep` 보간을 적용해 매 키에서 속도가 0이 되는 동작을 만들지 않는다. 타격을 통과하는 연속적인 궤적과 의도한 정지·감속 지점을 구분하고, 회전 연속성·오버슈트·급격한 속도 변화를 확인한다. 전역 속도 조절이나 무조건적인 보간 교체보다 문제가 있는 구간을 수정한다.

## 사람형이 아닌 캐릭터

실제 본 계층에서 몸통, 각 다리 체인, 공격 기관, 지지 부위, 말단 접촉점을 대응시킨다. 다족이면 구간별로 어느 다리가 지지·피벗·이동·공격을 담당하는지 정한다. 꼬리·턱·날개 공격에도 같은 역할 분석을 사용하되 사람의 팔이나 두 발 구조를 강제하지 않는다. 본 이름만으로 역할이나 IK 방향을 추측하지 않는다. 리소스와 요청으로 역할을 알 수 없는 경우에만 해당 부분을 확인한다.

## 비교와 시각 검토

실제 게임에서 사용하는 메시와 무기를 포함해 검토한다. 무기가 연결되지 않았거나 대체 도형을 썼다면 그 한계를 밝히고 실제 무기 검증을 완료로 표시하지 않는다. 원본 참고와 후보를 같은 프레임 레이트·카메라·속도로 비교한다.

정면, 측면, 게임 시점에 가까운 사선의 세 방향에서 전신을 확인하고 실시간과 느린 재생을 모두 본다. 정지 포즈 모음만으로 모션 품질을 판정하지 않는다. 길이와 공격 형태에 맞춰 전체 동작과 타격 구간을 검토하며, 고정된 프레임 수를 모든 공격에 강제하지 않는다.

- 지지 구간의 접촉점 이동, 발 침투·부유, 착지와 이탈, 무릎 튐, 골반 움직임을 확인한다.
- 무기 끝과 손의 궤적, 타격 방향, 팔·몸체·무기 관통, 실루엣, 타격 이후 감속을 확인한다.
- 시작·끝 포즈와 앞뒤 공격·대기 모션 연결을 요청 범위에 맞춰 확인한다.

발 접촉점 이동량, 본 위치 오차, 루트 이동, 관절 속도 변화 같은 수치는 문제 구간을 찾는 근거로 사용한다. 허용치는 캐릭터 크기, 단위, 공격 의도와 접촉 상태에 맞춰 판단한다. 발을 들어 옮기는 구간의 이동량이나 피벗 중 발목 이동을 곧바로 미끄러짐으로 판정하지 않는다. 루트 모션을 사용하는 장면에서는 실제 월드 접촉과 루트가 추출된 미리보기 좌표를 구분한다.

## Unreal로 되돌리기

원본 에셋과 참고 Action을 보존하고 새 후보 이름으로 `.blend`, FBX, AnimSequence와 필요한 몽타주를 저장한다. 기존 작업 파일이 있으면 덮어쓰지 않고 다음 후보로 만든다. 제작에 사용한 실제 Skeleton, 본 이름과 부모 관계, 검사한 Armature 오브젝트/루트 이름과 단위를 유지한다. 불필요한 leaf bone이나 새로운 Skeleton을 만들지 않는다. 보조 컨트롤과 제약은 필요한 최종 변형 본으로 베이크한다.

루트 이동을 제거하거나 in-place로 바꾸는 것은 요청과 런타임 사용 방식에 맞춰 결정한다. 원본의 체중 이동을 망가뜨리는 일괄 루트 고정을 피한다. Root Motion 사용 여부, 몽타주 슬롯과 블렌드 방식은 현재 프로젝트 설정에서 확인하며 새 애니메이션 생성만으로 기존 공격 연결이나 데미지 구간을 변경하지 않는다.

기존 Skeleton을 명시해 새 AnimSequence로 가져오고, 실제 에셋의 Skeleton·길이·샘플 수·루트와 주요 본 포즈를 재조회한다. Blender의 최종 동작과 Unreal 재생을 비교해 단위, 축, 루트 이동과 무기 방향이 유지되는지 확인한다. 발 고정 수치만 통과시키거나 Skeleton 수정으로 변환 오류를 숨기지 않는다.

## 완료 판단과 보고

변환 검증, 시각 품질 판단, 게임플레이 연결 검증을 구분해서 보고한다. 수치가 맞아도 사용자가 지적한 발 동작이나 무게감이 해결되지 않았으면 완료로 단정하지 말고 해당 구간을 수정한다. 기반 Skeleton이나 실제 무기 같은 필수 리소스가 없으면 확인된 산출물과 구체적인 미검증 범위를 남긴다.

보고에는 새 에셋과 원본 파일 경로, 참고한 동작과 수정한 구간, 실시간/느린 재생 미리보기, 검증 결과와 남은 품질 한계를 포함한다. “AAA 수준”, “실사급”, “모든 몬스터 지원” 같은 주장은 근거 없이 사용하지 않는다. 에이전트의 시각 판단과 사용자의 최종 미적 승인을 같은 것으로 취급하지 않는다.
